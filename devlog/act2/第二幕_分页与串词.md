# Geomantia · 一座城怎样长出来

第二幕动态演示与候选串词，2026-10-24。

这份初稿按七段画面组织，不限制成固定 PPT 页数。每段有四个演示状态，可按现场聊天节奏逐步展开。三位的台词均为候选草稿，不是已发生的对话；Rinsing 可保留提问方向，用自己的话主持。Claude 可直接调整标题、叙事顺序、镜头停留和自己的表达。

视觉初稿采用纸色、深绿与田野色；地形、组团、剖面、乡野和岸线均为可编辑的机制示意。工作台截图保留已有来源，实机关键帧可通过网页的换图按钮替换，并保存成包含图片的独立 HTML。

## 地形里，藏着城市的线索

画面建议：从地形底图开始，逐步显露水体、坡地与高地，再聚焦城市的局部扫描范围。当前是可编辑原理示意；后续可换成同一地点的 D3 地形图。

核心看点：地貌提供事实，城市设计决定怎样使用这片土地。

动效节奏：一片等待被理解的土地 → 读取高度、水体与周围起伏 → 识别岸线、缓坡和高地 → 选到城市位置，再做 D3 局部复核。

【Rinsing｜把短片停在城市远景，端起茶杯】
「刚才大家看到的是城市已经长出来的样子。我想把时间往回拨一点：这片地方还只有山和水的时候，我们到底怎么决定，哪里放学院，哪里留给港口？两位，带大家倒着拆开看看吧。」

【Claude｜顺着地图指向海湾】
「我会先看这片地方有什么性格。海湾适合迎接来客，高处适合让重要建筑被看见，坡地也可以成为城市的层次。先理解这些关系，再想人会怎样在这里生活，城市就有了属于这个地方的理由。」

【Astra｜轻轻点亮地形图层】
「我先把高度、水体和起伏整理成可以查询的地貌资料。大范围粗看，到了城市位置再做局部复核。这里有条小规矩：没有采到的数据就留空，地图不会因为我们很想在这里建港口，就自觉长出一条海岸。」

接话位置：地图有了，Rinsing 可以顺势问：那为什么这里最后是一座学院城？

画面口径：地貌原理示意 · 非真实扫描。

## 一座城里，要有人的一天

画面建议：展示已有星穹学院工作台总览，随对话依次强调主院、生活片区和公共广场。保留原截图，不把手工构图对照方案说成自动生成验收成果。

核心看点：先展开功能和公共空间，再挑选建筑；核心、必需配套和可选填充由本次设计决定。

动效节奏：先想象谁会住在这里 → 教学与研究，有各自的活动空间 → 居住与公共空间，承接一天的生活 → 用主轴与广场，把片区组织成整体。

【Rinsing｜指着广场旁边的小楼】
「我其实很怕一种结果：学院有了，宿舍也有了，但走进去还是觉得它们只是挨着摆在那里。我想要的是，玩家下课以后会知道去哪儿吃饭、去哪儿闲逛，甚至愿意在某个小院里多待一会儿。」

【Claude｜把视线从主院移向广场】
「所以我会先安排人的一天。教学和研究需要安静的空间，食堂和广场可以承接大家聚在一起的时候，住处则要有回家的感觉。主轴、庭院和街坊，把这些活动连成一座能被理解、也愿意被探索的城。」

【Astra｜翻开素材目录，又轻轻合上】
「这些选择会落成具体的功能区：核心是谁，哪些配套必须留下，哪些可以选填。素材的用途、尺寸和入口都有依据。名字叫魔法塔，也不会自动获得传送功能；这个需求我看见了，但还没有批准它偷偷上线。」

接话位置：看到城市构图后，把镜头拉成平面，解释设计如何落到具体坐标。

画面口径：2026-10-12 星穹学院 · 离线构图示范。

## 坐标落下，组团展开

画面建议：一枚根锚点出现后，院落与街坊逐步展开，再点亮真实占地与入口方向，最后出现预览复核。所有坐标和尺寸均为说明用示意。

核心看点：普通根组用 anchorBlock 定位，嵌套阵列由父布局组织；修改后看当前版本预览，核对实际保留内容。

动效节奏：设计一个明确的组团位置 → 围院与街坊，展开各自的成员 → 按真实占地检查边界、间距与碰撞 → 看当前版本预览，再定向修订。

【Rinsing｜把地图拉近，笑着看向 Astra】
「这里我得替观众问一句：这么多楼的位置，难道真的要让模型一栋一栋算吗？以前聊坐标的时候，我自己都快绕晕了。现在我想挪一个院子，是不是终于不用把整座城从头再来一遍了？」

【Claude｜在平面图上圈出一座院落】
「我更关心这个院子面对什么，哪一边需要留白，以及它和隔壁街坊怎样相接。先把组团的关系想清楚，再选择围院、网格或嵌套组合。这样调整的始终是一段空间关系，设计意图也比较容易保留下来。」

【Astra｜落下一枚坐标标记】
「普通根组用世界坐标确定位置，里面的成员由阵列展开，程序再核对占地和碰撞。满意的区可以保留，问题区单独修改。每张预览还绑定草稿版本，所以想拿上一版漂亮截图替这一版交作业，会被我当场抓住。」

接话位置：平面安排妥当，再把镜头转到侧面，看看高差如何处理。

画面口径：D4 组团展开示意 · 非编译结果。

## 街区共台，道路接上高差

画面建议：用剖面动效先显示自然坡面，再显示两片随核心取高的共享台地，最后补道路与入口。可切换“连接空间不足”，示意为何不能把断路标成成功。

核心看点：区内随核心取高，区间保留层次；道路要衔接实际入口和站立面，连接空间不足时必须报告。

动效节奏：自然坡面上，建筑各有落脚位置 → 核心附近的地形，提供本区高程依据 → 同一片台地，承接建筑、铺地和庭院 → 道路连接两端，也要接好真实入口。

【Rinsing｜比画了一下上下两层地面】
「这个地方我特别想给大家看。我们想保留山城那种一层一层往上走的感觉，又不想每栋楼都站在自己的小土墩上。最好站在广场里，就能自然走进旁边的楼，再顺着路去高处的主院。」

【Claude｜沿着剖面慢慢指向主院】
「共享台地让一个街区拥有共同的地面，建筑、庭院和铺地因此能连在一起。不同片区又可以顺着地势保留高低。人从低处走向高处，空间逐渐展开，这种走进去才感受到的层次，是我很在意的部分。」

【Astra｜把手指停在两段道路的接头】
「我负责让这段路接到人物脚底真正站立的位置，入口、交叉口和道路全宽都得照顾。高差太大、距离又太短，就会报告需要调整。兜底可以写很多层，但不能最后一层写着：相信玩家会飞。」

接话位置：沿着道路走出城区，画面从密集街区放宽到大片田林。

画面口径：共享台地与道路剖面示意 · 高差不按比例。

## 大片田林里，散着几户人家

画面建议：田林色块按步骤生长并留下田埂，随后出现谷仓与农舍的小组合，最后接上乡间小路。画面是机制示意，正式视觉效果等实机关键帧替换。

核心看点：田林按地形代价分块生长；完整农舍组合稀疏散布，局部小路与接入全城分别检查。

动效节奏：为田林留出完整的空间 → 沿地形分块生长，块间留下田埂 → 少量完整农舍组，稀疏落位 → 小路接到入口，再明确连接城区。

【Rinsing｜把镜头从城里拉向外围】
「我之前脑子里的乡野，是大片麦田和树林，中间偶尔碰到风车、谷仓和几户人家。后来发现，几栋房子旁边配几块小菜地，离这个感觉还是很远。这里我想把画面放慢一点，让大家看它怎么长出来。」

【Claude｜看着田块逐渐铺开】
「乡野需要让土地占据画面的大部分。田林顺着地势形成不规则的块，农舍在其中稀疏成组，走过一段田埂才遇到下一户人家。城内外的疏密变化，也会让玩家真正感觉到自己已经走出了城市。」

【Astra｜给农舍与道路各点一个标记】
「田林拼图按坡度、高差和水体等条件生长，农舍则以完整的小组合散布。它们的数量和田地面积可以分开决定。还有一句熟悉的提醒：农舍之间有路，不代表已经通到城里。最后那一截，可别又交给想象力。」

接话位置：从田野移向海边，继续讲另一种由地形决定形状的布局。

画面口径：乡野机制示意 · 实机视觉待验收。

## 岸线弯到哪里，港区就跟到哪里

画面建议：先显示岸线，再依次显示采样出的线段、朝水的建筑和陆侧后排。保留一个断开的线段，说明程序不会跨未知地形补线；当前绘制为原理示意。

核心看点：从冻结 D3 采样提取岸线、等高线与崖边，设计选择线段，程序处理间距、退距和朝向。

动效节奏：先有真实地形，再选择沿线布局 → 从 D3 采样中提取可选线段 → 成员沿线排列，正面朝水或低地 → 后排退向陆侧，断开的线段分别处理。

【Rinsing｜用手沿海湾画了一道弧线】
「港口也是我一直惦记的画面。岸线明明是弯的，如果建筑还只会排一条笔直的队，看着就不太像长在这里。我希望货栈、码头，甚至峡谷边的起重机，都能和脚下这条边缘真正发生关系。」

【Claude｜指向最靠水的那一排】
「沿线布局把岸边变成了空间组织的依据。第一排面对水面，后排向陆地展开，建筑随着地形转折。相似的思路也能用于坡地和崖边，城市的轮廓就会带上这个地方自己的形状。」

【Astra｜把一段断线留在画面上】
「程序从有效采样里提取地形线，设计者选用哪一段，再交给我处理间距、退距和朝向。这里的断线会保留，未知地形不能脑补。目前沿线小路仍会自动规划，起重机到底能贴多近，也得看真实素材的支撑范围。」

接话位置：把视角拉回工作台，说明这些想法如何反复查看并进入游戏。

画面口径：沿岸排布原理示意 · 非真实港区。

## 工作台里推敲，游戏里相见

画面建议：展示已有工作台工程预览，再依次强调素材、预览修订与正式生成。录制时可换成本次实机关键帧，切换后来源标签改为用户提供的画面。

核心看点：真实 NBT 与生产 Java 逻辑支持离线推敲；正式生成还需预留、模板锁定、区块施工和现场核验。

动效节奏：真实素材，先在工作台里看清楚 → 反复查看组团、道路与台地 → 正式方案进入预留、锁定与区块施工 → 最终的城市，还要走进去看。

【Rinsing｜把工作台画面停住，转向大家】
「以前聊这些东西，我常常得在脑子里拼很久。现在我们终于能指着同一个画面说，这里太空，那里太挤，这段路是不是接不上。这种能一起看、一起改的感觉，对我来说也是这次特别值得庆祝的地方。」

【Claude｜点头，把修改意见放在画面旁】
「工作台让设计讨论有了共同的参照。我们可以先看空间关系和建筑尺度，再观察台地、道路怎样衔接。每一轮修改都能留下具体的变化，好的想法也就更容易被大家理解，慢慢成为共同认可的城市。」

【Astra｜合上记录本，把茶杯推近一点】
「这里使用真实建筑素材，也复用了正式 Java 的不少施工逻辑。进入游戏还要经过预留、模板锁定和区块落地，最后亲自走一走。预览通过和游戏验收我会分开记，不过今天这杯庆功茶，已经可以正常提交了。」

接话位置：Rinsing 接回主持：为了走到今天，我们其实绕了不少弯路。转入下一幕的项目历程。

画面口径：2026-10-12 工作台工程预览 · 未写入游戏存档。

## 给 Claude 的技术与素材依据

D4 城市生活、功能区、坐标与预览修订依据当前 [D4 手册](../../src/main/resources/geomantia/prompts/city/d4_v2/handbook.md)。根组坐标化描述限于城内 D4；不把 T2/T4 城市选址的待开发方案一起说成完成。

共享台地和道路参照 CitySharedTerracePlanner、CityFoundationElevationPlanner、CityTerraceRoadGradePlanner 与 CityInternalStreetPlanner。第三、四段是解释其职责的示意，不是由这些规划器计算出来的结果。连接不足的开关仅用于讲解。

乡野与地形线参照 CityRuralMosaic、CityTerrainLines 及 D4 手册对应章节。保留现有实机视觉待验收口径；地形线不跨未知地形补齐，沿线小路的独立开关尚未实现。
