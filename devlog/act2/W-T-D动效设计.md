# W → T → D 动效设计说明

设计：Claude，2026-10-26。实现交给 Astra（GPT）。本文只规定观感、节奏和文案口径，技术细节由实现方决定。

## 一句话方向

**不是幻灯片，是一张地图和一个镜头。**

整场只有一张持续存在的地图。观众看到的是一个慢慢推近的镜头：世界 → 国度 → 一座岛 → 一座城 → 实机。场景之间不翻页、不转场，只移动镜头、增减图层。

参照物：老测绘图册、野外考察手账。不要参照：产品发布会、宣传片、数据大屏。

## 现在为什么像广告

| 现象 | 例子 | 改法 |
|---|---|---|
| 每页都有大标题和副标题 | 「看一次真实的设计迭代 / 工具反馈改变下一步，地图也随之改变」 | 删掉标题。只留左上角小号阶段标签 |

| 示意图冒充过程 | 7×11 假网格扩张 | 用存档真实数据驱动 |

## 动效原则

1. **数据决定节奏。** 扩张快慢来自真实认领代价，不按"好看"的曲线随便调。
2. **慢，稳，停得住。** 缓动统一 ease-in-out；不弹跳、不过冲、无粒子、无光晕、无闪烁光标。
3. **每一拍结束于静止画面。** 讲解可能聊很久，画面必须能一直停着。
4. **演讲者控制。** → 下一拍，← 上一拍，F 全屏。不自动播放。
5. **镜头连续。** 推近时保留上一层的淡影（例如推到城市时，国界线仍以 15% 透明度留在背景）。

### D · 城市

**节奏原则：像做菜一样，同一步骤第一次慢讲，剩余同类动作加速带过。** 只拿南宿院一个案例，把"选素材 → 写规划 → 展开阵列"慢慢走一遍，让观众学会这套画面语言；之后的修改沿用同一套语言，最后其余各区以相同动作快速展开。加速的是重复动作，不省去素材、参数与地图结果之间的对应关系；不逐组重复讲解，也不让其余各区直接跳到完成态。

## 文案规则

**只写"是什么"，不写"意味着什么"。** 意义交给对话去讲。

- 每屏最多一行图注，不超过 18 字。
- 可以写：名词、数字、地名、坐标、工具名。
- 不写：抒情句、对仗句、问句、破折号金句。
- 不用这些词：终于、每一步、成为、旅程、走进、回到、见证、诞生。

| 不要 | 要 |
|---|---|
| 地图上的选择，成为脚下的空间 | 镜潮 · (−2928, 5392) |
| 每靠近一步，前面的选择都留下线索 | 局部地形 |
| 国度和城市，逐层有了位置 | 七个国度的起点 |
| 这条路，终于回到玩家脚下 | （实机图，不放字） |

## 真实性角标

右下角统一格式：`来源 · 类型`，类型只有三种：

- **真实数据**：直接由存档或日志渲染。
- **近似**：用真实数据，但顺序或时间经过简化。
- **示意**：没有对应数据，只解释原理。

字号 11px，墨色 40% 透明度。只放在角标里，不进图注，也不进台词。

### 1. T1 设定纸条：从"三个示例"改成"七国名册"

问题：纸条写了共同背景加三个国度，下一拍却落下七个起点，观众对不上数。

改法：纸条改成一份**七行名册**，之后一直留着当图例。

- 顶部一行共同背景（来自 `realm_profiles.json`）。
- 下面七行，每行：色块 + 国名 + 一句不超过 10 字的特点。**色块就是该国之后的领土颜色。**
- 镜潮那一行加小字「固定领土」。这样 T3 里镜潮整片同时出现，观众也能理解。
- T2：每落下一个起点，名册里对应那一行同步加深一下，按名册顺序落点。
- T2–T3：名册缩窄后停靠在右侧，继续当图例；T4 推近时淡出。

### 2. 功能区：先交代职责和地形，再逐步声明功能区

问题：16 个功能区一次性全部出现，没有来由，也没有边界。

事实先说清：10.20 原始会话第 80 行通过 `city_d4_overview` 的 `overview.districts` 声明功能区，每项只有 `groupId`、`role`、`intent`，**没有坐标**；后续才用 `city_d4_district` 设计各区。位置写在 `intent` 里，用的是地形语言（例如「平原28北半部」「东南岸线陆侧」）。真正的坐标来自后面各组团的锚点，最终占地才提供空间范围。画面要如实表现这个顺序。

原 D1 拆成四拍：

| 拍 | 画面 | 图注 | 来源 |
|---|---|---|---|
| D1 地形 | 局部地形淡入；平原、台地、岸线等地形块标上原始编号（如"平原28"） | 局部地形 | D3 地形资料 |
| D1b 读背景 | 左侧纸条写出镜潮在 T4 时定下的职责，每项一行 | 镜潮 · 城市职责 | T4 / 城市意图存档 |
| D1c 读素材标签 | 纸条下方排出素材库的用途标签和数量（如"住宿 ×n"） | 可用素材 · 按用途 | 素材目录快照 |
| D1d 声明功能区 | 先用一个职责和选址依据清楚的区，慢速展示“职责强调 → 地形或邻接关系提示 → 名称 · 类别软标签落下”；确有新关系需要解释时再补一个例子。其余区重复相同动作并加速，最终完整显示 16 区，不直接批量补出标签。**不画边界** | 职责与地形 → 功能区 | `city_d4_overview` 请求 |

- D1d 的重点是让观众看到一条具体联系，例如公开 `intent` 中的“东部台地承担观测”怎样对应观测区；每次只强调当前这一条。16 区是在同一次请求中声明，逐个揭示只是阅读节奏，不表现成 16 次工具调用。没有明确地形编号的 `intent` 不强行对应某个地形块，也不借用最终坐标冒充此时已有的定位。
- 最新实播确认：“分小球”指从左侧逐项飞入真实地图的大致位置，不是另建纸面分类表。左侧每项名称后显示醒目的 intent 方位原文短语（如“平原28北半部”“星厅西北”），先留时间阅读，再从该行飞出一个标记到相应大致区域；已完成项保留编号与短名称。位置是依据自然语言的近似图解，不是提交坐标，不展示坐标数值或正式区界。明确点名的地形块同步强调。保留提示：“总方案：先说明用途和大致关系，具体坐标在后续组团设计时确定。”
- D7 全城快放结束时，按各区最终占地第一次画出“各区占地范围”（细墨线 + 浅色），区名移入其中。若轮廓由建筑占地归并生成，角标标明“近似”，不冒充存档里的正式区界；仅在存在真实分区边界数据时使用“区界”。
- 重新核对 Java 与原始 JSONL：进入 D4 时上下文已提供 materialCatalog 摘要和作者标签；第55行读取摘要，第72行读取学院素材作者标签（第74行返回），第80行才声明分区。第64行失败的是针对未声明分区的查询，不能据此认定之前看不到目录。实际播放顺序为 D1 → D1b → D1c → D1d，再进入 D2；D1c使用第74行已有标签，D2才讲按区选具体素材。

### 3. 阵列：加一张"参数单"，每填一格，地图就变一下

问题：素材卡之后组团直接出现，看不出"阵列"是填参数得来的。

改法：D3（写规划）先用请求里的 `layout.purpose` 交代“为什么这样排”（如四栋小宿舍围合公共内庭），再在组团旁边出现一张小参数单。中文含义为主，原始键名为小号等宽字。字段一个一个填上，每填一个，地图对应出现规划虚线；这是对同一次请求的拆解展示，真实展开结果留到 D4：

| 填入字段 | 地图同步变化 |
|---|---|
| 锚点 `anchorBlock` (−3040, 5485) | 十字落下 |
| 排法 `algorithmProfileRef`：`algorithm:courtyard` | 显示围合内庭的排布方向；具体虚线空位随下一步数量出现 |
| 数量 `structureCount` 4 | 出现四个空位 |
| 间距 `layout.gapBlocks`：6 | 空位之间的距离调整；内庭尺寸等细节按请求中的 `layout` 表达 |
| 素材 `requiredStructureRefs` | D2 留下的素材卡缩小，落进空位 |

- 字段显示"中文名 + 小号原始键名"，值用请求里的真实数值。只放请求里真实存在的字段，最多 5 行。
- 此次请求的 `patternPreference` 属于 `buildingGreeneryPolicy`，是绿化偏好，不用于解释建筑排法。排法由 `algorithmProfileRef` 配合 `layout` 中的具体参数讲解。
- D4：改为“检查展开：计划四栋，预览一栋”。规划虚线与真实展开结果对照，说明本次没有形成四栋宿院，需要检查数量完整性、地形适配与接路并继续修订；“保留一栋”是工具结果，不是主动缩减设计的决定。此时是编译预览，不代表游戏内落地验收。原记录显示 revision 61 为一栋，关闭停止条件后的 revision 62 仍为一栋，更换核心并明确配套后的 revision 63 为四栋；未找到足以确认初次缺失由地形导致的诊断，不将地形写成已证实原因。进入 D5 时简短交代上述修订，再检查平移后的接路情况。
- D5 平移：进入本拍时切到平移前的真实请求状态，锚点由 (−3040, 5495) 改为 (−3028, 5501)，对应东 12、南 6。它与最初申请的 (−3040, 5485) 之间还有修改，省略时用短注“中间修改略”交代，不能从最初值直接演成这次位移。整组平移后仍保留道路缺口，让观众看到这次修补未解决连接问题。
- D6 改组：根据公开修订请求，参数单拆成“一栋核心”和“三栋小宿舍”两组，分别显示 `algorithm:linear`、`algorithm:grid`，再用 `arrayCompositions` 的组合关系组织生活巷，并展示通向市场、食堂的连接。表达“重新组织组团”，不能只改原表里的布局和数量而隐藏新增组与组合关系。连接是否成功以返回的真实几何为准。
- D7 快放：恢复 16 张缩小参数单依次叠起的表现，16 个区都有对应的一张，卡上区名与 D1d 的名称保持一致。每张出现时，对应地图区域同步强调并展开；卡片错位叠放，保留全部区名可见，结束时能对上完整的 16 区。可以只讲少数例子，但不能只展示少数区的参数单，让其余展开失去来由。每张作为该区真实请求的摘要，区内有多个组团或组合时在卡内体现，不将一个功能区等同于一个阵列，也不虚构统一的参数结构。
- D7 每个新展开区仍保留“素材小卡进入 → 参数填写与规划虚线 → 真实轮廓展开”的可辨认动作，复用 D2–D4 的画面语言并加速，不另起慢速讲解。南宿院保留已完成状态，其参数单缩入总览，不重复生成一次；其余各区错峰接续，允许上一处收尾时下一处开始。5–8 秒只作为试播起点，若看不出卡片与地图的对应就延长，不为凑时长删掉动作。快放是对已核实记录的压缩展示，不暗示工具实际并行执行。

目的：观众能跟上“想让这里承担什么功能 → 怎样组织建筑 → 实际展开怎样 → 根据问题再修改”。参数单为这条过程服务，后面的快放沿用观众已经理解的画面语言。

### 修改后的 D 段节奏
