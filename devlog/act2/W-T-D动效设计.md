# W → T → D 动效设计说明

设计：Claude，2026-10-26。实现交给 Astra（GPT）。本文只规定观感、节奏和文案口径，技术细节由实现方决定。

## 一句话方向

**不是幻灯片，是一张地图和一个镜头。**

整场只有一张持续存在的地图。观众看到的是一个慢慢推近的镜头：世界 → 国度 → 一座岛 → 一座城 → 实机。场景之间不翻页、不转场，只移动镜头、增减图层。

参照物：老测绘图册、野外考察手账。不要参照：产品发布会、宣传片、数据大屏。

## 现在为什么像广告

| 现象 | 例子 | 改法 |
|---|---|---|
| 每页都有大标题和副标题 | 「看一次真实的设计迭代 / 工具反馈改变下一步，地图也随之改变」 | 删掉标题。只留左上角小号阶段标签 |
| 文案在升华，而不是在陈述 | 「这条路，终于回到玩家脚下」「地图上的选择，成为脚下的空间」 | 只写名词、数字、地名、坐标 |
| 信息装在卡片和面板里 | 左侧调用卡片 + 右侧图 + 底部导读 | 地图铺满，文字作为图注贴在地图上 |
| 示意图冒充过程 | 7×11 假网格扩张 | 用存档真实数据驱动 |

## 画面版式（16:9）

```
┌──────────────────────────────────────────────┐
│ W · 扫描                                      │  ← 阶段标签，左上，12–14px
│                                              │
│                                              │
│               地图（铺满上部 ~78%）            │
│                                              │
│                                              │
│ 图注一行                       来源 · 真实数据 │  ← 左下图注 / 右下来源角标
├──────────────────────────────────────────────┤
│        底部 ~22% 留空：后期放字幕和五人头像栏      │
└──────────────────────────────────────────────┘
```

- 没有页眉、页脚、进度条、Logo。
- 底部安全区内不放任何内容。

## 色彩与字体

纸面而非屏幕。整体低饱和，像墨和矿物颜料。

| 用途 | 颜色 |
|---|---|
| 纸 | `#F2EEE4` |
| 墨（文字、边界线） | `#2B2A26` |
| 次要文字、网格 | `#2B2A26` 30–45% 透明度 |
| 海 | `#A9BCBC`，深水略深一级；可加极细水平排线 |
| 陆地高程 | 4 级：`#E6E1CC` → `#D6CCAF` → `#C4B594` → `#A8987A` |
| 七个国度 | 石青 `#5E8C9A`、赭石 `#B07A4F`、藤黄 `#C9A63E`、胭脂 `#A65E66`、松绿 `#5F8A6A`、黛紫 `#6E6487`、灰绿 `#8A9478`；填充 30–40% 透明度，边界用墨色 1.5px |

- 地名、国名：衬线中文（思源宋体 / Noto Serif SC）。
- 数字、坐标、工具名：等宽（JetBrains Mono / IBM Plex Mono），小号。
- 不用渐变、发光、阴影、毛玻璃。

## 动效原则

1. **数据决定节奏。** 扩张快慢来自真实认领代价，不按"好看"的曲线随便调。
2. **慢，稳，停得住。** 缓动统一 ease-in-out；不弹跳、不过冲、无粒子、无光晕、无闪烁光标。
3. **每一拍结束于静止画面。** 讲解可能聊很久，画面必须能一直停着。
4. **演讲者控制。** → 下一拍，← 上一拍，F 全屏。不自动播放。
5. **镜头连续。** 推近时保留上一层的淡影（例如推到城市时，国界线仍以 15% 透明度留在背景）。

### D · 城市

| 拍 | 画面 | 图注 | 来源 |
|---|---|---|---|
**节奏原则：一组讲透，其余快放。** 只拿南宿院一个组团，把"选素材 → 写规划 → 展开阵列"慢慢走一遍，让观众学会这套画面语言；之后的修改沿用同一套语言，最后其余各区一起快速展开。不逐组重复，也不整城只放一遍。

画面语言（全 D 阶段统一）：

- **素材** = 建筑俯视轮廓小卡，旁边等宽小字写作者标注的用途或床位。
- **规划** = 虚线：锚点十字 + 成员空位虚线框 + 组团外框。
- **展开** = 虚线框逐个变成实心轮廓（墨线 + 浅填色），之后再补院子和路。

> [!IMPORTANT]
> 先核对存档或日志里有没有展开后的真实占地数据（建筑轮廓和位置）。

> - 只有请求、没有占地：D4–D6 用锚点加成员数量画近似轮廓，角标「近似」。D7 改为用 `design.webp` 按功能区分块揭开（遮罩逐区显现），角标「真实数据」（图是真实产物，只是揭开顺序按功能区）。
>
> 素材小卡同理：能从素材目录取到真实俯视轮廓就用真实的；取不到就只写建筑名和用途，不画假轮廓。

## 文案规则

**只写"是什么"，不写"意味着什么"。** 意义交给对话去讲。

- 每屏最多一行图注，不超过 18 字。
- 可以写：名词、数字、地名、坐标、工具名。
- 不写：抒情句、对仗句、问句、破折号金句。
- 不用这些词：终于、每一步、成为、旅程、走进、回到、见证、诞生。

| 不要 | 要 |
|---|---|
| 地图上的选择，成为脚下的空间 | 镜潮 · (−2928, 5392) |
| 每靠近一步，前面的选择都留下线索 | 局部地形 |
| 国度和城市，逐层有了位置 | 七个国度的起点 |
| 这条路，终于回到玩家脚下 | （实机图，不放字） |

## 真实性角标

右下角统一格式：`来源 · 类型`，类型只有三种：

- **真实数据**：直接由存档或日志渲染。
- **近似**：用真实数据，但顺序或时间经过简化。
- **示意**：没有对应数据，只解释原理。

字号 11px，墨色 40% 透明度。只放在角标里，不进图注，也不进台词。

## 实现边界

- 新建独立页面，不改现有 `index.html`。
- 数据来自 `run/saves/geometia_beta3_02/realm_debug/provider_3d25631f_r19200/`。大文件（如 33MB 的 `world_feature_grid.json`）先预处理成精简数组再嵌入，最终仍是单个可离线打开的 HTML。

## 第一轮验收修改（2026-10-27）

验收对象：`wtd-atlas.html`。W、T3 之后的镜头、素材卡、D4–D7 真实占地都保留。只改下面三处。

### 1. T1 设定纸条：从"三个示例"改成"七国名册"

问题：纸条写了共同背景加三个国度，下一拍却落下七个起点，观众对不上数。

改法：纸条改成一份**七行名册**，之后一直留着当图例。

- 顶部一行共同背景（来自 `realm_profiles.json`）。
- 下面七行，每行：色块 + 国名 + 一句不超过 10 字的特点。**色块就是该国之后的领土颜色。**
- 镜潮那一行加小字「固定领土」。这样 T3 里镜潮整片同时出现，观众也能理解。
- T2：每落下一个起点，名册里对应那一行同步加深一下，按名册顺序落点。
- T2–T3：名册缩窄后停靠在右侧，继续当图例；T4 推近时淡出。

### 2. 功能区：拆成"读背景 → 读素材标签 → 声明功能区"三拍，边界最后再画

问题：16 个功能区一次性全部出现，没有来由，也没有边界。

事实先说清：10.20 那次 `city_d4_district` 的声明只有 `groupId`、`role`、`intent`，**没有坐标**。位置写在 `intent` 里，用的是地形语言（例如「平原28北半部」「东南岸线陆侧」）。真正的坐标来自后面各组团的锚点，区的边界是由最终占地长出来的。画面要如实表现这个顺序。

原 D1 拆成四拍：

| 拍 | 画面 | 图注 | 来源 |
|---|---|---|---|
| D1 地形 | 局部地形淡入；平原、台地、岸线等地形块标上原始编号（如"平原28"） | 局部地形 | D3 地形资料 |
| D1b 读背景 | 左侧纸条写出镜潮在 T4 时定下的职责，每项一行 | 镜潮 · 城市职责 | T4 / 城市意图存档 |
| D1c 读素材标签 | 纸条下方排出素材库的用途标签和数量（如"住宿 ×n"） | 可用素材 · 按用途 | 素材目录快照 |
| D1d 声明功能区 | 16 个区逐个写成一行"名称 · 类别"。每写一行，`intent` 里提到的地形块就淡淡亮一下，再在那里放一个软标签。**不画边界** | 16 个功能区 · 尚无坐标 | `city_d4_district` 请求 |

- D7 全城快放结束时，按各区最终占地**第一次画出区界**（细墨线 + 浅色），区名移到区界里。
- 先核对原始 JSONL：第 80 行声明分区之前，是否读过素材标签或目录摘要。读过：按上表顺序。没读过：D1c 挪到 D1d 之后（与"按区查看素材"合并），不要为了好讲调换真实顺序。

### 3. 阵列：加一张"参数单"，每填一格，地图就变一下

问题：素材卡之后组团直接出现，看不出"阵列"是填参数得来的。

改法：D3（写规划）在组团旁边出现一张小参数单，等宽字体，像一张表格。字段**一个一个填上，每填一个，地图立刻对应变化**：

| 填入字段 | 地图同步变化 |
|---|---|
| 锚点 `anchorBlock` (−3040, 5485) | 十字落下 |
| 布局 `layout` / `patternPreference` | 虚线框按这种排法摆开 |
| 数量 `structureCount` 4 | 出现四个空位 |
| 间距 `gapBlocks` | 空位之间的距离调整 |
| 素材 `requiredStructureRefs` | D2 留下的素材卡缩小，落进空位 |

- 字段显示"中文名 + 小号原始键名"，值用请求里的真实数值。只放请求里真实存在的字段，最多 5 行。
- D5 平移：参数单里只有锚点这一格变成新值，整组跟着平移。
- D6 改组：布局和数量两格改写，组团跟着重排。
- D7 快放：右上角快速叠起 16 张缩小的参数单，同时各区展开。

目的：观众看懂"改一个数，城就变"这一件事，后面的快放就不需要解释。

### 修改后的 D 段节奏

D1 地形 → D1b 读背景 → D1c 素材标签 → D1d 声明功能区 → D2 选素材 → D3 填参数 → D4 只保留一栋 → D5 改锚点平移 → D6 改布局成生活巷 → D7 全城快放并画出区界 → D8 预览 / 实机。
