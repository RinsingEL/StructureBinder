# Astra · 第二幕连续讲解稿

前两段保留茶话会已说过的内容；从「国度在山水间落脚」起为本轮新增待录制讲稿。其他伙伴的台词保留在合并讲稿中，本文件只收录 Astra。每页可连续讲述，停顿随画面推进，不必逐句交棒。

## 先认识这片山水

现场记录

画面顺序：Minecraft 已有的山水 → 在规划范围内读取地貌 → 理解水体、起伏与可用空间 → 把地貌资料交给国度规划。

【Astra｜认真】
「好，先把镜头拉远。程序会读取这个种子的地形，把陆地、海洋、地势起伏和生物群系整理成底图，让后面的规划知道哪里有连续陆地、哪里隔着山海。大家现在看到的这些轮廓，就是文明安家的场地条件。我负责把地图读清楚，小克，接下来聊聊，什么样的人会在这里生活？」

## 谁会生活在这里

现场记录

画面顺序：先写下共同的世界背景 → 文化圈共享一些生活习惯 → 每个国度保留地方差异 → 设定继续影响选址与城市职责。

【Astra｜认真】
「我会把这些设定和地形资料一起交给后面的规划，让选址时还能看到这是谁的国度、需要怎样的生活。接下来先确定国度落点和疆域，再挑城市的位置、安排它的职责。选中的位置会留下坐标，职责也会跟着走到城内设计。这样，地图上的一个点，后面才知道该长成港口，还是学院城。」

## 国度在山水间落脚

新增讲稿 · 待录制

画面顺序：先选择国度的起点 → 不同地形有不同的扩张代价 → 扩张要考虑地形与其他国度 → 形成领土，交给全国城市规划。

【Astra｜认真】
「可以把它想成每个国度都有一份向外探索的行动力。每走一步，程序都会看这里是什么地形、要花多少代价，也要考虑周围国度的竞争。山地和海峡会影响扩张，但山脊并不一定就是国界。大家看这些颜色逐渐铺开，最后留下的形状，就是这些条件共同作用的结果。」

【Astra｜默认】
「开头那个落脚点也很重要。现在的流程会提供候选位置和地形资料，让模型结合国度设定作选择，接着由程序计算势力范围。等领土确定，城市规划就有了自己的活动范围。这张图到这里，回答的是大家分别住在哪片土地上；下一张才开始安排城镇。」

## 一国之内，各城有分工

新增讲稿 · 待录制

画面顺序：继承国度设定与实际领土 → 安排城市的职责和分布 → 查看候选与范围，调整方案 → 保存城市名册和设计说明。

【Astra｜认真】
「到了这里，我会把国度设定、领土和候选场地放在一起看：这座城要承担什么事情，选中的地方能不能支持它。模型给出选择和设计说明，程序把结果保存成城市名册。后面设计每座城时，都能接着读到这些资料，知道它在整个国家里负责什么。」

【Astra｜默认】
「看镜潮这个点，保存的位置是横坐标负二九二八、纵坐标五三九二。这是全国地图上给城市留下的起点，到了城里，还要继续安排教学区、宿院和市场的位置。这里一座城承担了全国的多种职责，所以之后看见十几个功能区，也是在展开同一座城。」

## 走近这座城的地形

新增讲稿 · 待录制

画面顺序：全国选址给出一个起点 → 局部扫描看清坡地和水边 → 复核城市的实际场地条件 → 把地貌资料交给城市设计。

【Astra｜认真】
「全国地图适合找方向，镜头拉近以后，我们还要重新看脚下。城市附近哪里连续平坦、哪里抬高、哪里贴着水，都要用局部扫描的资料复核。图上看着挺宽的一片地，走近可能被坡和海湾切开；这些差别，会直接影响院落能摆多大、入口该朝哪里。」

【Astra｜默认】
「这一步整理好的地貌资料会交给城市设计，后面的布局就有共同的依据。比如中央平地适合安排日常人流，高处可以考虑观测，岸边要给水体和通行留位置。我选一个坐标时，也得连着想：这组建筑展开以后，会不会伸进海里，或者挡住旁边的路。」

## 院落和街坊展开了

新增讲稿 · 待录制

画面顺序：先安排功能区和公共空间 → 定位组团，展开建筑与配套 → 检查实际占地和入口关系 → 查看当前预览，再定向修订。

【Astra｜认真】
「接下来才轮到我把这些生活安排写成能执行的设计。先声明功能区，再查素材：这栋楼有多少床位、能做什么，是看作者写下的资料。确定要用的建筑以后，再安排组团起点、成员和布局方式。一个院子里放哪些房子，几组院子怎样靠在一起，都可以分层表达。」

【Astra｜默认】
「提交以后，程序会展开阵列，把建筑的实际占地和入口关系放进预览。模型再根据图和返回的数据，检查原先的想法有没有成立。宿舍有没有到齐，院子是否还留着，市场和食堂能不能接过去，都在这一轮看。需要改哪片，就带着修改说明再提交。」

【Astra｜得意】
「工作台在这里也很有用：素材的形状能看，编译后的组合能看，放到设计里又能对照整座城的位置。人和模型就有东西可以一起指着讨论了。当然，我还会顺手检查引用和版本，免得大家聊得正开心，拿着上一版图纸给这一版宿舍装门——这种热闹咱就省了。」

【Astra｜默认】
「这页选的是十月二十日那次原始调用里的九个讲解节点，中间有省略，大家可以对着下面的行号找原文。先领取场地资料，再提交十六个功能区，接着按区查询素材。左边显示我交给工具的参数和它的返回，下边补上当时公开写下的设计说明。」

## 街区共台，道路接上高差

新增讲稿 · 待录制

画面顺序：自然坡面上，建筑各有落脚位置 → 核心附近的地形，提供本区高程依据 → 同一片台地，承接建筑、铺地和庭院 → 道路连接两端，也要接好真实入口。

【Astra｜认真】
「难点是平面上连起来的线，到了地形里可能一端在楼门口，另一端悬在坡上。所以要把建筑、院子和铺地放到共同的高度关系里处理，给同一片台地确定落脚的依据。大家看动效里那块地面托住整个街坊，之后道路才能沿着这些确定的高度去接入口。」

【Astra｜吐槽】
「我最怕的就是俯视图上一切连通，玩家走过去却发现门前差两格，得先练一下跳跃。所以接路还得看真实入口和沿途高差，再去游戏里走一遍。台地边缘、挡墙和上下台阶也一起看。这里的检查，最后都得回答同一个小问题：人到底能不能顺顺当当地过去。」

## 城市长出地形的形状

新增讲稿 · 待录制

画面顺序：田林成为乡野的主体 → 少量农舍成组散布 → 港区选择真实地形线 → 沿线排列，朝向水面与陆地。

【Astra｜默认】
「出了城区，安排空间的方式也会跟着变。乡野这一边，田和林占主要面积，农舍只是其中少量的生活节点；海岸这一边，则需要先找到可以依靠的地形线，再沿着它安排建筑和朝向。这样给模型的选择就更具体了：是在这片地里拼接，还是顺着这条线展开。」

【Astra｜认真】
「这一页的动效先把关系讲清楚：不同的田林块怎样接在一起，沿岸的房子怎样跟着线转向。它是原理示意，田野和港口的最终实机效果还要继续看。画面上的方块现在能整齐地转过去，真正放进游戏时，岸边的水、坡度和建筑入口仍然要逐个对上。」

## 现在，走进街道里

新增讲稿 · 待录制

画面顺序：方案确认，准备预留与模板锁定 → 激活计划，随世界区块生成 → 到游戏里查看街区与入口 → 这条路，终于回到玩家脚下。

【Astra｜认真】
「设计确认以后，后面还要预留空间、锁定使用的模板，再激活生成计划，随着世界区块生成把建筑放进去。这里每一步都要有自己的记录，才能知道我们现在停在哪儿：方案已经存好了，还是已经开始落地。最后到游戏里看见街道，才轮到现场检查接着往下做。」

【Astra｜感动】
「这些实机画面来自已有的学院测试，和前面的设计回放不是同一轮完整录制。现在就把镜头放低，看看门口、台阶和院子吧。写代码时我总盯着坐标和返回值，真走进来，才会觉得这些检查有了着落：我们终于有一条能站在一起、慢慢看过去的街了。」
