# 立绘透明底处理

参考原有本机 pic 工具，当前保留脚本作为可用的处理实现，后续按实际成图需要调整，不要求沿用旧工作流。脚本路径相对于本 skill 目录，不依赖本机盘符。可以直接阅读本文件执行，放在 devlog 不代表已安装到 agent 的自动发现目录。

## 绘制约定

Gemini 在首次绘制立绘时，自行根据角色配色选择适合抠图的纯色背景，并随成图注明背景色；无需先画复杂背景再替换。角色的头发、眼睛、服饰、配件和特效都要考虑。当前脚本支持绿 `#00FF00`、蓝 `#0000FF`、红 `#FF0000`；若画师选用其他颜色，应调整处理工具，不要求为迁就旧脚本重画。

背景颜色由 Gemini 决定，不预设本组角色统一使用绿幕或蓝幕。先用成图验证透明处理效果，再决定是否需要调整工具或绘制要求。

给画师的背景要求：

> 请根据角色配色自行选择便于抠图的纯色背景，并注明颜色。背景无渐变、纹理、投影、地面、文字、棋盘格，角色边缘不要加背景色光晕。保留参考角色的发色、衣服、配饰和比例。同一角色所有表情保持画布尺寸、人物大小、站位和身体姿势一致，只改指定表情。每个差分单独导出 PNG。

如果输入已有透明通道，不要再用 despill 脚本；它按 RGB 读取，会丢掉原透明度。复杂背景先在绘图工具中换成选定纯色，再检查角色是否被改画。

## 执行

以下命令从仓库根目录运行（Python 3.10+）：

```powershell
python -m pip install -r devlog/tools/ai-screen-despill/requirements.txt
python devlog/tools/ai-screen-despill/scripts/clean_green_screen.py INPUT.png OUTPUT.png --screen green
python devlog/tools/ai-screen-despill/scripts/batch_clean_green_screen.py INPUT_FOLDER --screen green
```

以上 green 仅为命令示例；按 Gemini 实际成图选择对应参数。必须明确传 `--screen`，历史默认值是 blue。批处理只处理指定目录第一层，跳过文件名以 `_despill` 结尾的图片，输出同目录的 `原名_despill.png`。相同 stem 的不同格式会写到同一个输出名；批处理前确保名称唯一，并备份已有输出（重跑会覆盖）。单张处理的输出目录需预先存在，输出路径不要与原图相同。

`--alpha-strength` 默认 2.0；调高会增强透明处理，但不一定改善主体。算法依据整张图的色彩通道，不识别人物轮廓，会同时改变主体中相似颜色，不能视作通用智能抠图。

另保留无第三方依赖的纯绿容差工具：

```powershell
python devlog/tools/ai-screen-despill/scripts/remove_00ff00.py INPUT.png OUTPUT.png --tolerance 0
```

仅支持 8 位非交错 RGB/RGBA PNG。`0` 只去精确纯绿，默认容差 24；不去色边，边缘混色可能留下绿线，同色主体也会被删除。

## 验收与交付

把输出叠在白、深灰和最终视频背景上检查：背景是否透明，发丝、耳尾、眼睛、白衣、小史莱姆是否完整，有无绿边和半透明破洞。确认尺寸和人物站位与其他差分一致。

发现主体损伤时先定位原因，评估调整抠图方法或参数；确实需要换背景时再与画师协调，不默认要求重画，也不要一味提高强度。处理完成不等于视觉验收通过。原始绘图保留；试验图放临时目录，选定的正式透明 PNG 再纳入对应幕的 assets。不要将本机旧照片和全部试验输出一并入库。
