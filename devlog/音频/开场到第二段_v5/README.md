# 开场到第二段：画面卡拍版 v5

2026-11-11。在 [Astra 的 v4](../开场到第二段_v4/README.md) 上改的。v4 是"音乐迁就画面"：速度在 104.94～113.68 BPM 之间调来调去，好让乐句落在原来的画面上。v5 反过来，**先把画面吸附到 108 BPM 的拍子上，音乐就可以一直用 108，不再变速**。

编曲本身（乐器、和声、角色乐句、接话、表情曲线、混音）全部沿用 v4，没有改动；写法和经验见 v4 的 README 和 [参考经验](../开场到第二段_v4/参考经验.md)。

## 画面怎么卡到拍子上

- 节拍表在 [devlog/视频素材/common/beatgrid.js](../../视频素材/common/beatgrid.js)：108 BPM，每段视频从第 0 拍开始，时长取整到小节，几段接起来拍子也是连着的。
- 开场（`opening.html`）和第二段（`act2.html`）排时间时：
  - 每屏字幕从拍上开始，结束时间取到拍上（阅读时间最多少 0.3 秒）；
  - 盖章、PPT 翻页那一屏从重拍（每小节第 1、3 拍）开始，动作正好落在重拍上；
  - 镜头推近、拉回的停顿是三拍，推近本身两拍；天象台的放大、缩回也从拍上开始。
- 代价：开场从 121.8 秒变成 126.7 秒，第二段从 832.5 秒变成 857.8 秒。

## 怎么生成

在仓库根目录：

```bash
# 1. 导出两段卡好拍子的时间表
cd devlog/视频素材/tools
node export_timeline.js ../开场/opening.html ../../音频/开场到第二段_v5/timeline_开场.json
node export_timeline.js ../第二段/act2.html ../../音频/开场到第二段_v5/timeline_第二段.json
cd ../../..
# 2. 生成落点（固定 108 BPM，段落起点也从时间表里算）
python devlog/音频/开场到第二段_v5/build_hits.py
# 3. 渲染；--video 给卡好拍子的画面（开场接第二段，用 tools/record.js 录）
python devlog/音频/开场到第二段_v5/make_preview.py --video 画面.mp4
```

和 v4 一样，配到第二段 T3 翻页之前，约 5 分 14 秒。样片和音频不提交，生成在本目录。

## 和 v4 相比的改动

- `hit_points.json` 由 `build_hits.py` 生成，多了 `sections`（段落起点），速度锚点只有首尾两个。
- `make_preview.py` 的段落起点不再写死成拍号，从 `hit_points.json` 读；加了 `--video` 参数。
- 云端这次用的是 GeneralUser GS 1.47（2.0.3 下载不到），音色会和本机略有不同；本机用 2.0.3 重新渲染即可。

速度 108.0～108.0 BPM；18 个角色落点的起音误差最大 10 ms（v4 的检查方法）；响度 -21 LUFS。好不好听还要 Rin 听。
