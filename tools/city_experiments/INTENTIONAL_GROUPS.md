# 有目的的嵌套组团（网页实验）

当前方案为 `campus-groups.json`，可从“试验方案 → 学院 · 公共广场与嵌套组团”载入。工作台端口由 Python HTTP 服务提供；每次生成启动 Java 离线进程，复用生产道路、台地、挡土和执行器。新增矩形排布与公共空间骨架位于 Java 实验适配层，设计绿化在 Python NBT 合成层实现；均未接入正式 Minecraft 世界生成。

## 排布意图与实例

整体 COURTYARD 围绕食堂前公共广场组合四侧：食堂及生活服务、主教学院落、教学配套组合、住宿组合。主教学院落 4 栋（礼堂、两栋完整翼楼、研究书楼）；教学配套由两个 4 栋 GRID 通过 LINEAR 嵌套；住宿由两个 4 栋 GRID 通过 LINEAR 嵌套；食堂服务 LINEAR 3 栋。共 23 栋、6 个叶阵列、3 个组合。

叶节点没有手工建筑坐标；实际包围盒与逐栋朝向参与排布。展示分区仍分教学与生活，但不控制建筑在整体的固定两块形状。三个教学核心各带一个台地，食堂带生活台地，共四台地。层次嵌套不自动产生新台地。

## 通用配置

在 arrays / compositions 可选 `layout`，不提供时沿用旧生产提案行为：

- `gapBlocks`：4～40，矩形之间的净距。
- `columns`：GRID 列数；各列宽、各行深按实际成员计算。
- `courtWidth / courtDepth`：COURTYARD 中央留空的尺寸；anchorBlock 是此留空中心，核心放在北侧，不强制占据中心。
- `faceInward`：叶 COURTYARD 逐栋根据作者首个实际入口旋转，北/西/东/南四侧分别朝内。
- `crossAlign`：LINEAR 的 START / CENTER / END 横向对齐；例中小服务建筑与食堂对齐正面。
- `purpose`：空间用途说明，作为工作台层级标签。

矩形 COURTYARD 至多四个直接成员；更多建筑通过子组团嵌套，每个子组自身可以包含多栋。组合按完整子组真实包围盒平移，中央留空与子组留空一起平移。四角包围盒超出中央尺寸时会扩大侧边间距，不允许建筑相撞；当前未提供随父组合整体旋转子组的能力。GRID / LINEAR 支持四个 directionDegrees，但院落四侧当前使用世界轴。

## 程序公共空间

`publicSpaces` 按留空节点 ID 配置 `GARDEN / PLAZA`，可替换花卉、绿篱叶片与小树叶片材质，不引用 MG 或学院算法分支。例中院落花园与共享广场都由留空实际掩码产生，完整中央承载面进入所属核心台地。

先保留 5 格主轴/横轴步行空间以及实际道路两侧净距，再生成四块花坛、低绿篱、边缘 6 格小树、座椅。广场花坛缩至边缘，保留集散面积，并有侧袋小井、公告栏、灯。建筑背侧采用连续低花带。建筑、道路、构件、实际台地高程和已有方块优先；位置不安全则不放植物。绿化关闭仅移除花坛/植物，通路、座椅、公共设施保持。

院落留空和向内入口产生实际骨架，组合公共通路作为跨组网络共享；生产障碍绕路器继续避让实际建筑。入口仍无法连接时拒绝发布新版本。新版本生成失败保留上一个成功状态与历史目录。

## 组团间小间隙绿化

场景可选 `gapLandscape: true`，工作台提供“组团间连接绿地”开关。它使用实际核心台地边界识别相邻空隙，不改变建筑、道路或台地排布。两侧边界的地面路径距离合计不超过 32 格，连通片至少 60 格；水域及两格岸边、陡坡、与台地高差超过 6 格的位置排除，道路两侧保留两格净距。

连接片保持现有地面高程，生成连续草地、分层低灌木和花带，内部较宽平缓位置安排间距至少 14 格的疏树。座椅只尝试与附近道路同高的完整平地，条件不足则跳过。规则不引用学院、文明或具体建筑编号，当前在 Python 离线拼合阶段执行；没有接入实机原版树木的清理。

R21 保持 R20 的 23 栋建筑、4 处台地及道路几何，识别 5 片小间隙，生成 103 个低灌木、136 株花和 10 棵树，本例未找到合适座椅位置。3 项间隙单元测试覆盖小间隙、水域、深谷和远距离；4 项集成测试检查真实写入及道路净距；22 条实际输出方块步行路线通过。浏览器证据在 `runtime/campus-workbench/gap-landscape/`。

## 素材与验证

### R24 近邻连接台地

R28 移除台地内部重复的建筑地块围栏：来源为 Java 施工的 SURFACE_OR_ENGINEERING，并非建筑 NBT。离线合成仅跳过核心台地内部、地表上一格且上方没有堆叠构件的墙/栅栏；明确的 TERRACE_EDGE_*、台地外边、灯柱和模板方块保留。实际移除 1420 个围栏方块，metadata 的 removedBuildingEnclosures 留存记录；Java 原执行报告保持原始证据，不宣称此规则已经改进正式模组生成。R28 的 4 项集成和 22 条实际输出步行检查通过；显式台地设施计划与构件检查和 R26 相同。浏览器证据 no-building-enclosures/。

R26 补充道路两侧同步：一侧连接面触发后，使用对应真实路面横断面的宽度向另一侧延伸，无需另一侧再次满足两核心距离条件。已有台地、水域/两格岸边、陡坡、与路面高差超 6 格、构件和真实既有方块约束仍优先；另一侧没有相邻台地时，以触发侧的道路边缘外延宽度为上限，且不超过 smallGapMaxBlocks。同步后统一执行承载、内边撤除和暴露外边界防护。roadBands 缺少内部街巷时，使用真实路面方块的局部横纵连续长度识别走向。`synchronizedColumns` 单独记录实际新增同步格，R26 共 336 格，连接面合计 4444 格。4 项连接回归覆盖单侧触发、已有台地截断、水域/深谷保留与真实支撑；4 项集成与 22 条步行路线通过。浏览器证据 `runtime/campus-workbench/paired-road-terraces/`。

当前示例使用 `gapSurface: CONNECTION_TERRACE`，把近邻道路两侧间隙转成有连续承载、石砌支撑和外围防护的连接台地，不改变原核心建筑和道路。外围风格读取相邻核心的 styleRef；同高接缝旧栏杆、柱与帽在四邻域均有承载时撤除，有真实落差的位置保留防护。不同高程仍分段连接，不强行把两侧核心统一抬平。连接地表保留两格铺装边，再安排花带和草地；原始核心仍由 Java 生成，连接施工是离线合成适配，单独记录在 `connectionTerracePlan`，不伪装成 Java 施工报告。

`smallGapMaxBlocks` 默认 32，范围 4～64，网页可调。判定是候选地面格到两侧真实台地边界格的最短四邻域路径距离之和不超过阈值，包含道路宽度，不使用建筑中心距；平直情况下边界格中心距离 32，相当于最多 31 格中间净空。水域/两格岸边、陡坡、高差超 6 格及非相邻宽阔空地排除；保留原规则至少 60 格连通片的面积门槛。连接模式道路高程延伸范围使用同一阈值，旧 ROAD_LEVEL 仍为 16 格。

R24 实际增加 4108 格连接承载，撤掉 143 个同高内部防护方块，新增 131 格暴露外缘/层级落差防护。6 项间隙回归包含 32/33 格阈值边界，连接台地回归验证石砌支撑与内部栏杆撤除，4 项集成与 22 条真实输出步行路线通过。浏览器证据位于 `runtime/campus-workbench/connection-terraces/`。

### R23 道路两侧间隙同高

用户修正目标为“邻近城区与中间道路形成整体”。当前示例增加 `gapSurface: ROAD_LEVEL`：使用实际 ROAD_SLAB / ROAD_STAIR 的 targetSurfaceY 将邻近道路的小间隙整平，再生成草地、植物和收边。道路距离可以经过既有核心台地，但整地掩码排除台地及道路本身；从路面向外延伸最多 16 格，仍只处理相邻核心边界之间合计不超过 32 格的间隙，水域、岸边、深谷和陡坡不填。原始地面与目标路面高差超过 6 格不处理。地表支撑填土，较高原地面挖到目标高度；已有建筑、灯、墙及其他设施写入优先。

此模式下两格道路净距仅禁止植物和收边，地面工程可以进入净距以消除路边落差。`engineeringColumns` 记录原高程、实际目标、所跟随路面坐标和距离；收边与树木读取整地后的高度。关闭 greenery 保留连接地表；关闭 gapLandscape 才同时关闭连接工程。未设置 gapSurface / 设置 NATURAL 的旧示例沿用 R21 原地貌模式。R23 处理 945 格连接地表，其中 383 格实际改变高程；道路与建筑排布保持 R22 原样。5 项间隙测试、4 项集成测试、22 条真实输出方块步行路线和实际浏览器检查通过，近景位于 `runtime/campus-workbench/road-level-gaps/road-gap.png`。仅属离线合成工程，未接正式 MC 原地貌植被清理；不同道路高程仍形成对应的分段地表，不保证整个城区为单一平面。

R22 增加可选 `landscapeBorder`，显式指定 `straight / outer / inner / end` 四项基础设施 assetId。示例使用 MG-46～49-v01：每件是 1×2×1 的真实 NBT，包含石砖承载与一格楼梯或半砖，带 infrastructure 标签，不能作为阵列成员。程序读取实际 NBT、验证哈希，依照种植掩码的八邻域轮廓选择转角与旋转；不硬编码文明或素材编号。院落与广场花坛收边，缺承载、道路净距、构件、树干及树冠处跳过；组团间只收近道路的一侧，保留背侧自然过渡。关闭 greenery 同时关闭收边。

本例落地 398 件（院落 260、广场 52、小间隙 86），含直段、内外角及半砖端头。3 项轮廓测试检查四角旋转、L 形内角、单格/细线排除；4 项集成测试检查程序消费与真实 NBT 合成、绿化开关。22 条步行路线通过，浏览器证据位于 `runtime/campus-workbench/landscape-borders/`。素材可通过 `python -m studio.landscape_fixtures` 或 `studio.build` 按 MG 编号重建。

新增 MG-43-v01 小实验室、MG-44-v01 洗浴房、MG-45-v01 小商店（门前棚摊、柜台、货箱包含在模板内）。MG-34-v02 / MG-37-v02 是独立建筑版本，侧面上层收为封闭护栏阳台，不依赖外部连廊；原 v01 连接素材保留。

- `python -m unittest discover -s tools/city_experiments -p test_intentional_layout.py -v`：真实 Java 矩形/朝向/嵌套留空平移、另一文明素材、真实 NBT 公共空间/碰撞状态与绿化开关。
- `check-campus-walk.py <成功版本目录>`：由冻结道路求路线，对真实输出方块做单端起步的保守步行检查；不补任何地板。23 栋对应 22 条组内/跨组路径，不允许截断或未到达。不是 NPC 或游戏内验收。
