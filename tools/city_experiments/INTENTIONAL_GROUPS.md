# 有目的的嵌套组团（网页实验）

当前方案为 `campus-groups.json`，可从“试验方案 → 学院 · 公共广场与嵌套组团”载入。工作台端口由 Python HTTP 服务提供；每次生成启动 Java 离线进程，复用生产道路、台地、挡土和执行器。新增矩形排布与公共空间骨架位于 Java 实验适配层，设计绿化在 Python NBT 合成层实现；均未接入正式 Minecraft 世界生成。

## 排布意图与实例

整体 COURTYARD 围绕食堂前公共广场组合四侧：食堂及生活服务、主教学院落、教学配套组合、住宿组合。主教学院落 4 栋（礼堂、两栋完整翼楼、研究书楼）；教学配套由两个 4 栋 GRID 通过 LINEAR 嵌套；住宿由两个 4 栋 GRID 通过 LINEAR 嵌套；食堂服务 LINEAR 3 栋。共 23 栋、6 个叶阵列、3 个组合。

叶节点没有手工建筑坐标；实际包围盒与逐栋朝向参与排布。展示分区仍分教学与生活，但不控制建筑在整体的固定两块形状。三个教学核心各带一个台地，食堂带生活台地，共四台地。层次嵌套不自动产生新台地。

## 通用配置

在 arrays / compositions 可选 `layout`，不提供时沿用旧生产提案行为：

- `gapBlocks`：4～40，矩形之间的净距。
- `columns`：GRID 列数；各列宽、各行深按实际成员计算。
- `courtWidth / courtDepth`：COURTYARD 中央留空的尺寸；anchorBlock 是此留空中心，核心放在北侧，不强制占据中心。
- `faceInward`：叶 COURTYARD 逐栋根据作者首个实际入口旋转，北/西/东/南四侧分别朝内。
- `crossAlign`：LINEAR 的 START / CENTER / END 横向对齐；例中小服务建筑与食堂对齐正面。
- `purpose`：空间用途说明，作为工作台层级标签。

矩形 COURTYARD 至多四个直接成员；更多建筑通过子组团嵌套，每个子组自身可以包含多栋。组合按完整子组真实包围盒平移，中央留空与子组留空一起平移。四角包围盒超出中央尺寸时会扩大侧边间距，不允许建筑相撞；当前未提供随父组合整体旋转子组的能力。GRID / LINEAR 支持四个 directionDegrees，但院落四侧当前使用世界轴。

## 程序公共空间

`publicSpaces` 按留空节点 ID 配置 `GARDEN / PLAZA`，可替换花卉、绿篱叶片与小树叶片材质，不引用 MG 或学院算法分支。例中院落花园与共享广场都由留空实际掩码产生，完整中央承载面进入所属核心台地。

先保留 5 格主轴/横轴步行空间以及实际道路两侧净距，再生成四块花坛、低绿篱、边缘 6 格小树、座椅。广场花坛缩至边缘，保留集散面积，并有侧袋小井、公告栏、灯。建筑背侧采用连续低花带。建筑、道路、构件、实际台地高程和已有方块优先；位置不安全则不放植物。绿化关闭仅移除花坛/植物，通路、座椅、公共设施保持。

院落留空和向内入口产生实际骨架，组合公共通路作为跨组网络共享；生产障碍绕路器继续避让实际建筑。入口仍无法连接时拒绝发布新版本。新版本生成失败保留上一个成功状态与历史目录。

## 素材与验证

新增 MG-43-v01 小实验室、MG-44-v01 洗浴房、MG-45-v01 小商店（门前棚摊、柜台、货箱包含在模板内）。MG-34-v02 / MG-37-v02 是独立建筑版本，侧面上层收为封闭护栏阳台，不依赖外部连廊；原 v01 连接素材保留。

- `python -m unittest discover -s tools/city_experiments -p test_intentional_layout.py -v`：真实 Java 矩形/朝向/嵌套留空平移、另一文明素材、真实 NBT 公共空间/碰撞状态与绿化开关。
- `check-campus-walk.py <成功版本目录>`：由冻结道路求路线，对真实输出方块做单端起步的保守步行检查；不补任何地板。23 栋对应 22 条组内/跨组路径，不允许截断或未到达。不是 NPC 或游戏内验收。
- `capture-campus-groups.mjs`：实际浏览器检查层级选择、全景、两区、院落近景、俯视与去屋顶，无脚本错误和缺纹理。

当前视觉用于观察构图和尺度。现有大模板地块仍可能留有较大草地/底板；D3 海岸与高程仍是 16 格采样，不声称达到参考图的精细地形与美术密度。
