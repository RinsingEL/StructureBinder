# 场地构图阵列

控制台入口：`http://127.0.0.1:8767/spaces`，学院工作台侧栏“场地构图”可直达。当前为独立平地构图实验，不覆盖学院岛版本、不新增核心台地，不把构图预览宣称为正式游戏生成。

## 可编辑内容

界面提供场地宽深（32–128）、种子、地表、步道宽度，以及节点选择、相对 X/Z、指定素材或池、POINT/LINE/GRID/RING、数量、间距、半径、旋转和列数。完整方案编辑器可以增加/删除节点、嵌套组、留白区、入口及素材池权重；导出 JSON 可复用。修改后需点击生成，失败保留上次画面并显示原因。

节点以中心坐标放置，子节点使用父组相对坐标；父组旋转同时作用于子节点位置与朝向。一个节点只能有 assetId、pool、children 三者之一。环绕支持 faceCenter 将北向素材朝向中心（四向取整）；嵌套最多六层、128 个节点、200 个素材实例。整个场地共享地面基准，暂不支持节点局部抬高或下沉。

素材允许目录中 infrastructure 消费类型或 landscape 标签，保持原目录分类，不把所有景观强制改成建筑核心。实际读取并校验 NBT 哈希；程序保留已有模型尺寸，不缩放。加权素材池使用固定 seed，候选不合适时尝试其他候选；全失败会明确拒绝，不静默少放。整包围盒保守避让，素材空气不清除地面。

entries 表示必须连接的地面端点，可以是边缘入口，也可以是场内目的地；clearings 为禁止素材进入的矩形留白区，允许人流穿过。完成主体构图后，A* 按配置宽度绕开完整占地并留一格缓冲，连接入口、复用已有路径。路径当前为轴向折线，不是曲线景观道路；不自动为每个素材安排观赏入口。

## 三个示例

阅读花园新增 `plantingZones`：每区声明 id、左上角 x/z、width/depth、pool、count、spacing、shape（RECTANGLE / ELLIPSE / PATH_EDGE）。先完成主体与道路，再在区内既有草地选址；模板完整足迹避让道路及一格缓冲、原成员及中央留白，不能放下的候选跳过，并报告 requested/placed。支持高树、灌木、花丛与短绿篱复用已有素材池，单次最多新增 400 个配套。未配置种植区时保持原行为。

`plantingDensity`（0–2）控制种植目标数量，界面“植物丰度”显示 0–200%；空间已满时提高目标不保证增加实际数量。默认阅读花园新增 108 处植物，总成员 124；原 16 个主体成员和通路保持不变。直达：`/spaces?example=garden`。

配置位于 `space-examples.json`，均由 `space_composer.py` 同一解释器消费。

| 示例 | 构图 | 实际成员 |

| 星泉广场 | MG-10 大喷泉居中，8 株环形树、4 处角落花槽，四侧入口绕行 | 13 |
| 阅读花园 | 两个嵌套 MG-29 阅读小庭，树群、花槽、灌木与中央留白 | 16 |
| 仪式庭院 | MG-42 星石标景暂代主坛，两侧树列及花槽框景，前方集会留白 | 17 |

## 接口与证据

- GET `/api/spaces/examples`：三个完整可编辑配方。
- POST `/api/spaces/preview`：请求为完整场地方案；与学院构建相同的同源限制和 `X-Campus-Write: build` 头，最大 200KB，使用同一串行锁。返回 world、placements、routes、summary；不修改学院 state.json。
- GET `/api/campus/catalog`：新增 tags，供场地素材选择器筛选。

验证：`python -m unittest test_space_composer`（在 city_experiments 目录）；`npm run build` 和 `node scripts/capture-spaces.mjs`（在 structure_studio 目录）。三种实际方块场景均通过离线碰撞通行检查，单入口作为种子，其他三个端点作为目标。测试还覆盖确定性、嵌套平移、占地碰撞、留白侵占及入口阻挡。

截图与检查报告：`runtime/space-composer/`。正式城市公共空间接入、可变高程、游戏内水体行为和完整关系约束语言尚未实现。
