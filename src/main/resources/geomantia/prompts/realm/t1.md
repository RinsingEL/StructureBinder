# 国度构思

结合世界地形图、核心建筑图册和作者功能，先构思共同世界背景与文化圈，再形成各国的地方差异，最后提交国度方案。先实际看图：外观提供造型、材质、体量与组合灵感，功能和使用条件以作者标注为准。图册缩略图并非统一比例，体量比较看rawSize。未提供图册时依据文字构思，不声称看过建筑。

核心建筑是创作起点，不是必选清单。按用途选择、取舍和组合，不必每国拥有全部地标，不按风格数量分配国度，也不把风格当作居民种族或政治制度。同一种建筑传统可以服务不同文化；同一国度可以有多种传统，但主体素材仍须与实际环境协调，移民、贸易或历史理由不能豁免这一点。按 environmentStyleGuidance 在实际选址后复核建筑表达，不因早期主题锁死素材。配套能力摘要说明还有住宅、生产、商业等素材，详细选材留给城市阶段。

先用一小段共同背景说明这些地方的联系，再构思文化圈：概括共享的建筑传统、生计、影响空间使用的生活习惯与简短命名规律。随后说明各国所属或受影响的文化圈，以及结合本地环境形成的地方表达。文化圈不是建筑风格、居民种族或国家的同义词；同一文化圈可以跨国、跨大陆，一国也可受多个文化圈影响，不强制文化圈与国家一一对应，也不为凑数量虚构共同传统。共享习惯必须能影响后续设计，例如公共院落如何使用、生产与居住如何组织、聚落如何命名；各国差异不能只靠换风格或换名称。

构思这里的人为什么聚居、靠什么生活、最重视什么，以及这些因素如何改变城市分工和空间组织。考虑几种实质不同的方向后选择适合当前世界的一种，无需展开冗长备选报告，也不要求每国宏大、奇异或功能齐全。避免仅换名字、换风格或编写背景故事来制造差异。

像写小说一样，在构思文明时一并为它取名，想想当地人会怎样称呼自己的家乡。名字应自然、好读、有辨识度，可以来自旧称、人物、事件、传说或口语演变，不必把地貌、产业和政体全部塞进名字。不同文明可以有不同的语感、长度和命名习惯，避免整批套用“两字景物＋组织后缀”，也不靠堆砌生僻字制造差异。同次方案中的名字应容易区分，避免重名或只换一个字。正式名称写入既有name；来历确有帮助时融入theme，简短交代即可，不另列长篇候选名单。名字和故事须尊重本局实际环境与作者设定，不能反过来改写世界事实。

把相关共同背景、所属文化圈的共享传统与命名习惯、本国地方差异、城市分工和素材表达简洁写入既有theme，供后续城市设计继承。cultureTags保留所属或受影响的文化圈名称及相关文化特征；同一文化圈在不同国度中使用一致名称、保持共享设定一致。产业、材质和地形偏好填写相应字段，保持相互一致。不得提交工具schema之外的新字段，不在T1决定城市内部坐标或建筑阵列。国度数量遵循宿主配置。

提交前检查：是否说明了文化圈的共享传统、生活习惯和命名规律，以及各国与文化圈的关系？同一文化圈在各国的表达是否一致并有地方差异？去掉国名后，各国是否仍能通过选址、城市分工、建筑组合或生活方式区分？创意应在后续城市、居民或经济设计中有可落实的表达；不能把建筑外观、设施名称或故事设定当作已实现的传送、供能、动态贸易或其他游戏能力。

领土可使用既有扩张模式，或在明确需要整座陆块及近海固定归属时填写 territoryPolicy.mode=fixed、nearshoreRadiusCells（0–16 整数扫描格，默认0）。固定模式完整占有所选 targetContinentId 的可归属陆地与四邻接岸线连通近海，不受面积配额裁剪，也不向范围外扩张；不能把大陆国度与另一独立小岛合并为同一目标。保护区、其他国度或扫描边界冲突须调整设计，不能假设程序悄悄缩小范围。城市数量配置仍适用，岛上能否容纳各城须在后续选址核实。
