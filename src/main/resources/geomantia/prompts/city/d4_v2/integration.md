# 阶段三：复核全城，修订并扩展

## 目标

通过当前实际全城图和必要局部图，检查城市要求、地形关联、整体性和规模；把薄弱部分改到足以承担这座城市的职责。

## 复核顺序

1. **要求是否落实**：按 citySeed 的主要功能与玩家活动检查实际保留内容。核心周围是否有足够配套、公共空间与通行组织？哪些活动还缺少承载空间？
2. **地形是否参与设计**：位置与朝向、岸边和高差、安静与热闹区域、保留的自然空间是否有清楚的用途依据？计划中依赖的地形适配是否仍待施工？
3. **是否是一座整体城市**：在全城图上依次检查：能否一眼读出主轴和中心？一级地标是否唯一且位于轴线尽端或高点？是否有远离骨架、只靠长路连接的孤立组团？根锚点是否过多、过散？广场是否比围合它的建筑大得多而显得空洞？庭院四周的楼是否朝向庭院？是否所有组团都用同样的间距和密度？隔河和合理留白可以成立，说明图上的依据。
4. **体量是否相称**：比较本城服务地位、功能需求、现场容量和图中实际体量。还缺哪些承担职责的配套或次级公共空间？新增内容应贴着骨架补进已有组团或广场边，不在远处另开组团。停止扩展的理由可以是职责已有承载、容量限制或需要保留的环境；"还有空地"不是扩展理由。

## 修订操作与规则

把发现的问题落实到具体功能区，用 city_d4_district 指定 targetDistrictId，提交新的完整 districtDesign、designAnswers、当前 baseDraftHash 与 assessment。其他区设计和布局保留。city_d4_mark 和 city_d4_integrate 是可选空间组织能力，其用途和允许修改范围以 schema、submissionRules 为准。

正常生成只对复核中明确影响城市要求、整体性或体量的问题作必要修订，整体性问题优先；修改后重新编译并看新图，避免无目标的循环。功能确有需要时大胆配置阵列和配套，图中已成整体且职责有承载则完成。用户明确要求测试或修订时，可复用同一 D3 多轮比较。工具给出 finalize 作为 nextAction，表示允许提交，完成判断仍由上述四项复核决定。

## 最终保存依据

assessment 基于当前图，分别说明四项目标，指出主轴、中心、一级地标的具体位置与可见关系、有效配套及停止扩展的理由。先解决影响职责成立的必需内容缺口；可选填充和适配告警结合用途判断。若当前证据不足，调用 city_d4_preview 补充图像。

满足这些依据后，用 city_d4_finalize 提交当前 baseDraftHash、assessment、functionsPreserved=true。想保留后续修改机会时明确 autoAdvanceAfterD4=false；默认会推进后续施工准备。无法改善或遇到宿主阻塞时，如实报告当前结果与剩余问题。
