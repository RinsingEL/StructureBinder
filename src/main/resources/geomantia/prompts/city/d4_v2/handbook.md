# D4 城市设计流程

## 设计目标

把本城要求展开成一座适应现场地形、功能有层次、连续成整体、与地位相称的城市。每次进入世界都应能探索一座有文明生活的异世界城市；依据这次地形和作者素材作出具体设计。

设计与终审始终检查五件事：

1. **功能展开**：citySeed 的定位、coreFunctions、gameplayRequirements 与服务地位，要展开成可以分辨的片区和子区，每个子区有自己的活动和空间。几个大标签各放几栋楼不算完成。
2. **场地利用**：D3 上每一片主要用地都有去向：承担哪个片区或子区，或者为什么保留。
3. **全城成为整体**：骨架清楚，片区之间连续相接，没有远离骨架、只靠长路挂着的孤立组团。整体性约束的是城市是否连续，不限制城市的大小。
4. **城市生活**：工作、公共、居住都有足够的空间，白天、饭点、傍晚和夜里都有地方热闹。
5. **体量与地位相称**：首都、全国唯一或区域中心的城市，应当是这个国家或地区最重要的地方。

## 先读懂这座城的地位

- 从 citySeed 的 role、serviceHierarchy 和 coreFunctions 判断这座城在国度里的分量。首都或全国唯一的城市，职责要展开得最充分。
- theoreticalScale 与 scaleDesignTask 的建议数量只是初版的起点，不是上限；职责与场地需要时，大方超出。
- citySeed 里“紧凑”“保留林地”“按可建面积取舍”之类描述，理解为城市要连续、留白要有理由、素材要按实际尺寸挑选，不是要求城市小。
- 把对规模的判断和理由写进城市意图。

## 功能展开：片区 → 子区 → 建筑组 → 建筑

| 层级 | 是什么 | 在 D4 中怎么表达 |
| --- | --- | --- |
| 片区 | 城市的一大类职责，例如教学、居住、迎客与贸易 | 由若干相邻子区组成，在城市意图中说明 |
| 子区 | 有自己的活动、服务对象和空间组织的一块 | 总览中的一个 district，有一个核心 |
| 建筑组或院落 | 子区里围合庭院、街坊或轴线的一组建筑 | 一个阵列，或嵌套组合 |
| 建筑 | 单栋 | 阵列成员 |

展开的方法：对每个片区问三件事——谁在这里，做什么，什么时候来。活动不同、服务对象不同、需要的空间气氛不同，就是不同的子区。每个子区除了核心，还要有让人停留和生活的配套：自习、休憩、餐饮、仓储、庭院或小广场。同类子区相邻，共同形成一个片区。

下面用一座港口商贸城示范展开的方法；学院、矿城、王都同理。子区的名称和数量由本城职责与场地决定，示例不是模板：

```text
港口与贸易片区：码头装卸区｜货栈街｜商会与税关｜水手酒馆街
市场片区：      中央集市广场｜手工作坊街｜行商客栈区
居住片区：      商人宅院坊｜工匠联排街｜渔民湾岸村
公共与信仰片区：神殿广场｜灯塔与瞭望台
```

两种情况都要避免：一个用途只放一栋楼；把每个用途词都单独开一个区。子区要有自己的空间表现（自己的院落、街道或广场），不能只是换了一个名字。

## 场地盘点：每片主要用地都有去向

- 全城构思时，从 D3 总览列出主要用地，例如“北部平地”“东北林地”“西南岸”，写明各自承担哪个片区或子区。
- 决定保留的用地要写具体理由，例如：这条林带是观测片区与居住片区之间的静区；这片坡地高差过大，只适合做观景台；这片水湾留给码头。只写一句“保留林地”不够。
- 城市沿骨架向新用地生长：新片区与已有片区相接，不在远处另起孤立组团。
- 不追求覆盖率，不要求填满空地；要求的是每片地都经过考虑。

## 空间构图手法

以下手法让城市“成为整体、有层次”，按顺序使用。

### 1. 先定骨架：一条主轴、一个中心

- 在 D3 地图上找出入口（岸边、道路来向或低处）和制高点或最好的平地。连接两者的方向就是**主轴**，城市最重要的序列沿它展开：入口 → 前导空间 → 中心广场 → 核心建筑。
- 片区沿主轴和次轴展开，并向两侧用地延伸。中心广场或主庭院放在主轴与次轴的交点；主要的二、三级建筑放在广场四边或轴线端点。

### 2. 子区内成组，子区之间相接

- 每个子区用一个根组合加嵌套组织成整体，用 anchorBlock 定位；同类重复建筑放进同一个阵列。不要把同类建筑拆成许多 1～2 栋的小组散在各处。
- 子区之间紧邻相接，共享道路、广场和庭院边。连续是指子区与子区挨着生长，不是指全城只能有几个组团。

### 3. 建筑分级：一个地标，少数次级地标，其余成组

- **一级地标**：全城最大、最高、功能最重要的那座（例如礼堂、宫殿、主神殿）。放在主轴尽端或制高点，正面朝向主轴或广场。全城只有一个。
- **二级地标**：各片区的主建筑。放在广场边、轴线另一端或次轴端点，与一级地标保持可见关系。
- **普通建筑**：同类小建筑（课堂、宿舍、商铺、作坊）放进同一个阵列，组成街坊或围院。

### 4. 公共空间是“图形”，不是剩余空地

- 先定庭院和广场的尺寸，再让建筑围合它。用 COURTYARD 阵列并开启 `faceInward`，让围合建筑正面朝向公共空间。不开 `faceInward` 的庭院，四周的楼会背对庭院。
- 尺度要和围合它的建筑相称：庭院边长约为围合建筑宽度的 1～1.5 倍，主广场约 50～80 格。超过周边建筑体量很多的空旷广场会显得空洞。
- 同一条主轴上，空间应有收放：前导空间较窄，中心广场开阔，核心庭院较安静。
- 绿化也要有结构。用 public_realm 的 `spaces` 为主要公共空间设计构图：主路两侧用 PATH_EDGE 种植区或 LINE 布置行道树；广场中心放一个 POINT 焦点；庭院用 RING 或 GRID 对称布置。`greenery` 与 `fringe` 的随机撒点只作为底色。

### 5. 疏密梯度：中心疏朗，生活紧密，外围舒展

- 不同组团用不同的 `gapBlocks` 与 `densityClass`。参考值：地标与主庭院 8～12，宿舍、商铺、作坊街坊 4～6（DENSE），农田与苗圃用 CONTIGUOUS 紧贴成片，放在外围。
- 所有组都用同一个 gap、同一个密度，是“看起来均匀撒开、没有层次”的主要原因。

### 6. 地形承担层级

- 一级地标占高点或主轴尽端；台地按重要性分级，核心区台地最高，广场与生活区逐级降低。
- 岸边、低地给入口、码头和农林；陡坡、水湾和林带作为片区之间的自然分隔，并说明它们在构图中的作用。

### 7. 阵列拆分规则

只有空间用途不同时才拆分阵列（例如“围合主庭院的楼”和“宿舍街坊”）。同一用途的重复建筑放进同一个阵列，用 count 与 fillPools 控制数量。子阵列通过嵌套组合到本子区的根组合里。

## 工作、居住、公共与人口

功能区按人在一天中去哪里分成三大类，在功能区 role 开头写明：

| 大类 | 什么时候人多 | 怎么做 |
| --- | --- | --- |
| 【工作】 | 白天 | 按职责展开，写清岗位和服务对象 |
| 【居住】 | 夜里、累了 | 随工作与服务对象做大，宁大勿小 |
| 【公共】 | 饭点、傍晚、节日 | 随全城人口做大，放在居住与工作之间的通勤路上 |

顺序：

1. **先展开空间，再估人数。** 工作子区展开后，才知道需要哪些职业和服务对象（例如学生、旅客、病人）。
2. **公共与居住做足。** 居住街坊和公共空间宁可宽裕：多种住宅、几处食堂或酒馆、能停留的广场。这些是城市生活的主体，不是工作区的附属。
3. **最后核对数字。** 人数用范围估算，用来检查床位、岗位与公共容量是否大致可信；不要为了对上某个数字去压缩城市，也不要在精确入住率上反复修改。

templateFacilityCapacities 的 workplaces 是模板里的工位总数，不等于在岗人数：居民模组对每栋的在岗人数另有上限，按两者中较小的一个估算；上下文没有给出上限时按每栋约 4 人估算。在 districtDesign.population 中：工作子区填 jobs 和服务对象、residents 为 0；居住子区填 residents 与 housingGroupIds；公共子区在 purpose 写明容量与服务对象。同一个人只统计一次。

## 对照示范：魔法学院的骨架

下面是工作台中一座“看起来是整体”的魔法学院的骨架，只示范主轴与中心的组织；实际城市的每个位置都应继续展开成子区，场地也应按“场地盘点”逐片决定。

```text
海湾码头（东南岸）─┐
                   ▼
院务塔（南端，前导）  两侧：药草温室庭 / 器材店
        │ 主轴（南→北，沿坡上行）
星泉广场（主轴与东西横轴交点，泉水居中）
   西：藏书馆（二级地标）    东：长桌食堂（二级地标）
        │
星穹主院（COURTYARD + faceInward：礼堂居北，双教学翼楼东西围合）
        │
礼堂（一级地标，主峰，台地最高）     东肩：观星台（二级地标）
外围：西北书院课堂（DENSE 网格）、东侧宿舍街坊（DENSE 网格）、西南试种田与苗圃（CONTIGUOUS）
```

要点：只有一条主轴；广场四边全是重要建筑；生活与教学紧贴广场两侧；台地自北向南逐级下降；农林和码头在外围低处。

## 流程与阶段成果

| 阶段 | 目标 | 本阶段需要形成的成果 |
| --- | --- | --- |
| 理解要求与场地 | 读懂地位，盘点场地 | 本城分量与规模判断；主要用地清单；入口、制高点、主轴方向 |
| 全城构思（OVERVIEW） | 定骨架，展开片区与子区 | 城市意图（主轴、中心、一级地标；片区与其子区；每片主要用地的去向）、按主次排列且标明大类的子区 districts、全城设置 |
| 逐区设计（DISTRICTS） | 把每个子区做成有生活的组团 | 建筑与阵列、嵌套、公共空间和景观、本区 population，以及初次编译结果 |
| 全城复核与修订（INTEGRATION） | 看图检查五项目标 | 未展开的功能、无去向的用地、不足的公共与居住、孤立组团；定向修订并再编译 |
| 最终保存 | 证明五项目标均已落实 | 当前预览的具体 assessment、功能保留确认与定稿 |

总览在第一个子区保存后锁定，所以片区与子区要在总览时就展开完整。当前 d4Workflow.instruction 说明本阶段操作。程序自动推进只代表已保存一份有效初版；城市设计是否充分，仍需在全城复核时判断。

## 信息与工具如何使用

先读 citySeed、scaleDesignTask、D3 总览和 siteReviewDecision，再按本区用途查素材。materialCatalog 提供摘要；city_d4_materials 查询分类、原始用途、风格与尺寸，city_d4_example 查询布局案例及 public_realm 公共空间目录，city_d4_blocks 查询实际方块。具体工具参数以本次 schema 和 submissionRules 为准。无需为了设计读取整份存档或编译几何。

素材的特色/通用类别、基建/景观标签、用途和风格相互独立。本次核心、必需配套、可选填充由设计决定。作者的原始用途与风格是依据，未实现的传送、供能等玩法不得从名称推断。

## 字段与程序边界

- 阵列算法：GRID、LINEAR、COURTYARD、CENTER_SYMMETRIC、COMPACT、ORGANIC_COMPACT、CONTIGUOUS。先明确空间目的再选算法。
- 根建筑组或根组合用 anchorBlock 明确世界方块坐标；嵌套成员由父布局组织，省略独立坐标。按 D3 地图判断位置，程序负责具体成员落位和编译反馈。
- 一个功能区声明一个核心，相关组共享该区台地归属。核心代表功能和高程归属，几何中心由设计决定。
- 道路通过明确 CONNECTION 服务真实目的地。public_realm 提供可组合的庭院、广场模板和池。
- D4 预览用于检查平面组织、边界、碰撞与实际保留内容；支撑、台地和跨水等适配仍需后续施工。将计划内容、预览保留内容和施工结果分清。

## 看图修订与停止依据

正常生成先完成各区有效初版，再实际读取当前 baseDraftHash 对应的局部与全城预览。修订优先级：功能没有展开、主要用地没有去向、公共与居住不足、孤立组团与轴线断开，这些高于局部美化与数字核对。避免为了细枝末节反复重画。输入错误按反馈修正，程序故障与失败预算遵循宿主状态。

完成判断须回答五项目标，指出具体区域和可见关系：每个片区展开成了哪些子区；每片主要用地承担什么或为什么保留；工作、公共、居住是否足以形成城市生活；全城是否连续、有层次。“不报错、不出界、全部保留”只说明程序可行，不说明城市已经设计充分。


## 乡野片区与地形线

乡野是大片田林中的少量农舍组合。景观用 growth.ruralMosaic=true，按 D3 cellStepBlocks 换算 targetCellCount；parcelCount 控制田林分块，多种作物/林块使用不同景观与作者 fillSelection。每块可以几千格，规模独立于农舍数量。坡度、峡谷、水体与已占空间仍约束生长，分块之间留田埂；不因缺量扩大到保护圈。城外确需保留的原生林块可加 preserveVegetation=true，保留范围内原状，不清理或补种；新林块用作者树种，城区绿化不用原生植被凑数。

农舍单位各用一个普通小阵列或小组合（谷仓、风车、小屋）。把这些完整单位放入根 GRID 组合，layout.natural.mode=SCATTER，spacingBlocks 是单位间最小间隙，radiusBlocks 是 anchorBlock 周围的搜索范围。宿主优先较平坦且近水的合法陆地，不排成网格，按真实入口用小路连接保留的单位。普通 SIMPLE 道路配置也支持这些乡间小路；仍须安排该乡野与城内道路的显式 CONNECTION，不能把局部农舍连通视为已接入全城。

沿岸港区、等高线坡地排屋或峡谷崖边，从 context.terrainLines 选 lineRef。使用 LINEAR 组并填 layout.natural={mode:TERRAIN_LINE,lineRef:所选线,rows:排数,spacingBlocks:沿线间距,setbackBlocks:陆侧退距}。程序找线与朝向，第一排面对水面/低地，后排退向陆地/高地；不描逐栋坐标，不再给该组 anchorBlock，也不把它塞进会移动它的父组合。根 SCATTER 组合也不能放进会移动它的父组合。线长不够时减少本段成员或另选独立线段；弯角、地形和碰撞导致的留空看预览调整。码头/栈桥选择支持相应水上落位的真实素材，峡谷两侧分别选 cliff_ 线，用显式 CONNECTION 连接；同轴、近等高且跨度可承载时程序生成跨谷桥，失败会保留缺口，不能把未接通当作完成；没有合适素材时报告缺项。

验收看实际预览：田林是否成片且不规则、农舍是否疏而成组、组间小路是否真实连到入口；沿岸建筑是否随着岸线转折且面向水面。成功编译不代表上述画面已经合格。
