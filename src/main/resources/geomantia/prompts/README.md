1. `city/d4_v2/handbook.md`：四项首要目标、完整流程及共同规则。
2. `city/d4_v2/overview.md`：理解要求、场地和全城规模构思。
3. `city/d4_v2/district.md`：完整功能区设计与保存后修订。
4. `city/d4_v2/integration.md`：整体与规模复核、扩展和最终保存条件。
5. `city/d4_v2/finalize.md`：最终保存检查清单。当前状态机没有单独加载此文件，终审要求已写入 integration；此文件供复核和 后续独立阶段参考。
6. `city/d4_v2/complete.md`：保存后与重开边界。

这是设计指导；工具 schema、版本绑定、失败预算与施工门禁由代码执行。本轮重写不改变这些校验，也不改变 Context 的传输压缩策略或清空既有设计。`scaleDesignTask` 的 AI 视图提供规模背景，不提供建筑或阵列数量建议；完成依据以实际预览中的功能、地形关联、整体性与体量为准。

2026-10-12 补充空间构图手法：handbook 新增“空间构图手法”与魔法学院骨架对照示范（主轴、唯一一级地标、广场四边布置二级地标、COURTYARD+faceInward 围合、疏密梯度、贴骨架扩展），各阶段改为先定骨架再定数量，“规模充分”改为“体量与职责相称”。起因是独立 Agent 的学院 D4 有 6 个分散根锚点、全部组同一间距与密度，预览缺乏整体性。不改变字段、校验或失败预算。

## 本轮 review 范围与待对齐项

本轮重写上述提示词并同步开发实例，供用户评审；没有开始规划或修改城市存档。信息分层和完成目标是本轮文案，不新增提交字段或程序门槛。

- 决策视图已移除 D4 Patch 选址/排序候选与固定阵列数量建议，替换旧 recovery 指引。完整存档中的旧字段保持兼容，Context 身份与设计进度不因此变化。
- 格式、引用、核心、必需内容及施工门禁仍由代码检查；四项设计目标的充分性由设计者看当前预览判断。正常生成先初版后必要复核，用户明确测试/修订时可复用 D3 多轮比较。
- Context 传输层压缩、目录按需加载、重复说明去除尚未实施。本轮主要供审阅设计目标与阶段组织。

`agent.md` 提供共用总指令；`realm/environment_style.md` 提供环境风格判断，D4 正常修订可处理新发现的不协调。运行时优先使用实例 `config/geomantia/prompts` 下的已有文件；资源文件修改不会自动覆盖用户定制。开发实例已显式同步本轮版本，后续准备设计任务时读取。

realm/t1.md 指导国度构思：结合地形、核心建筑图册与作者功能，先构思共同背景与文化圈，再形成各国地方差异，不按素材风格一一建立国度。文化圈说明共享建筑传统、生计、空间使用习惯与命名规律，可以跨国、跨大陆；所属圈名称与文化特征写入 cultureTags，相关共享设定和地方差异写入 theme，供后续任务继承，不新增工具字段或预制文明枚举。内容包提供 realm_core_atlas.json 时，T1 附带核心图册；未提供则明确说明只有文字资料。设计时像小说创作一样一并命名，考虑当地称呼与文化来历，避免整批同构的景物加组织后缀；名称保存于既有 name，不增加命名调用或硬校验。国度创作意图保存于既有 theme，并交给后续城市与附属设计任务。

realm/environment_style.md 统一 T1、T2/T4、D3 与 D4 的环境风格判断：依据真实群系及作者素材选择，重选后复核，允许在维持文明职责的同时调整本城建筑表达，不用背景故事豁免已知错配。它不是 biome ID 白名单，也不增加工具调用或编译门槛。整合包作者可以在此补充风格的环境偏好与明确例外。此新文件会自动补入旧配置目录，已有提示词文件仍保留作者编辑。
