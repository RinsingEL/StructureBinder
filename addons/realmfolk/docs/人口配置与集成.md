# 人口配置与集成契约 · v0.4.0

## 配置与持久化

首次启动世界时创建 `config/realmfolk/design.json`（版本 2）。世界首次采用后，将已发布设计、版本号、草案、最近 32 次发布回执与居民快照一起保存在主世界 `realmfolk_society` SavedData。修改现有世界使用[设计 MCP](城市设计MCP.md)，不会每次进世界都被安装目录配置覆盖。社会存档版本升至 2，使用 UTF-8 NBT 字节数组，避开单个文本约 64 KiB 的上限；兼容读取旧 society 文本。旧存档首次载入时补齐职业快照，保留人物 UUID、姓名、住所、关系和任务。升级后的经济存档不支持直接降级旧版模组读取。

`population.json` 保留用于首次迁移姓名、人口上限、住宅容量、待售间隔、用途映射与关键人物；已有 design.json 时不重复迁移。旧 `templateRoles` 为建筑补充明确用途，`entityTypesByTemplate` 在新接入建筑生成一个指定生物，沿用其原有 AI，不继承居民交谈能力。`/realmfolk reload` 只重载这两类旧映射，不绕过城市方案发布。

## 定义与继承

| 定义 | 内容 |
| --- | --- |
| professions | 职业 ID → 名称、能力、外观、工作用途、作息、属性范围、装备、委托、商品、招募好感。ID 不局限于旧七种职业。 |
| realms | 文化规则 ID → 名称、人口规则及法律参数。必须有 default。 |
| realmBindings | 主模组 realmId → 文化规则 ID，未绑定时使用 default。 |
| cityTemplates | 模板 ID → 可复用人口规则，必须有 default。 |
| cities | runId:citySeedId → 模板、人口覆盖项、关键人物与经济池选择；旧裸 cityId 继续兼容读取。 |

人口字段按“默认国度 → 绑定国度 → 城市模板 → 城市覆盖”继承。省略字段表示继承，显式 null 拒绝。提供 map/list 时整项替换；例如城市提供 jobs 后就是该城完整职业配额。草案 patch 的顶层五类 map 按条目 upsert；一个职业或模板条目也是完整替换，未提交的其他条目保持不变。不提供删除定义、表达式、脚本和动态类加载。

| 人口字段 | 限制与作用 |
| --- | --- |
| populationMode | housing 按住宅补员；fixed 使用显式人数。新安装默认 housing；旧世界缺此字段时保持 fixed。 |
| housingOccupancy | 0–1，默认 0.85。housing 目标 = min(256, floor(可用住房名额 × 入住率))。 |
| population | 0–256，只在 fixed 模式使用。已有及已故 NPC 计入人口，其他生物不计入住房目标。降低目标不删除居民。 |
| residentsPerHouse | 1–8，同时受实际可站立位置数量限制。 |
| residentsByFunction | 可选，用途词 → 1–8 人；仅匹配住房用途，多用途取最大覆盖值而非累加，未匹配用 residentsPerHouse。 |
| saleHouseEvery | 0 关闭或 2–256，按新住宅发现顺序预留空房。 |
| housePrice | 1–1024 旧计价单位，实际账户扣款乘经济配置 legacyUnit。 |
| workplaceCapacity | 1–16，同一个工作建筑所有职业共享总容量。 |
| names | 1–256 个基础姓名，程序附加稳定短后缀。 |
| housingTerms | 精确匹配已批准建筑用途，确定居住空间。 |
| traits | 标签 → 正权重；当前仅人物标签和对话展示，不改变 AI 行为。 |
| jobs | 职业 → min/max/weight；先关键人物及最低岗位，再按权重填充。 |

关键人物每城最多 16 位，提供稳定 id、name、profession、bio，计入配额与人口目标。缺住房或工作地点时保留缺口；未到场关键人物和最低岗位预留人口名额。配置矛盾拒绝发布，实际空间不足则显示缺口。

## 能力与职业

已实现 14 项能力：conversation（交谈）、commission（物资委托）、trade（出售）、buyback（收购）、gift（接受赠礼请求）、companion（同行）、combat（近战）、patrol（工作区域巡逻）、witness（目击）、law_enforcement（执法）、rumors（传闻）、travel（城际护送）、land_office（房产及示范讨伐奖励）、public_life（参加公共活动）。

所有职业要求 conversation。law_enforcement 要求 combat + witness，不能兼任 companion；travel 不能兼任 companion。执法者是否巡逻由 patrol 控制。没有 combat 的人物不会主动近战助战或因受击设置近战目标。外观仍从 resident/farmer/smith/ranger/guard/merchant/mayor 的原版村民样式选择，与职业 ID 独立。

生命 1–200、攻击 0–40、移速 0.05–0.6 的范围按人物身份分别抽取并保存。装备使用已安装物品 ID。职业快照固定后不会因全局定义修改自动换能力、商品或任务材料。旧 offers 保留读取兼容，新货架使用 itemPools 和 stockSlots（1–54），库存及经济规则见[经济契约](城市经济与主流程契约.md)；委托材料 1–64、奖励 0–64、好感增加 0–30、声望增加 0–20。作息为 0–23999 世界时刻，支持跨零点休息；招募好感 -100–100。

队伍上限仍为 3；护送报酬、示范讨伐流程和奖励仍使用既有常量，不属于此次配置接口。简介不会自动变成新任务代码、剧情或地图标记。

## 人口生成与 Geomantia 接入

只读取主模组正式登记、已确定高度且全部片段有落地证据的建筑与冻结目录中已批准的 functionTerms。不猜用途、不创建建筑、不加载整座城；玩家周边已加载建筑逐步登记。

住所与工作地点独立分配。住宅可站立位置成为住房名额；工作建筑按 workplaceTerms 精确匹配，空列表表示在自己住宅工作。待售及玩家财产不分配给新居民或新雇员。已生成住户不因规则变更强制搬家。

使用世界种子、城市实例、住房名额派生身份，再独立抽取姓名、标签、职业和属性。相同已知世界与规则的预览和发布一致，map 顺序不影响结果；探索顺序改变已保留居民后，不承诺整城倒退重算成相同布局。每人有独立住所点。死亡人物不复活，管理员移除实体不自动补刷。

## 住宅人口与公共活动

可用住房名额按每处住宅 min(residentsPerHouse, 已确认站立点数) 求和；待售房和玩家房产不计入。已入住的普通住宅仍计算全部容量。发现新住宅后按目标补足缺口；职业权重、职业上限、岗位容量和关键人物保留名额仍可能使实际人数低于目标。预览返回 populationMode、occupancy、housingBuildings、housingSlots、freeHousingSlots（本次补员前空余）、target、existing、created 和 shortages。256 是实现保护上限，不代表已验证 256 人的性能。

activities 是整项继承/替换的公共活动列表，最多 8 项。每项配置 id、name、start/end（0–23999，不可相等，支持跨零点）、participation（0–1）、capacity（1–32，单城单活动人数）、maxDistance（16–256，从住所算距离）、placeTerms（精确用途词）。新安装默认午间闲逛 5000–8500、60% 参与、最多 12 人；傍晚小聚 10000–12000、40% 参与、最多 8 人。旧世界缺活动列表时保持原有作息。

PUBLIC 且非玩家财产、非待售的对应建筑周边已加载可站立点作为聚集点，不占住房名额。不自动铺路或加载远处区块；只安排已加载、持有 public_life 能力、未休息且空闲的 NPC，执法者、旅行中和同伴不参加。按人物与活动当天的稳定抽样错开出发/离开，活动间避免占用同一站立点。交谈与战斗优先；结束后恢复工作或回家。当前实现步行与短暂停留，不包含真实购物消费、进食动画或生产经济。原版寻路仍受地形限制；20 秒未接近目标或单次行程超过 90 秒时，本次活动恢复普通作息，下次活动再试，抵达者可正常停留。

旧世界需通过 MCP 发布住房模式和活动规则；希望已有普通居民参加时，对对应职业加入 public_life 并选择 refresh_unprotected。已保护角色保留原快照。住房与公共活动仍需显式发布；0.4.0 首次经济升级会给旧居民加入 gift、旧 trade 加入 buyback，其他设计与人物身份保留。

## 法律与运行时

国度规则可设置目击距离、报案延迟、擅闯宽限、警卫察觉和追捕距离、丢失视线时长、重复违例阈值及各类罚款。发布后用于新行为，已经记录的罚款不重算。默认目击 18 格、报案 600 tick、擅闯 200 tick、察觉 28 格、追捕 64 格，三次未结纠纷升级。

不取消破坏事件。开容器本身无罪，拿取、归还和赔偿以服务端物品变化为准。目击要求同镇、具有 witness、能看见玩家和事发处；同伴不充当公共目击者。直接受伤者可识别攻击者，杀害的额外追责需要其他目击者。报案者须存活且已加载。各国声望和报案分开记录。漏斗、掉落拾取、爆炸和间接破坏尚未纳入完整追责。

居民在已加载区块分批生成，之后按原版实体持久化。客户端只请求操作，服务端校验能力、距离、视线、任务和支付。商人旅行保留原住所和国度归属，不把到达城市中心永久变成新住宅。

交谈期间客户端保持心跳，服务端在距离和视线有效时暂停日常导航；关闭界面或失联 60 tick 自动释放，战斗仍可正常继续。
