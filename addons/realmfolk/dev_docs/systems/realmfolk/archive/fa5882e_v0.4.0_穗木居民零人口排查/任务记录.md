# 穗木居民零人口排查

后续复查及对前次归因的更正见[真实调用复查与外部方案](复查与外部方案.md)：已找到原始调用记录；穗木段约 73 秒，工具耗时合计约 3.8 秒。AI 更早见过住房用途，主模组已传蓝图；不能将此前上下文与速度推断视为最终结论。

*需求入口*：用户反馈穗木共社居民规则发布返回 `future_only`、创建 0 人，玩家加载城市后仍没有 NPC；要求排查 `D:\PCL2-2.8.12\.minecraft\versions\1.20.1-Forge_47.4.23\saves\geometia_beta2_04`。

*修改内容*：只读诊断并登记故障；未修改测试端规则、社会存档、模组或实现代码。

*验证结果*：读取 `data/realmfolk_society.dat` 内 `society_utf8`。设计 revision=6，穗木方案在 active 中，无待发布 drafts，citizens=0。首次读取已导入 71 栋建筑，后续离线快照为 73 栋，测试端仍在发现建筑；两次均有 14 栋“家庭居住”，每栋 8 个可站立 slots，售价均为 0。穗木 overrides 没有 housingTerms，继承默认 `[住宅, 民居, 住宿, residential, housing]`，与“家庭居住”不匹配。

直接使用测试端安装的 `realmfolk-0.4.0.jar`、Gson 2.10、Java 17 调用纯函数 `PopulationPlanner.plan`，输入为存档副本，固定 seed=0（验证容量与补员行为，不预测真实世界人物抽签）：原规则 housingBuildings=0、housingSlots=0、target=0、created=0；在内存副本的穗木 overrides.housingTerms 保留默认值并增加“家庭居住”后，housingBuildings=14、housingSlots=28、target=23、created=20。仍缺 guard、merchant、mayor 各 1 个最低岗位；领事关键人物 suimu_council 等待岗位。原有 farmer/smith/ranger 职业用途也与该快照实际用途无交集。

根因是发布方案的住房与职业用途词未对齐建筑批准用途。`PopulationPlanner.java` 使用精确字符串交集，不作同义词推断。`future_only` 保留已有居民快照，允许未来创建；`GeomantiaBridge.refresh` 在发现建筑后调用 `DesignService.populate`，不是 scope 阻止补员。自定义种源管理员、木器维护商已包含本城实际用途。

用户追问自动生成可靠性与配置耗时后进一步核对：`CityPlanningExtension.context` 只组织国度、城市种子、默认人口、职业摘要和经济目录，没有向居民扩展提供蓝图建筑用途清单；职业摘要也省略 workplaceTerms，需要逐项 read 才可见。`DesignValidator` 对 housingTerms/workplaceTerms 只校验列表数量与字符串长度，不核验与城市用途交集。`CityPlanning.submit` 只选已发现 town 进入人口预览；城市尚未发现时 towns 为空，预览不执行该城人口推算，但允许发布并记录完成。由此“等待加载”与“规则永远无法匹配”没有分开验证。工具流程有 submit/preview/publish 三次顺序调用，另有 context 与逐项 read；这构成额外调用与生成负担，未采集耗时剖析，不能据此断言实际延迟主要花在哪一步。

*剩余问题*：尚未修复或进行游戏内验收。最小修正是保留穗木完整城市方案，为住房用途补充“家庭居住”并重新预览发布；完整修正还需对齐实际“农田种植”“议事”“集市交易/零售”“林务管理”“工具维护/木器制作”等职业用途，警卫需依据真实批准岗位确定。职业定义为全局共享项，应评估其他城市影响或使用城市专属职业。修改实例 config/realmfolk/design.json 不会覆盖已有存档内的 active 方案。
