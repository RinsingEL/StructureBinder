## 代码核对及更正

- `PlanningExtensionContext` 已含 blueprint；主模组 `PlanningExtensions.context` 读取正式 city_blueprint.json 交给扩展。居民 `CityPlanningExtension.context` 未使用 blueprint，也没提供模板批准用途清单。缺口在附属模组上下文组装，不是主模组没有蓝图。
- `planning_resume` 已包含 extensionTask，额外 context 调用并非协议必需。
- `CityPlanning.submit` 只把已发现 towns 纳入事务；真实穗木预览 towns=[]，不是“已预览住房为 0 并提示缺口”。
- `CityPlanningTest.publishesUnloadedCityRulesWithoutSpawningAndSurvivesRestart` 明确验证未加载城市可发布。不能用“created 必须大于 0”替代规划有效性检查。
- 当前纯函数 PopulationPlanner 已批量生成普通 NPC；AI 本来就在做职业/城市规则和少数关键人物。此前建议“普通人口改由程序生成”并不是新增能力。
- 字符串精确匹配本身不是充分根因；缺少共享候选约束、实际用途交叉验证才让不匹配规则通过。更换成 ID 如果仍允许未知引用、没有验证，也不能自动解决。

## 外部方案：只采用官方文档及作者源码

1. MineColonies：Residence 按等级提供明确居住容量，Town Hall 控制自动分配住房和空闲岗位。可借鉴显式建筑容量与岗位分配；它不是本项目这种 AI 城市配置流程，不能用于推定 LLM 延迟或证明必须移除 AI。
   - https://minecolonies.com/wiki/buildings/residence/
   - https://minecolonies.com/wiki/buildings/townhall/
2. Epic Smart Objects：行为对象提供槽位、位置、活动标签，查询返回符合过滤条件的对象和空闲槽位，再 Claim/Use/Release；Gameplay Tags 进入中央字典注册。说明 tag 机制可以可靠运作，关键是受控词汇与明确匹配/占用状态，不能一概否定 tag。
   - https://dev.epicgames.com/documentation/en-us/unreal-engine/smart-objects-in-unreal-engine---overview
   - https://dev.epicgames.com/documentation/unreal-engine/using-gameplay-tags-in-unreal-engine
3. Generative Agents 作者代码：run_gpt_prompt_action_sector 从空间记忆构造可访问候选，生成后检查结果是否属于候选；不合法时回退到居住区域。可借鉴候选约束与结果验证，不照搬默默回退，也不能把多轮行为模拟当作快速人口配置方案。
   - https://github.com/joonspk-research/generative_agents
   - https://raw.githubusercontent.com/joonspk-research/generative_agents/main/reverie/backend_server/persona/prompt_template/run_gpt_prompt.py
