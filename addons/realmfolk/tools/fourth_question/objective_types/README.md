# 模组专属目标 · 独立实验 03

这是用户纠正“任务类型”含义后的新原型：传统 NPC 接取、执行、回来回报；通用目标是交付物品、击杀生物，作者的模组扩展目标是“掌握不同 Ars 符文”。不采用旧版学院初访的固定三阶段流程。

新入口：`http://127.0.0.1:8776/`。使用普通静态文件服务，无被拦截的 PowerShell 启动脚本：

```text
python tools/fourth_question/objective_types/serve.py --port 8776
```

命令在 Realmfolk 仓库根目录运行，终端保持打开。它只向本机提供本目录静态文件，显式设置 `.mjs` MIME 类型，避免 Windows 注册表的 text/plain 映射阻止浏览器加载。不会启动 Minecraft、修改安全软件设置、运行外网脚本或访问模组存档。

## 体验

1. 在学院的 51 栋 D4 建筑底板上查看用途，点击人物标记切换对话。选择星落或青枝的 AI 配置，点击“重开当前样例”。每位居民有独立任务，可以自由选择顺序。
2. 向导师接取。实验工具先“取得符文物品”，观察学习进度仍为零；再“模拟学会”，观察进度增加，符文物品消耗一枚。
3. 满足不同种类要求后回报，观察奖励、好感和 NPC 回应。重复领取不生效。
4. 文库交付会扣纸；守卫讨伐只计接取后的指定生物。工具中的牛是无关目标。
5. 展开配置区可模拟不启用 Ars，或不计入已有学习。改变条件后须重开；若已有知识使“新学”候选不足，拒绝接取并解释原因。

## 分工

| 文件 | 作用 |
| --- | --- |
| author-catalog.json | 作者给出类型、适配器、候选、数量范围、奖励及是否计入已有知识；两种学院共用。 |
| ai-instances.json | 本轮 AI 写好的两组样例：选类型、NPC 职业、目标、数量、奖励、地方措辞。切换时不调用在线模型。 |
| engine.mjs | 离线编译、模拟输入判定、扣物、一次结算。浏览器和 Node 测试共用这一个实验引擎。 |
| app.mjs / index.html | 传统居民对话、个人进度、单独标识的实验工具、配置对照。 |
| campus-layout.json / map.mjs | 原学院 51 栋 D4 建筑的占地与批准用途；6 个样例人物按两种学院绑定到相应建筑。支持鼠标和键盘查看。 |

目前任务**不随机**：两份实例由本轮 AI 预先写好，程序负责读取、校验和执行；重开同一样例只重置进度。尚未接入每局读取城市与模组条件、调用 AI 重新编排的生成阶段。地图导出脚本 `export_layout.py` 只读取已有冻结证据，不改变城市和任务配置。

作者可另取类型名字，例如 `my_pack:botanical_study`，但必须引用已实现的适配器。JSON 无法凭空判定新的模组机制；将来可以由附属模组或受支持的脚本事件提供适配。本轮只证明配置关系与判定语义，不承诺支持任意模组。

## 实验边界

- 建筑底板来自已有 D4 冻结证据，导出时检查批准用途并保存源哈希。人物落点、物资、击杀与学习仍为实验设定；没有扫描当前世界、证明附近怪物存在，或实例化真实 NPC。标记放在建筑平面中心，不代表可站立点。
- Java 接入草稿曾通过聚焦测试，但本网页不调用它。网页使用独立 JS 实验引擎；真实 Ars capability 的接入尚未游戏验收。
- Ars 机制依据本机 1.20.1-4.12.7 JAR 与官方指南。浏览器的“已学会集合”是模拟输入；返回访客预置光亮和治疗，仅为测试条件，不代表 Ars 新玩家的默认知识。
- 普通背包采用物品 ID，不模拟 NBT、堆叠容量、丢失物品、真实战斗、寻路或法术教学过程。奖励数值仅供体验。
- 进度在浏览器 localStorage；不是服务器存档或防作弊方案。已有知识的规则冻结于接取时，修改作者配置须重开。
- 尚未部署正式 JAR、修改游戏存档或完成城外地牢接入。早先的 Java 草稿本轮未继续改动或部署。
