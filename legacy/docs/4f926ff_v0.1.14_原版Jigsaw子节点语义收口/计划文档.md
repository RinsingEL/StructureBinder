# 子节点原版 Jigsaw 语义收口计划

## 本次任务标题

把当前子节点求解改回“原版 jigsaw 逻辑为主、AI 只替换随机选模板”的实现语义。

## 最终计划摘要

本轮只收口子节点求解主链，不扩展新的 solver 能力，不重做完整执行层。目标是修正当前 `CityVanillaJigsawAdapterService` 中偏离用户设计的地方：不再直接构造脱离 parent jigsaw 原始配置的临时 `single(template)` pool，而是优先读取 runtime parent jigsaw 自带的 pool，并从该 pool 中精确收束到 AI 指定的 child 模板元素，再继续调用原版 `JigsawPlacement.addPieces(...)` 完成单层 child 生成。

## 实施步骤

1. 回读当前 child solve 逻辑，明确现有“临时单模板 pool”与用户设计的偏差点。
2. 从 runtime parent jigsaw 中解析原始 pool 标识，并在注册表中读取对应 `StructureTemplatePool`。
3. 在原始 pool 元素中定位 AI 指定的模板元素，保留原始元素 projection / processor / element 语义，只把随机候选收束到目标元素。
4. 继续复用原版 `JigsawPlacement.addPieces(...)` 进行 depth=1 child 生成。
5. 补充定向测试，验证：
   - 命中原始 pool 中指定模板时可以继续生成
   - 不在原始 pool 中时会明确失败
   - 调试证据能说明当前使用的是 runtime parent pool

## 验收标准

- 子节点求解不再使用脱离 parent jigsaw 的 `single(template)` 临时 pool 作为主语义。
- AI 指定 child 后，仍由原版 `JigsawPlacement.addPieces(...)` 负责实际 child 生成。
- trace / debug 中能看出：
  - parent runtime jigsaw 的 pool
  - AI 指定模板是否命中该 pool
  - 实际用于 vanilla 生成的 pool 来源
- 定向自动化测试通过。

## 关键假设

- 当前要修的是 child 求解语义，而不是一次性重做所有 `apply_now` 执行细节。
- runtime parent jigsaw 的 NBT 中可读取到原始 pool 信息，足以作为本轮真值来源。
- AI 指定模板应当属于 parent jigsaw 原始 pool；若不属于，当前应显式报错而不是静默回退。
