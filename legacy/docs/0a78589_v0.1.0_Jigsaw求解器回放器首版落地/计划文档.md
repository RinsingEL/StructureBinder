# 本次任务标题

实现主模块 Jigsaw 求解器回放器首版，落地独立 `code_process_viewer/` 工程

## 最终计划摘要

本轮正式进入实现阶段，在实现仓库顶层创建独立子工程 `code_process_viewer/`，使用 Go 后端 + 内嵌静态页面实现首版回放器。首版只消费已经生成的 `jigsaw_solver_debug/<runId>` 调试产物，不负责触发求解；导入后写 SQLite 会话，并导出规范化 session JSON 缓存。

## 实施步骤

1. 沿用当前任务目录，补充进入实现阶段的计划、需求和修改记录。
2. 安装 Go 工具链，创建独立的 `code_process_viewer/` 工程骨架。
3. 实现 Jigsaw 调试产物导入器：
   - 读取 `trace.json`
   - 复制预览图到 runtime cache
   - 组装 session / node / edge / table / checkpoint
4. 实现 SQLite 存储、缓存导出和 HTTP API。
5. 实现最小只读工作台页面，展示步骤流程、预览图、详情、证据表格和审查标记。
6. 编写测试、README，并同步更新必要的文档仓库文档。

## 验收标准

- 实现仓库中存在独立目录 `code_process_viewer/`，且依赖声明、代码、静态页都在该目录下。
- 默认端口 `6657` 可启动服务。
- 能导入一个真实 `jigsaw_solver_debug/<runId>` 调试目录。
- 导入后能在页面中浏览 `request_context / runtime_jigsaws / parent_connector_resolution / vanilla_piece_result / validation_result / apply_result`。
- 节点详情中能看到源码入口、证据表格、预览图和审查状态。
- 审查标记可保存并刷新后保留。

## 关键假设

- 首版样本改为主模块 `Jigsaw` 求解器真实调试产物，而不是 `dev_docs` 任务目录。
- 首版只读现有调试产物，不负责触发 `city_jigsaw_solve`。
- 工程采用独立模块 + 依赖声明，不做 `vendor`。
