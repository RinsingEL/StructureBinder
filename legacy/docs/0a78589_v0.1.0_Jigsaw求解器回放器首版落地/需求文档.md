# 用户本次需求摘要

用户要求开始实现这套回放器，并明确了以下实现边界：

- 工具作为实现仓库顶层的独立子工程目录 `code_process_viewer/`。
- 技术框架固定为 Go + Web。
- 前端保持纯展示，不拆独立 SPA。
- 首版样本不再使用 `dev_docs/current_20260407_150600`，而改为主模块 `Jigsaw` 求解器真实调试产物。
- 首版只消费已经跑出来的 `jigsaw_solver_debug/<runId>` 调试目录。
- 默认开发端口使用 `6657`。
- 依赖采用独立模块 + 依赖声明，不做 `vendor`。

## 用户特别强调的约束

- 工具单独一个文件夹，包括它自己的依赖声明、代码和静态资源。
- 首版以“能真实试用 Jigsaw 调试回放”为主，不追求一次覆盖所有 agent 开发过程。
- 当前机器如果缺 Go，就先装 Go 再开工。

## 不做的事情

- 本轮不触发 `city_jigsaw_solve`。
- 本轮不做实时事件流接入。
- 本轮不做多人协作或复杂权限系统。
- 本轮不做独立前端框架工程。
