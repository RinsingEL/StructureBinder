# Start 选点修复与水平/垂直 Jigsaw 分流计划

## 本次任务标题

修复主链 start 选点与朝向策略，并将独立 Jigsaw Solver 正式收口为“水平专用 + 垂直占位分流”。

## 最终计划摘要

本轮先不实现垂直 jigsaw 求解器，而是把当前求解器正式限制为只处理水平 jigsaw；`up/down` 进入独立 vertical solver 路由占位并返回专门错误。与此同时，把 `ServerLevel/StructureTemplateManager` 接入 `C8` 生成入口，在主链里按 runtime 水平 connector 与第一跳 child 可扩展性修正 `start_x/start_z/start_rotation`。若主链暂时拿不到 runtime 模板，则显式回退到旧 catalog heuristics，并写出 warning 与调试证据。

## 实施步骤

1. 在 `CityController` 与 `/city_jigsaw_solve` 中增加水平/垂直 jigsaw 分流，`up/down` 返回独立 vertical pending 错误。
2. 扩展 `CityC8Stages.generate(...)` 的调用链，把 `mcServer.overworld()` 或 `StructureTemplateManager` 传入 `C8` 主链。
3. 在 `CityC8Stages` 的 start 节点初始化与 `CityC8ArrangementEngine` 的 seed 逻辑中加入 runtime-aware start 评估：
   - 只看水平 runtime connector
   - 在 anchor 周围局部搜索
   - 联合评估朝内方向和第一跳 child 可扩展性
4. 为 start 节点和 foundation 增加 runtime 选点调试字段与 fallback 证据。
5. 补充定向测试与真机回归，验证 `g_market_03` 的 start 不再固定在北侧边缘且水平首扩展风险下降。
6. 同步更新实现仓 `dev_docs` 与文档仓 Jigsaw Solver / 主模块验收文档。

## 验收标准

- `/city_jigsaw_solve` 请求 `jigsaw_up_*` / `jigsaw_down_*` 时，明确返回 vertical pending，而不再进入当前水平 solver。
- 水平 jigsaw 请求继续走当前水平 solver，并保留现有 Step 04 调试能力。
- `C8` 主链生成 start 时，优先选择存在水平 runtime connector、朝向多边形内部且第一跳 child 风险更低的 `start_x/start_z/start_rotation`。
- 若拿不到 runtime 模板管理器，主链会显式回退并输出 warning/调试证据，而不是静默回退。
- `C8 foundation`/debug 产物中能看到新的 start runtime 选择字段。
- 文档仓同步说明本轮 start 修复口径与垂直 solver 占位路由。

## 关键假设

- 当前水平主扩展长不出来的主因是 `start_x/start_z/start_rotation` 没围绕水平 runtime connector 和第一跳 child 余量来选。
- 本轮 vertical solver 只做路由占位，不实现垂直拼接。
- 主链 start 评分优先使用 runtime 模板；若无法获取 runtime，再显式回退到 catalog heuristics。
- 当前首扩展默认只面向水平 jigsaw，`up/down` 不参与本轮 start 最佳候选评分。
