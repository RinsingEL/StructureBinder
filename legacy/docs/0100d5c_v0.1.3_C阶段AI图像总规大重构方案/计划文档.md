# C阶段 AI 图像总规大重构方案

## 最终计划摘要

本轮先不改代码，围绕用户提出的“新的 image2 模型能力增强后，C 阶段很多旧工具是否可以降级”编写正式方案。方案目标是把 C 阶段从程序扩张、选簇、数学切块主导，调整为 AI 图像总规主导，程序负责底图、契约、解析、校验、修复和 Minecraft 落地。

## 实施步骤

1. 读取实现仓与文档仓现有 C1、C3、C7-C9 方案、契约与测试入口。
2. 在文档仓新增 C 阶段 AI 图像总规产品总案。
3. 在文档仓新增对应的轻量数据契约草案。
4. 在文档仓新增验收文档，并更新主模块测试入口。
5. 在实现仓 dev_docs 记录本轮决策、修改与后续风险。

## 验收标准

- 正式产品方案能回答：AI 是否直接画边界、功能区、道路，以及旧选簇工具如何保留。
- 契约草案明确 AI 图像输入、分层输出、结构化 JSON 与 validator 的边界。
- 验收文档明确底图一致性、图层可解析性、越界/压水/断路等失败条件。
- 不改动 Java 运行时，不误把方案真值写回实现仓旧文档体系。

## 关键假设

- 本轮是方案先行，不启动 Minecraft，不运行 C 阶段代码，不提交 git。
- “image2”作为当前强图像模型能力的项目口径，不在本轮绑定具体 API 参数。
- 旧 C1/C3/C6/C7 工具先保留为 fallback、debug 与迁移期兼容能力。
