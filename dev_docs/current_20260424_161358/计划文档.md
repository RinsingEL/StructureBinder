# 本次任务标题

T3 单独入口零面积门禁最小修复

# 最终计划摘要

在实现仓库 `E:\Mod_Dev\StructureBinder` 中修复 `/t3_run_continent` 的假成功问题：当 T3 扩张结果中 `claimed_total + wild_total == 0` 时，HTTP 入口返回 409，并附带明确错误、排查提示和每个 territory 的零面积摘要。正常成功时保留原有返回字段，并补充面积汇总。若接口契约或验收入口已有正式文档记录，再同步更新文档仓库 `E:\Mod_Dev\designer_territoryMod`。

# 实施步骤

1. 定位 `TerritoryController.handleT3RunContinent(...)` 与 T3 结果对象结构。
2. 统计 `results` 中的 `claimed_total`、`wild_total`、每个 territory 的 `claimed_chunks / wild_chunks`。
3. 在零面积时返回 HTTP 409，包含 `error`、`hint`、`exported_count` 和 per-territory 摘要。
4. 在成功时保留 `continent_id`、`exported_count`，并新增 `claimed_total`、`wild_total`、`territories` 汇总。
5. 增加或更新轻量单元测试，优先测试纯 summary builder；必要时测试 controller 响应构造。
6. 检查文档仓库是否需要同步接口语义、测试入口或代码导览。
7. 运行指定 Gradle 验证，并在验收前读取本目录三份文档。

# 验收标准

- `/t3_run_continent` 在零面积 T3 结果下不再返回 200。
- 零面积响应使用 HTTP 409，并返回明确 `error` 与排查 `hint`。
- 成功响应包含新增面积汇总字段且不破坏原有核心字段。
- 测试覆盖零面积失败响应构造逻辑。
- 至少运行 `./gradlew.bat test --tests "*Territory*"` 与 `./gradlew.bat compileJava compileTestJava`，或记录无法运行的原因。
- 若涉及正式契约或验收入口，文档仓库完成同步。

# 关键假设

- 本轮只做最小修复，不改 T3 扩张算法、不改 survival C1、不改旧 C1。
- `wild_total` 视为有效国度面积，因为当前 sovereignty 判定接受 claimed 与 wild chunks。
- 当前工作区存在用户未提交改动，本轮只修改与任务直接相关的文件。
