# Group 级清表工具计划

## 本次任务标题

为指定 city/group 增加独立的 group 级地表清理工具，方便在结构联调前先把测试区域清干净。

## 最终计划摘要

本轮在实现仓新增一个“按 group/build_area polygon 清表”的独立接口，复用现有执行层的方块分类语义，但把输入从“单个 placement bounds”提升为“group 级 area geometry”。默认优先解决测试视野和落地干扰问题：支持按 polygon 范围清除可软清理植被、替换类方块以及 polygon 内高于基准面的非保护方块，并返回中文清理统计；如需要，再保留最小量预览或日志产物，便于确认到底清了哪里。

## 实施步骤

1. 回读现有 `BuildTerrainPreparationService`、`ServerLevelBuildWorldAccess`、`CityController` 与 `CityC8Stages.AreaGeometry`，明确可复用的清理与 polygon 真值。
2. 设计 group 清表服务的数据输入与默认清理边界：
   - `city_id`
   - `group_id`
   - 可选 `build_area_id`
   - 默认 vertical clear 范围与是否清理实心块的策略
3. 在实现仓新增 group 清表服务与 HTTP/MCP 入口，输出：
   - 清理范围摘要
   - 中文统计
   - 结构化清理结果
4. 补充定向测试，验证：
   - polygon 外不会被误清
   - parent/protected block 不会被误清
   - group 级统计能正确返回
5. 若接口契约发生变化，同步判断并补文档仓正式文档。

## 验收标准

- 能针对 `city_3120_-3200 / g_market_03` 这类 group 直接触发一次 group 级清表。
- 清理逻辑以 group/build_area polygon 为真值，不会越出 polygon。
- 返回中能直接看懂：
  - 清了多少 soft obstacle
  - 清了多少 solid/embedded block
  - 采用了什么 vertical 范围
- 不会误清保护方块。

## 关键假设

- 当前用户需要的是“为了联调更容易观察和测试”的 group 级清表，不是完整的地形重塑系统。
- 当前最可复用的规则是执行层已有的 `soft_clearable / protected / embedded_excavate` 语义。
- 若没有额外指定，本轮默认围绕当前 group 的 build area polygon 和 foundation 基准面做清理，而不是全城范围操作。
