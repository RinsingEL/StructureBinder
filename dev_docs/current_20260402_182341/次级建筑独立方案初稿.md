# 次级建筑独立方案初稿

## 1. 背景

当前主模块建筑链路已经基本切到：

- `C7` 工头计划
- `C8` 节点决策与校验
- `C9` 队列生成与建造执行

在这条主链稳定后，下一阶段更适合优先推进次级建筑，而不是道路系统。

原因：

- 道路当前更倾向外包，不适合现在作为主开发方向深挖内部实现。
- 次级建筑可以直接承接当前“主体建筑先定调、剩余空间再填充”的既有口径。
- 仓库内已经存在关于“次级建筑后置补充”“次级建筑默认输出为可建造块”“次级建筑 `single` 化”的现成结论，适合继续落地。

## 2. 已有结论回收

本初稿沿用以下已讨论过的稳定口径：

- 次级建筑是后置补充层，不与主体建筑争夺核心语义。
- 主体建筑允许保留复杂 arrangement；次级建筑整体降级，不走同等复杂度流程。
- 当主体建筑最终有效落地面积占比 `<= 60%` 时，允许进入次级建筑补充流程；`> 60%` 时默认不强制补次级建筑。
- `C8` 对次级建筑的默认输出，不是复杂拼图扩张结果，而是一批“次级可建造块”。
- `C9` 再基于这些次级可建造块，按大小和约束随机或规则化落地次级结构。

## 3. 本案目标

本案不追求一次做成完整的次级建筑系统，而是先做一个最小闭环：

- 从主体建筑结果中识别需要补充的空间
- 生成一批次级可建造块
- 让大多数次级建筑按 `single` 路径落地
- 复用现有 `C9` 队列与执行链路
- 保证次级建筑不明显破坏主体建筑表达

## 4. 本案不做的事情

- 不把次级建筑重新拉回主体建筑那套“工头计划 + 逐节点复杂 AI 决策”主链。
- 不优先建设道路系统本体。
- 不在第一阶段强行支持大量 `pair / linear / start-expand` 例外。
- 不先接入店铺命名、NPC 背景、地图 POI 等高阶语义。

## 5. 建议主线

### 5.1 阶段定位

建议把次级建筑明确定位为：

- 主体建筑基本稳定后进入
- 作为后置空间填充层
- 默认不参与主体主骨架的关键决策

换句话说，次级建筑不是“主体施工过程中的并行节点群”，而更像“主体完成后的第二轮补全”。

### 5.2 输入来源

建议第一阶段优先使用现有 `C6` 的 `secondary_fill` 作为入口语义来源，再结合主体建筑最终结果生成次级可建造块。

现有代码中已经存在：

- `LayoutPlan.secondary_fill`
- `SecondaryFill { zone, style, params }`

因此不建议重新发明一个完全平行的新入口。

### 5.3 中间产物

建议在 `C8` 或 `C8 -> C9` 之间引入明确的“次级可建造块”概念，作为次级建筑的核心中间产物。

每个次级可建造块建议至少包含：

- `build_area_id`
- `group_id`
- 块的范围或 rect
- 尺寸信息
- 所属 zone
- 基础 tag
- 与主体的最小距离信息
- 是否靠边 / 靠路 / 靠主建筑

第一阶段不要让 AI 对整块剩余空间自由发挥，而是先让程序把“可补的位置”切成较清晰的次级可建造块。

## 6. 第一阶段默认落地方式

### 6.1 默认按 `single`

建议第一阶段直接定为：

- 大多数次级建筑默认按 `single` 处理

原因：

- 最贴合“次级建筑整体降级”的方向。
- 更容易复用当前 `C9` 队列与执行器。
- 更适合边测试边修，不需要一开始就面对复杂扩展链。

### 6.2 少量例外先不优先做

以下例外类型先不作为第一阶段重点：

- `pair`
- `linear`
- `start-expand`

这些类型可以先保留为后续增强项，而不是当前分支的阻塞目标。

## 7. 运行链路建议

建议第一阶段形成如下链路：

1. 主体建筑通过当前 `C7 -> C8 -> C9` 主链完成规划与落地
2. 根据主体结果、留白区和 `secondary_fill` 生成次级可建造块
3. 对次级可建造块做基础过滤：
   - 是否满足面积要求
   - 是否离主体过近
   - 是否落入禁入区
   - 是否与其他次级块明显冲突
4. 为每个可建造块匹配次级模板池
5. 按 `single` 方式生成次级结构 placement
6. 将这些 placement 接入现有 `C9` queue / executor

## 8. 第一阶段最低规则建议

即使先做简化版，也建议至少定死以下规则：

### 8.1 主体避让

- 次级建筑不得压主体 footprint
- 次级建筑不得侵入主体主入口前方区域
- 次级建筑不得侵入关键院落/中庭/主视线带

### 8.2 次级之间的基本间距

- 次级建筑之间需要最小间距，避免过密或硬碰撞

### 8.3 边界与安全边距

- 次级建筑必须在可建造块内
- 对外边界需要保留内缩或安全边距

### 8.4 高度容差

- 次级建筑的地形容差建议低于主体建筑复杂链路的自由度
- 第一阶段优先选择更平整、更稳定的可建造块

## 9. AI 参与边界建议

第一阶段不建议让次级建筑也走完整的重 AI 语义规划。

建议边界如下：

- 程序负责生成次级可建造块
- 程序负责候选模板池与基础约束过滤
- 次级结构优先走规则化或轻量选择
- 仅当后续需要对重点次级建筑加语义时，再对少量块引入 AI

这能避免把刚稳定下来的主体主链再次复杂化。

## 10. 与道路系统的边界

当前道路更倾向外包，因此本案只需要保留最小接口意识：

- 次级可建造块或次级结构结果中，可以顺手保留“潜在道路接入点 / 朝向偏好 / 临边信息”
- 但本案不负责完整道路骨架生成
- 也不把道路规则作为当前分支的主阻塞项

## 11. 与现有代码的潜在映射

当前可优先关注的落点：

- `C6.secondary_fill` 作为输入起点
- `C8` 增加次级可建造块输出
- `C9` 继续复用 placement / queue / executor

这意味着新分支更像是在现有主链旁补一条“次级建筑简化支线”，而不是推翻现有结构。

## 12. 当前最建议先拍板的问题

虽然已有不少结论，但在正式开工前，仍建议优先确认以下问题：

1. 第一阶段是否正式定死“大多数次级建筑默认按 `single` 处理”
2. 次级可建造块究竟落在 `C8` 输出还是 `C8 -> C9` 的中间转换层
3. 主体 exclusion zone 最小集合到底包含哪些区域
4. 次级模板池的来源是按 function/tag 映射，还是单独维护一套次级池

## 13. 推荐的第一阶段分支目标

如果要把本案转成实际开发目标，建议第一阶段只做：

- 从 `secondary_fill` 与主体结果中生成次级可建造块
- 大多数次级结构按 `single` 落地
- 接入现有 `C9` 队列与执行器
- 做好主体避让、最小间距与边界限制

先把这条最小链路打通，再继续讨论复杂例外与语义增强。
