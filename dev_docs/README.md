# dev_docs 入口

`dev_docs/` 保存开发过程、联调证据和可复用故障经验，不是当前需求、契约或实现真值。

## 正式目录

| 范围 | 入口 | 内容 |
| --- | --- | --- |
| 系统 | `systems/<系统>/` | 系统开发记录、故障索引及相关故障资料。 |
| 工具 | `tools/<工具>/` | 工具开发记录与联调资料。 |
| 项目工作流 | `workflows/<主题>/` | 工作流开发记录与故障索引。 |

各范围内的新任务记录使用 `active/YYYYMMDD_中文任务名/任务记录.md`；提交后的归档方式以策划案仓《开发与 Bug 留档规则》为准。归档后的 `任务记录.md`、各处 `故障索引.md` 与本入口由 `.gitignore` 自动纳入 Git；`active/` 与其他证据默认只留在本机。

根目录现存的 `active/` 和 `archive/` 是旧结构，只用于必要追溯，不再作为新记录入口。本入口不负责迁移或删除其中内容。

## 线上阅读

已归档的任务摘要和故障索引随实现仓提交，可在 GitHub 按上表的系统、工具或工作流目录查阅。本轮学院 D7 与居民实测还保留了逐轮记录及已选入版本管理的验证证据。

历史记录保留当时的修改、验证及剩余问题；其中“未提交”“未 push”等表述只描述记录当时的状态，后续提交以 Git 历史及归档目录名为准，不据此扩大验收结论。

记录中的部分链接指向本机保存的 `active/` 任务、日志、截图或其他附件。这些材料依照既有留档规则默认不随仓库发布，GitHub 上可能无法打开；需要复查时从原开发环境读取，或另行选取证据随归档提交。

## 读取边界

- 继续同一开发任务、任务交接或排查已登记 Bug 时，只读取对应范围的任务记录或故障索引。
- 创建或更新开发/Bug 记录时，读取策划案仓 `docs/01_workflows/开发与Bug留档规则.md`。
- 普通需求理解、新任务定位和实现验收不得默认读取 `dev_docs/`，也不得用其中历史内容覆盖用户最新原话、当前需求案、契约或代码事实。
- 无法定位记录时，先按系统、工具或工作流缩小范围，再在该范围内搜索；不得先扫描整个 `dev_docs/`。
