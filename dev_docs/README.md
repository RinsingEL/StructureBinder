# dev_docs 入口

`dev_docs/` 保存开发过程、联调证据和可复用故障经验，不是当前需求、契约或实现真值。

## 正式目录

| 范围 | 入口 | 内容 |
| --- | --- | --- |
| 系统 | `systems/<系统>/` | 系统开发记录、故障索引及相关故障资料。 |
| 工具 | `tools/<工具>/` | 工具开发记录与联调资料。 |
| 项目工作流 | `workflows/<主题>/` | 工作流开发记录与故障索引。 |

各范围内的新任务记录使用 `active/YYYYMMDD_中文任务名/任务记录.md`；提交后的归档方式以策划案仓《开发与 Bug 留档规则》为准。

根目录现存的 `active/` 和 `archive/` 是旧结构，只用于必要追溯，不再作为新记录入口。本入口不负责迁移或删除其中内容。

## 读取边界

- 继续同一开发任务、任务交接或排查已登记 Bug 时，只读取对应范围的任务记录或故障索引。
- 创建或更新开发/Bug 记录时，读取策划案仓 `docs/01_workflows/开发与Bug留档规则.md`。
- 普通需求理解、新任务定位和实现验收不得默认读取 `dev_docs/`，也不得用其中历史内容覆盖用户最新原话、当前需求案、契约或代码事实。
- 无法定位记录时，先按系统、工具或工作流缩小范围，再在该范围内搜索；不得先扫描整个 `dev_docs/`。
