# T3/T4运行态恢复与触发接口修复

## 本次任务标题

修复 T3/T4 运行态恢复与触发接口问题。

## 最终计划摘要

本轮在实现仓库修复 T3 结果无法从磁盘恢复到运行态、`/workflow/run` 字段兼容不足、零面积 T3 覆盖有效产物，以及缺少显式历史 T3 导入入口的问题；同时在文档仓库同步 T3/T4 契约、代码导览和验收入口。

## 实施步骤

1. 检查当前实现仓库与文档仓库变更，避免误改无关内容。
2. 为 `/workflow/run` 增加 `stage_id` 与 T4 参数别名兼容，并取消缺省静默跑 T1。
3. 为 T3 dat 增加读取/解码能力，并为运行态主权结果增加磁盘恢复路径。
4. 增加显式 `/territory/t3_import` 入口，用于把历史基础 ID T3 结果导入当前实例 ID。
5. 防止零面积 T3 覆盖已有非零 canonical T3 产物。
6. 补充单元测试和必要的运行态验证。
7. 同步文档仓库正式契约、代码导览与验收入口。

## 验收标准

- `/workflow/run` 支持 `stageId` 与 `stage_id`，缺少 stage 返回 400。
- T4 参数支持新旧命名。
- T3 dat 可 roundtrip 解码，导入后运行态主权查询能命中。
- 零面积 T3 不覆盖已有非零 T3 产物。
- `/territory/t3_import` 支持 dry-run 与真实导入，并处理 source 空、target 缺失等错误。
- 文档仓库同步记录接口与验收方式变化。

## 关键假设

- 采用显式导入策略，不自动把旧基础 ID T3 结果塞进当前 `@cN` 实例。
- 不提交 git，除非用户后续明确要求。
- 如真实 `runClient` 运行态耗时过长，至少完成单元测试与接口级验证记录。
