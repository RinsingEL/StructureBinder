# 冒险者地图揭示与 LandUse 容量容差

*需求入口*：用户实机验收提出：冒险者地图未开放区域使用黑色蒙版；核对当前底图是否真的来自 W 粗扫地形；LandUse 以落地优先，required Landscape 实例实际形成容量达到申请容量的 90% 即可通过，低于 90% 才失败。

*问题定位*：本次 W 的 `world_biome_preview.png` 已包含完整且可辨认的群系轮廓，粗扫数据本身正常；冒险者地图当前只把整个 `world_feature_grid.json` 压成分类纹理，没有携带服务端开放区判定结果，因此规划范围被全部画出。LandUse 在 D6 后对每个 required Parcel 使用 `claimed < minimumExecutable` 的 100% 硬门禁，`850/864` 的轻微地形损失也会中止整城。

*拟修改*：地图快照按 `PlanningAreaAccessPolicy` 为每个粗栅格冻结 reveal mask，客户端将未开放像素绘制为黑色，并在普通图层隐藏蒙版外城市节点；底图仍只读 W feature grid，不加载区块。LandUse 按 required Landscape instance 汇总申请量与实现量，门槛固定为 `ceil(requested * 90%)`；90%—100% 记录可审计降级告警和容量字段后继续，低于 90% 明确失败。

*修改内容*：地图快照新增与 `PlanningAreaAccessPolicy` 同源的逐像素 reveal mask，mask identity 同时绑定 W/国境产物、开放区配置和队列/城市状态；客户端将未开放像素绘制为近黑色，普通图层不画蒙版外城市。LandUse required Landscape 改为按实例汇总容量，固定 90% 向上取整门槛；通过但未满额时写入 `CITY_LANDSCAPE_REQUIRED_CAPACITY_DEGRADED` warning，并在 quality 冻结 requested、realized、threshold、basis-points ratio、status 与 reasonCode。

*验证结果*：真实 run `provider_4c88d8fb9d1cfd78_r8192` 的 W 群系预览已确认正常，地图填满问题属于揭示层而非扫描层。`AdventurerMapStatusReaderTest` 与 `LandUsePlanningServiceTest` 定向通过，`reobfJar` 打包通过；850/864 可通过，864 的最低通过量为 778，777 仍失败。产物 `build/libs/geomantia-0.1.0.jar`，SHA-256 `F72ECDA5A289BCC3188301E991F662ADE73F2636B469CFB8F03FB11785D8E0A1`。待新包重启后实机复验地图视觉与原失败城市续跑。

## 2026-09-03 地图实机复验补充

*需求入口*：用户反馈地图仍把中间小块地形平铺到整个渲染面，且玩家位置与地貌看起来不一致；最新口径是直接复用 W 粗扫预览语义，显示粒度按缩放层级选择，并只处理玩家视口内的地图与节点 LOD。

*问题定位*：`AdventurerMapScreen.drawMap` 误用九参数 `GuiGraphics.blit` 重载。该重载把目标宽高同时当作源区域宽高；实际 8192 半径 W 样本经固定降采样后仅为 `66×66`，放大到 GUI 数百像素时 UV 超过 1，形成重复采样。玩家实时 X/Z 和粗图 block bounds 共用同一线性变换，数值链没有发现轴交换；视觉错位由错误底图 UV 直接造成。现有 `zoom` 始终围绕完整 W 范围中心，服务端固定生成整图最多 `96×96` 并发送全部城市节点，不是玩家视口驱动的分级 LOD。

*修改内容*：客户端改用源区域与目标区域可分别指定的纹理绘制重载，固定以完整 W 纹理的 0—1 UV 拉伸一次。缩放按钮改为请求新的玩家视口：服务端以玩家位置为中心、按 256 block 量化以复用缓存，缩放 `0.5—4.0` 对应半径 `8192—1024`；在该范围内从 W feature grid 重新选择聚合倍率，远景合并多个 W cell，近景恢复到 W 原始 cell 粒度。网络只下发视口内城市节点，实时玩家标记继续每帧读取本地 X/Z。网络协议随请求结构升级。需求案、代码导览和测试入口同步最新 LOD 口径。
