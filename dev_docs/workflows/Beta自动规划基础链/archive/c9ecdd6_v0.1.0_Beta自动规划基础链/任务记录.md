# Beta 自动规划基础链

*需求入口*：`CityD4后自动编译队列-v0.1`、`初始活动区与规划区域开放-v0.1`、`W一次完整扫描-v0.1`、`City城市设计调度队列-v0.1`；用户澄清 W 一次扫描完整范围，距 0,0 的辐射顺序属于城市调度。

*修改内容*：已完成城市设计上层队列、D4 后自动编译、初始活动区和 W 一次完整扫描主链。T4 CitySeedRegistry 覆盖所有国度首都后自动生成持久化 `city_design_queue.json`；默认按城市距 0,0 排序，可通过 `config/geomantia/city_design_queue.json` 或单次请求改为按国度分组。一次只放行一个 `currentCity` 进入 D2-D4，越序请求拒绝；D4 接受后进入现有单线程后半段队列，成功到 `WAITING_FOR_GENERATION` 自动放行下一城，失败保持 `needs_agent` 并提供不重复 AI D4 的 retry。区域配置默认初始活动区 2048、首城最小距离 3072；TP 只允许初始区或已开放城市。W 对配置范围一次完整扫描，长任务位于 API worker并保留 tile 缓存恢复，不承担城市排序。

*验证结果*：实现已提交为 `c9ecdd6`（`feat(beta): 实现城市调度与区域开放基础链`）。`gradlew test --offline --no-daemon --max-workers=1` 全量 754/754 通过，0 failure/error/skipped；`country_designer_mcp npm test` 7/7 通过；双仓 `git diff --check` 无错误，仅既有 LF/CRLF 提示。新增回归覆盖全局径向排序、按国度排序、多国首都未齐时延迟启动、D4 状态驱动自动切城、失败阻塞后续城市、越序拒绝和持久化恢复；既有 D3/D7、W/T 与 City 回归全部通过。

*剩余问题*：需在真实服务端统一验收：多国 T4 完成后队列排序、当前城市 D3/D4、D4 后自动切城、失败 retry、初始区内外 TP、已开放城市和 W 一次完整扫描。玩家自配多模态 Provider 尚未开发，因此当前 `waiting_for_agent` 由现有 MCP Agent 消费；以后 Provider 直接消费同一队列接口。大型城市仍不属于本案。
