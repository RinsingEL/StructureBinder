# 开发方式约束修订

*需求入口*：用户 2026-08-24 原话——"改成严格按照案子实现完成，完成后对照用户的需求原话"；并补充禁止在代码里分版本开发（如设置开关打开老版本代码）。起因是外部 Agent 擅自把案子缩水为最小原型并在记录中自称"最小交付原型"。

*修改内容*：修订 `AGENTS.md` 开发方式一节，改用 MUST/NEVER 措辞——MUST 严格按案子实现、完成后 MUST 逐条对照用户原话验收，NEVER 自行缩减范围，切片边界只能由案子或用户当轮原话划定，记录中"原型/最小交付/后续再补"未经用户确认视为未完成；preview 保留但不等于交付完成；NEVER 在代码中分版本开发（不得保留新旧实现切换开关、配置项或并行代码路径），唯一例外是案子明确写明需要该开关。

*验证结果*：核对两个仓库，"最小交付原型"字样不在本仓记录中（源自外部 Agent 自身环境）。用户澄清"除了案子里明确写"是分版本开发的唯一例外条件，条款已按此写入。
