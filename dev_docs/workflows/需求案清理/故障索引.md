# 需求案清理故障索引

## 活跃实现当前案修订误触发清理

*现象*：开发者根据真实测试反馈修改正在开发的当前需求案后，下一次 Session 启动被 `DUE_REQUIREMENT_CHANGED` 打断；修复记录尚未提交并留在 `active/` 时，后续 Agent 又把上下文中的该记录误当成流程仍在执行。

*首次偏离*：把当前案内部的需求收敛误判成同一职责链存在另一份竞争真值。

*根因*：需求案规则将“发现同一职责链存在相反要求”写得过宽，未区分当前案内部修订与跨案冲突；2026-08-26 因而错误执行到期标记脚本。Session 门禁虽然要求检查脚本，但没有显式禁止 Agent 把未提交 `active/` 记录或上下文摘要解释成续跑信号。

*修复*：活跃 `实现当前案` 根据用户反馈修订不触发清理；只有竞争案冲突、替代案接管或职责链迁移触发即时清理。新增唯一触发源门禁：只有本次 Session 现场脚本输出 `DUE` 才能询问清理，摘要、`active/`、工作区和历史记录全部无权触发。

*验证*：Session 检查恢复输出 `OK 2026-08-27T12:32:41.0479755+08:00`，双仓库 `git diff --check` 通过。
