# City 测试运行包重构任务记录

## 目标与边界

- 把 `runId + citySeedId` 的一次 City 全链路测试包装成单一可复制、可续跑、可恢复的目录。
- D3、Blueprint、D4-D7、LandUse、Decoration、workflow 和 walls 改为包内阶段目录。
- 根清单保留请求快照、停止点、步骤和多次续跑 attempt。
- 不修改本轮景观扩张算法、Blueprint 语义或世界落地逻辑。

## 当前计划

1. 冻结共享运行包契约与 City 测试口径。
2. 新增统一路径对象并替换 City 各阶段手写目录。
3. workflow report 升级为包根 manifest，支持 attempt 追加与原子写入。
4. 保留已有 legacy run 的读取/续跑布局，验证新旧不混写。

## 关键决策

- 新目录为 `<runId>/city_test_runs/<safeCitySeedId>/steps/<stage>/`。
- 包身份稳定使用 `runId + citySeedId`，不为每次暂停/续跑生成随机 ID。
- 已存在旧阶段目录且尚未建立新包时，该 City 保持 legacy 模式；一旦新包存在，所有阶段固定走新布局。
- 旧 run 首版不隐式搬迁，避免破坏已有验收现场。

## 重要修改

- 新增 `CityTestRunLayout`，集中定义 City 测试包根、17 类阶段目录和 legacy 前缀；包根存在时强制新布局，只有旧阶段目录存在时锁定 legacy。
- `CityPlanningEndpointHandler`、`CityBlueprintService`、`CityBlueprintCompilerService`、`RealmPlanningHttpController` 和 `PatchExplorerService` 不再各自拼接活动阶段目录。
- 新 workflow 使用 `test_run_manifest.json`；每次调用先写 `running` attempt，阶段执行中持续原子更新，暂停或续跑后保留历史 attempts。
- manifest 冻结 world identity、CitySeed 快照、最近请求、状态、下一动作和 artifact 引用；D3 选址、Blueprint prepare/submit/compile 的单独调用也更新恢复点。
- 新增布局与 manifest 单测，并把 Patch Explorer 的 City fixture 切换到新包布局；旧 Blueprint/端点 fixture 保留用于验证 legacy 兼容。

## 验证结果

- `CityTestRunLayoutTest`、`CityTestRunManifestTest` 通过。
- `CityPlanningEndpointHandlerTest`、`CityBlueprintServiceTest`、`CityBlueprintCompilerServiceTest` 通过。
- `PatchExplorerServiceTest` 通过；迁移 fixture 时首次发现测试仍向旧 design-loop 目录写 occupied artifact，改为包内目录后复跑通过。
- 实现仓库与文档仓库 `git diff --check` 通过；活动 Java 代码只剩显式 legacy array/dressing 路径。
- 未启动 Minecraft 客户端或执行新区块现场验收；本轮只改变 artifact/trace 组织，不改变世界生成算法。

## 未解决风险

- 现有 legacy run 不自动迁移；它们仍可按旧布局续跑，但要获得完整新清单需后续显式迁移工具。
- `testRunId` 当前固定为 `runId + citySeedId`。同一身份的多次 workflow 调用视为同一次测试的续跑；需要并列 A/B 测试时应使用不同 runId 或 citySeedId。
