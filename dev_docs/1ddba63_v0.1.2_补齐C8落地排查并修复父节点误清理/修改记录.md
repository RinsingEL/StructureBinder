  - 而是后续 `child` 落地前的 `terrain preparation` 会在重叠 bounds 内，把父节点已落地结构的一部分当成 `embedded_solid` 清掉。
- 证据：
  - 修复前，第一跳 child 的 `20260411_162618_446/trace.json` 中，`06_apply_result.terrain_preparation.embedded_excavate` 清掉了大量明显属于 start 建筑本体的块：`stone_bricks / oak_stairs / oak_planks / glass`。
  - 这解释了为什么现场会出现“start 看起来像只剩半截”，因为它是在 child 落地时被后续链条削掉了。
- 修复内容：
  - 在 `BuildTerrainPreparationService` 中新增“父节点保护 bounds”逻辑。
  - 当前执行层会读取 transient queue 中已落地的 `DONE/BUILDING` 任务 bounds，在清理当前节点时跳过这些保护区。
  - 这样 child/grandchild 仍能清自己需要的 terrain，但不会再把父节点主体当成普通埋入实体整块挖掉。
