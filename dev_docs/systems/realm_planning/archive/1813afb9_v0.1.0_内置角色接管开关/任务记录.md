# 内置角色接管开关

*需求入口*：用户要求 MCP 设置中分别选择高级/Flash 是否由 Mod-Harness 接管，两项可以同时开启。

*修改内容*：MCP 页提供高级/Flash 独立接管开关及各自 API 配置按钮，两项可同时开启。Flash 沿用旧配置；高级单独文件与 Key、Harness 会话目录。两种内置消费者使用不同租约身份，共享世界锁；外部总调度等候被内置接管的任务。仅修改接管开关不重启 MCP；Provider 页开关与接管标志同步；主菜单可配置，联网设置包按角色路由并过滤其他角色迟到响应（协议 6）。

*验证结果*：24 项 Java、21 项 MCP 回归通过，覆盖双配置及 Key 隔离、旧开关迁移、双开/单独关闭、两个内置身份不能共占租约、外部让出已接管任务，以及修改接管不重启 MCP（真实 Node 服务保留原 MCP session）。基于 8c1b8833 的独立 worktree 打包，只纳入本任务和上一轮持续调度文件，未混入工作区其他城市改动。主模组/Harness 已重新打包、reobf、核对 SHA-256 并复制到 PCL 测试端；旧 jar 备份于 geomantia-backups/20260926-harness-role-takeover。日志及清单见本目录。

*剩余问题*：高级配置默认不启用，须由用户填入希望使用的高级 API/模型/Key；本轮未替用户选模型或发起高级 API 实测，也未改动原 Flash 凭据和启用状态。

提交归档：实现提交 1813afb9，版本 v0.1.0；本地测试与部署证据随本目录归档。
