# AI 场景策划与程序执行分工

*需求入口*：策划仓 `docs/systems/realm_planning/10_product/案子/AI场景策划与程序执行分工-v0.1/README.md`；用户已授权开发，补充结构功能与风格必须由整合包作者开局前标记，AI 不得猜测。

*根因与分层归属*：沿作者资料 → Agent 工具边界 → 正式程序执行核对。Hermes 原先忽略宿主 executor，导致来源注入和 scope/终止控制被旁路；开发 MCP 把作者目录作为模型入参，并只返回图片路径。T1 不完整 schema 与底层 fixture 默认值组合后，把缺失/错拼的设计字段悄悄替换为固定国家。调度又要求全世界 T4 完成后才进入首城。这些不是模型单纯“想得慢”，也不能靠替换框架名称解决。

*修改内容*：

- 作者资料由共享 HTTP 入口绑定。正式 D4 prepare 仅收 run/city；拒绝模型提供三类来源字段。自动发现只接受唯一 bundle，多份要求作者显式指定。可引用结构必须有 approved 功能/风格；保留真实模板 NBT/hash/rawSize 预检。
- Java Provider 与 Node MCP 共用紧凑决策视图和实际图片。保留作者语义、身份和完整冻结 artifact，省去密集 cell 集合。图片受当前世界路径边界、数量/大小预算约束；图片 base64 不挤占文本预算，Hermes 首轮另防 10 MB 请求超限并声明缺失预览。
- 正式 T1 发布完整嵌套 schema，要求显式国家/大陆/主题/比例/性格，拒绝错拼、未知字段、非整数数量和越界值，不静默裁剪或注入固定国家。提交先验证全部大陆再替换已有 profile；底层 rule_fixture 仅保留作调试验收。
- W、统一 T3、队列刷新由宿主执行。全部 T2 后统一扩张；按核心距原点推进国度，单国 T4 后立即逐城，城市按世界原点距离排序。修复 T4 恢复读取错误目录。
- Hermes 经本地带能力令牌的桥接调用同一 scope-locked executor；成功阶段提交后宿主结束模型轮，核实真实状态推进。作者/内容故障立即停，相同拒绝连续三次停；不改变 D4 五次真实编译失败预算，不向自动城市轮暴露环境重试。
- 新增独立 Hermes 0.18.2 session-stream 取消适配层，断流取消协程时中断后台 agent，并覆盖取消早于 agent 创建的竞态；不修改 vendor。初始消息也传真实图片。
- Context 增加基于实际 Reference Catalog 的 designGuide，说明功能与风格权威、真实阵列能力、功能区组合、道路目的与修订边界。保留已有 RTF 地形快路径和确定性城市编译器，不另造城市算法。
- 策划当前案、系统入口、W/T 与 City 接口/数据契约同步；下一会话整理标记已置位，本轮未做文档清理。
