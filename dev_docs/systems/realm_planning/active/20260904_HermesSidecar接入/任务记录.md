# Hermes Sidecar 接入

*需求入口*：Provider 自动规划在城市阶段运行三十多轮仍反复重取上下文、质疑工具结果，用户要求改用较完整的新 Agent 框架，并选择 Hermes。

*根因*：现有 `DeepSeekToolLoopClient` 只维持单次 Java 请求内的消息数组；宿主按确定性阶段再次唤醒时，新请求没有成熟的会话恢复和压缩机制。城市工具白名单还包含 D4 后台编译状态查询，使模型能够在应由宿主等待的阶段继续轮询。Hermes `/v1/runs` 虽接受 `session_id`，但源码确认该入口不会按 ID 自动装载旧消息，不能满足本项目的上下文连续性。

*实现*：新增 `ProviderAgentClient` 边界和 `HermesAgentClient`。默认 `agentRuntime=hermes`，设置页可切回 `legacy`；配置 schema 升至 v0.3，网络协议同步升级。Java 在当前存档的 runtime 目录提取单文件 Geomantia MCP，并启动独立的、按存档隔离的 Hermes profile。会话按 `debugRoot + runId + citySeedId/realmId` 稳定命名，调用 `/api/sessions/{sessionId}/chat/stream`，由该接口从 Hermes SQLite 恢复完整历史。Provider 密钥只通过子进程环境变量传入，profile 配置只保存 `${GEOMANTIA_PROVIDER_API_KEY}` 引用。

*职责边界*：Mod 继续拥有 discovery、正式 artifact、阶段推进、三次无进展预算和 D4 后台编译；Hermes 只处理会话、压缩与工具循环。每次 sidecar 启动只注册当前阶段 MCP 白名单；城市阶段不再暴露 `city_post_d4_auto_compile_status`，提交后由宿主等待确定性状态变化再唤醒同一会话。Hermes 的 terminal、file、browser、web、memory、skills、delegation 和 cronjob toolset 均禁用，单次唤醒最多 24 个 Agent turn，避免模型在一个确定性阶段内部重新形成三十多轮循环。

*打包*：`country_designer_mcp` 使用 esbuild 生成随 Mod JAR 分发的单文件 ESM bundle。由于 Axios 依赖仍包含 CommonJS 动态 `require`，bundle 注入 Node `createRequire` shim；否则 Hermes stdio MCP 会在 `Dynamic require of "util" is not supported` 处退出。

*本机依赖*：安装 Hermes Agent `v2026.7.7.2`（包版本 0.18.2，提交 `9de9c25f6`）。官方 Windows 安装器在 uv 0.12.9 的 Python 3.11 minor-link 检查上失败，改用本机受支持的 Python 3.12.10 创建隔离 venv，再按官方 lockfile 执行 hash-verified `uv sync --extra all --locked`。`hermes.exe` 已加入用户 PATH，并设置用户级 `HERMES_HOME=%LOCALAPPDATA%\hermes`；另启用 Git 用户级 `core.longpaths=true` 以允许官方仓库在 Windows checkout。

*验证*：JVM 全量 103 suites / 716 tests 通过，0 failure/error；MCP 7/7 通过；最终 Provider 聚焦测试与 `reobfJar` 再次通过。独立真实 smoke profile 启动 Hermes Gateway 后，`/health/detailed` 返回 0.18.2、gateway running、API Server connected；Hermes 日志确认 stdio MCP 只注册白名单中的 `mcp__geomantia__realm_w_refresh`。smoke 进程及临时 profile 已删除。

*部署*：确认无 Java 游戏进程后，将 `build/libs/geomantia-0.1.0.jar` 安装到当前 Forge 47.4.23 实例；构建包与安装包最终 SHA-256 均为 `02A4348FE250C7861FBDB88B2C1342F979D8D9F2FE21F4AEE1DC5C6FA2A4B00A`。原包备份为 `geomantia-0.1.0.pre-20260904-hermes-sidecar.jar.bak`，哈希 `222CB429666633A24F8F1E957C0233BD35EA1504CC644AED114B0E40F873EF42`。

*实机启动修复*：首次实机运行确认旧的 PCL/游戏进程环境未能通过 PATH 解析 Hermes，且 Java 的候选文件探测没有命中已存在的标准安装路径。启动器现在补充 `USERPROFILE` 候选，并在探测失败时仍优先把确定的标准安装绝对路径交给 `ProcessBuilder`，不再退回裸命令 `hermes`。修复包已通过 `HermesAgentClientTest` 和 `reobfJar`，并于 2026-09-05 部署到测试实例；SHA-256 为 `6B71ADA12A1636B8C94800193155B84F23F847CFA164686B71E4DC73A178D382`，上一版备份为 `geomantia-0.1.0.pre-20260905-hermes-absolute-path-fix.jar.bak`。

*玩家免依赖运行时*：实机进一步证明原安装是 Codex AppContainer 内的 editable 开发环境，游戏不能看到被重定向的 `%LOCALAPPDATA%\hermes`，而 editable finder 又绝对指向 Codex 容器源码；该目录还包含 uv 的 `*-none` Junction，不是可发布运行时。现已用官方 `v2026.7.7.2`/Hermes 0.18.2（提交 `9de9c25f`）重建 Windows x64 便携包：内置 CPython 3.12.10、非 editable 锁定核心依赖、MCP 1.26.0 和 Node.js 22.23.2，强制 copy link mode，不含 Junction。压缩包约 100.9 MiB，SHA-256 为 `B893E737FF8C5373A8B22DB2C0BFA03B042183DE98786D4D6AEEC51EA5923580`。Mod 首次运行自动解压到 `config/geomantia/runtime/hermes-0.18.2-win-x64/`，并通过 `PYTHONHOME`/`PYTHONPATH` 和内置 Node PATH 启动；profile 也改存于游戏目录，不再读写 AppData。专项测试已在临时目录真实解压并在清空系统 Python/Node PATH 的条件下成功运行 `Hermes Agent v0.18.2`。内置 MCP 后的最终 Mod JAR 已重新生成并部署；上一版备份为 `geomantia-0.1.0.pre-20260905-bundled-hermes-runtime.jar.bak`。

*Gateway 与 MCP 工具注册修复*：便携运行时补入 `aiohttp 3.14.1` 后，真实 Gateway `/health` 已返回 200；但进一步实机与源码排查发现，MCP 1.26.0 在 Windows stdio 初始化时需要导入 `pywintypes`。便携包本身已经包含 pywin32 311，然而其 `site-packages` 是通过 `PYTHONPATH` 外挂，Python 不会处理其中的 `pywin32.pth`，导致 `win32/lib` 与 `pywin32_system32` 未进入模块搜索路径；Hermes 又把该 ImportError 吞成 `_MCP_AVAILABLE=false`，因此 Gateway 可连接但 Agent 没有任何 Geomantia 工具。启动器现显式把 `site-packages`、`win32`、`win32/lib` 和 `pywin32_system32` 全部加入 `PYTHONPATH`。真实隔离 smoke 已证明 Gateway connected、Provider 收到 `mcp__geomantia__realm_w_refresh` schema、Hermes 调用该工具、模拟 Minecraft API 收到 `/realm/w/refresh`，最后会话返回 `DEV_SMOKE_OK`。运行时导入回归、`HermesAgentClientTest` 和 `reobfJar` 均通过；2026-09-05 修复包 112108459 bytes，构建包与安装包 SHA-256 均为 `18BBC3C5EE98AD13F10BF64CC747ECC31AD65A161030F35A4A4C0C11A87C5F67`，上一版备份为 `geomantia-0.1.0.pre-20260905-hermes-pywin32-path-fix.jar.bak`。

*剩余验证*：启动游戏后在 Provider 设置中保持运行时为 Hermes，首次启用应先显示内置运行时解压进度，然后出现 “Hermes Gateway 已启动” 和稳定会话日志，并跑到第一座城市 `WAITING_FOR_GENERATION`；这一步会使用玩家现有 Provider 配置并产生真实调用费用。
