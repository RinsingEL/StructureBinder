# T2 重复地形重采样

*需求入口*：用户询问本次 Patch 阶段耗时很久是否异常，并于 2026-08-31 要求将 T2 严重性能问题按 Bug 留档后修复。

*修改内容*：保留原问题定位，在 `PatchExplorerService` 增加磁盘共享的 `t_scale_refinement_cache.v0.1`。缓存 identity 绑定规范化 W 允许范围、实际 terrain provider / dimension / source fingerprint / sampling semantics 及算法版本；同一 run 的相同范围只执行一次 T 尺度采样、分类与跨 region 合并。各探索 session 的 `scope_snapshot.json` 改为只保存共享 artifact 路径和内容 SHA-256，恢复会话时校验文件路径、hash 和 step。HTTP 层传入完整 provider identity，并让 T Patch ID namespace 使用缓存 identity，避免按 realm 重算和产生顺序相关结果。

*验证结果*：问题基线仍为真实 run `realm_w_mte38ltl_f1964c5a`：W refresh 393.61 秒；三个国度 T2 open 为 295.43、267.58、260.46 秒，原实现各写约 108.5MB snapshot。新增回归证明相同范围、同 provider 连续打开两个 realm 时 runner 只调用一次，第二次返回 `tScaleRefinementCacheHit=true`；session snapshot 不再内联 `scopeCells/candidates` 且小于 8KB；show candidates 可从共享文件恢复；更换 provider identity 会重新 refinement。`PatchExplorerServiceTest`、`RealmPlanningHttpControllerPathTest`、`RealmT4PatchPlanningServiceTest` 定向回归通过；完整 JVM 99 个套件、738 项通过，MCP 7/7 通过，两个仓库 `git diff --check` 无空白错误。

2026-08-31 在开发客户端存档 `RTF0810` 对同一 sealed W run 做真实 T2 复验，不重跑 W。三个同范围国度依次 open：`realm_salt_kingdom_0` 冷启动 268.905 秒、`cacheHit=false`；`realm_stone_march_1` 热命中 1.563 秒；`realm_green_court_2` 热命中 1.311 秒。三次总计 271.779 秒，相比原 823.47 秒减少 551.691 秒（67.0%）；第二、第三次分别减少 99.42% 和 99.50%。三国都引用同一份 39,820,448 bytes（37.98 MiB）refinement；三个 session snapshot 分别为 962、961、961 bytes，不含 inline `scopeCells`，且 terrain/all-patches 总览均存在。第三国度 `show_candidates(plain)` 0.910 秒成功并生成 Top Patch 图；客户端日志没有 T2 ERROR/Exception。
