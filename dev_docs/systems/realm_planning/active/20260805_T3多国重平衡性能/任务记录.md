# T3 多国重平衡性能任务记录

## 现象

- run：`rtf0805_newsave_w32768_20260805_1840`。
- W 为 66048 x 66048 blocks、66564 粗 cell；T3 目标大陆 `continent_0` 为 10871 个可分配 cell。
- 12 个国度的 T1/T2 已完成；旧 `quota_frontier` T3 运行约 9 分钟仍没有 `realm_territory_map.json`。
- 现场 Java working set 约 10.32 GiB、private memory 约 11.91 GiB；线程栈停留在 `rebalanceAreaQuotas -> bestRebalanceCandidate -> hasOwnedNeighbor`，持续运行而非死锁。

## 根因

- 每移动一个边界 cell 都重新扫描所有 ownership 统计 count。
- `bestRebalanceCandidate` 每轮执行 `profiles × land cells` 全扫描，再对候选执行 donor 连通性 BFS。
- receiver 达到 quota 后仍可继续接收至 120%，不能保证一次移动降低总配额误差；真实首轮优化暴露两次各 43484 move 的振荡上限。

## 修复

- 初始只索引跨国边界 cell，以确定性优先队列选择最低 score 候选。
- realm count 常驻维护；移动后仅更新 donor/receiver count，以及当前 cell 和四邻边界候选。
- 候选 score 随 count 变化时懒刷新后重新入队。
- donor 必须超 quota，receiver 必须低于 quota，使每次移动严格降低面积误差。
- seed cell 不可转移、`canReleaseCellWithoutDisconnecting` 连通性门禁、repair 产物与公开契约保持不变。

## 验证

- 新增 `quotaFrontierScalesToTwelveRealmsAndRemainsDeterministic`：约 4096 cell、12 国，两次 T3 各自在 10 秒门限内完成，JSON 相同、12 国均有领土且单连通，quota move 不超过 territory cell 数。
- 既有 quota/action model、比例归一化、checkpoint 回归通过。
- 真实 run 重启后从 W/T1/T2 checkpoint 懒恢复并执行 T3：HTTP 8.034 秒完成，10871 cell 全部 owned，12 国 `componentCount=1`、`largestComponentRatio=1.0`。
- 真实 quota repair 为 299 move；未再撞 43484 上限。
- 完成后 Java working set 约 5.51 GiB、private memory 约 6.26 GiB。
- T4 `rule_fixture` 17.439 秒生成 36 城、12 首都；正式 `realm_t4` Patch Explorer 对 `realm_salt_kingdom_0` 1.530 秒完成，provider 为 `rtf_heightmap_preview_v0_0_5`。

## 边界

- 本轮只修复单 normalization group 内的 `quota_frontier` 兼容模型性能与收敛性。
- T1 默认 `realmCount=3` 和“默认只选择最大大陆”尚未改为按 W 大陆面积自动分配；多大陆联合 T3 属于后续产品语义调整。
- strict 正式主线仍默认 `action_budget`，本轮没有把强 quota rebalance 引入 action model。
