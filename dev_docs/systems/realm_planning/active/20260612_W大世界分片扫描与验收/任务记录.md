# W 大世界分片扫描与真实验收任务记录

## 背景

用户确认 W 阶段应面向开放世界大地图，不能只扫单个 GIS Region；初始世界设定需要等待配置范围内 W 全部扫描、分片缓存、patch 汇总并 sealed 后，才能进入 T 阶段规划。

## 本轮实现范围

- W 默认粗扫 step 采用 `cellStepBlocks=128`，GIS 内核默认 step=4 不变。
- 新增 `WorldSurveyRunner`，按 `planningRadiusBlocks` 枚举 GIS Region tile，逐 tile 扫描并写 `tiles/region_<x>_<z>.json`。
- 新增 `WorldSurveyResult`，作为 sealed W 调度结果，供 `RealmPlanningService` 消费。
- `RealmPlanningService` 从单 `RefreshResult` 消费改为优先消费 sealed `WorldSurveyResult`，旧单 Region 入口保留为兼容包装。
- HTTP / MCP 新增 `planningRadiusBlocks`、`resumePolicy`，`radiusChunks` 保留为兼容字段。
- Forge 命令改为 `/geomantia realm acceptance [planningRadiusBlocks] [cellStepBlocks]`。
- `acceptance_report.json`、`world_survey_context.json`、`w_manifest.json` 记录扫描范围、tile 数、缓存命中、失败数、数据量和 sealed 状态。
- 同步文档仓库国度规划方案、数据契约、MCP 接口、代码导览和测试验收口径。

## 风险与后续

- 当前 `world_patch_map.json` 为完整 cell 明细 JSON，8192 半径时约 8.6 MB；更大世界范围需要考虑压缩、分页或二进制缓存。
- 目前 tile 缓存复用按 run 目录和文件存在判断，后续应增加配置 hash 校验，避免不同 seed / step / 半径误复用旧 tile。
- 当前 patch merge 仍以 GIS Region 内 patch 为基础，跨 tile 的同类 patch 还没有做全局连通合并；T 阶段可用，但后续更大世界建议补全局 patch merge。
- MCP SDK 默认单请求 60 秒超时，长 W 扫描需要调用方传长 timeout 或拆成异步 job/status 工具。
- 当前 W tile cache 绑定 run 目录；如果想用同一 sealed W 底图快速试多套国度配置，需要后续拆分 `surveyId` 和 T `runId`，或把 tile cache 提升到按世界 seed / 维度 / step / bounds hash 共享。

## v1.2 自测与真实游玩验收补充

- T3 从旧的静态 claim 排序改为多源 frontier 扩张，并加入孤岛修复、未声明 cell 挂接和面积 rebalance。
- T3 strict 硬阻断现在关注拓扑和 `scalePlan.minAreaRatio/maxAreaRatio`，`targetAreaRatio` 偏差进入评分；避免把地形连通性约束下的可玩结果误判为失败。

- `qualityMode=strict` 用于正式验收；Forge GameTest 使用 `qualityMode=smoke` 覆盖真实 `ServerLevel` 链路，不再把 W 粗分类质量问题当成 GameTest 编译 / 启动失败。
- v1.2 当时 `microSampleStrideBlocks` 已进入接口和 manifest，但仍是质量元数据，`microSamplingImplemented=false`；真实 16/32 block cell 内 micro-sampling 留待后续 W 质量重构补齐。

## v1.3 / v1.4 补充实现记录

- v1.3 已在 `WorldSurveyRunner` 内补齐真实 micro-sampling：
  - `WorldSurveyRunner.Config` 新增 `localSlopeRadiusBlocks`，默认 `8`。
  - 分片 W survey 会按 `microSampleStrideBlocks=32` 对每个 planning cell 采样，聚合 `heightP10/P50/P90`、`robustRelief`、`slopeMean/P90`、`steepFrac`、`waterFrac`、`biomeHist` 和 `microSampleCount`。
  - 新增 `world_feature_grid.json`，并把统计内嵌到 `world_patch_map.json.cells[]`。
  - tile cache 与 feature grid cache 写入 `configHash`，不同 seed / 维度 / 范围 / step / stride / slope radius 不应误复用。
- v1.4 已新增 T3 `action_budget` 模型：
  - `strict` 默认 `expansionModel=action_budget`；`smoke` 默认保留 `quota_frontier` 对照。
  - 程序从 `ScalePlan.priority` 和 `ExpansionStyle` 派生 `ExpansionBudget`、`TerrainCostProfile`，不让 AI 填底层成本表。
  - `RealmTerritoryMap.territoryCells[]` 新增 `status=owned/wild/contested/blocked/unreachable`、`claimCost`。
  - `t3_report.json` 新增 `expansionBudgets`、`terrainCostProfiles`、`territoryStatusSummary`、预算使用率、地形成本分布和停止原因。
  - `score_manifest.subScores.T3` 新增 `budgetCoherenceScore`、`terrainIdentityScore`、`wildlandScore`、`contestedReasonabilityScore`、`overExpansionPenalty`。
  - action model 下 `scalePlan.targetAreaRatio/min/max` 作为软目标和评分信号，不再通过 rebalance 强行吃满大陆；`quota_frontier` 下仍保留面积弹性硬阻断。

## 最终剩余风险

- Dregora 标准档 JSON 产物仍较大，`world_patch_map.json` 和 `world_feature_grid.json` 后续建议做压缩、分页或摘要化。
- `wildlandRatio` 在 action budget 下仍较高；本轮通过是“可玩国度 + 大荒野”口径，后续若希望国度更密，需要继续调预算模板或引入剧情 / 道路 / 资源驱动二次扩张。
- 当前自动 T1 点已为验收避免孤点，但手动 AI 选点仍允许玩家选择极端海角；这类结果会由 T3 strict 最低可玩领地阻断兜底。
