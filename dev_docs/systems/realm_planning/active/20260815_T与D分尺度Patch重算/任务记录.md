# T与D分尺度Patch重算

*需求入口*：`designer_territoryMod/docs/systems/realm_planning/10_product/案子/T与D分尺度Patch重算-v0.1/README.md`。

*修改内容*：新增多 GIS region 统一指标计算与全局四邻接 Patch 合并；T2/T4 的 HTTP open 以 W / owned cells 为范围，使用当前地形 provider 在不大于 32 格的 T 尺度重新采样、分类和生成候选，候选模型升级为 `landform_patch_candidates_v0_2`、正式 `candidateBasis=t_scale_landform_patch`。D3 在既有城市 step 采样后统一跨 region 重算和合并，并把全局 Patch 交给 review、预览和 LandUse terrain field。T2/T4 下游用精确 anchor block 换算回 W grid，避免混用尺度。后续按最新反馈把候选预览改为三张同边界总览：原始地形、全部 Patch、当前各类型 Top Patch；T/D 共用固定色表，批量阶段不再逐候选生成孤立预览，选中后的城市尺度确认图保留。MCP 描述与双仓库契约同步。

*验证结果*：跨 region 平地单 Patch、W `ridge` 在 T 细尺度重分为水体、Explorer 使用 T cell、T anchor 转回 W territory grid 等聚焦回归通过；最终完整 JVM 94 个套件、669 项测试通过，0 failure / error / skipped，MCP 7/7 通过，双仓库 `git diff --check` 通过。三张同边界总览的聚焦测试覆盖固定色号、PNG 产物存在和三图尺寸一致。真实 `RTF0810` 中，T4 以 32 格重算 5904 cells、7 类并生成每类 Top 3 共 21 个候选同框图；D4 以 16 格地形场生成 8 类、22 个 Top 同框图。修正标签避让后人工检查无标签相互遮挡或越出地图框。T4 open 原需约 28 秒，MCP 改用 refresh timeout 后正常返回 `ok=true`。

*剩余问题*：T4 当前真实 provider 因 RTF generator context unavailable 回退到 Minecraft prior；该来源已在正式响应中明确记录，本次不影响三图同框与 Patch 关系预览验收。
