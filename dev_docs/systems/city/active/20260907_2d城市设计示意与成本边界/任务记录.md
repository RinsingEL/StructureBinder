# 2d城市设计示意与成本边界

*需求入口*：用户要求独立「2d城市设计」案、示意图，并明确高成本原型不做。

*修改内容*：创建设计中案与三种人工空间示意，登记产品索引；不变更游戏代码、存档、正式工作流及当前案身份。可视化使用可编辑二维图形，未生成宣传性假实景。

*验证结果*：三份 SVG 已渲染 PNG 并目视检查，中文与标注可读；会话示意在 736px/360px 检查无横向溢出，三个图均显示。产品 README 引用 PNG、SVG 保留可编辑源。图示不是生成算法输出，不能算原型已实现。按前序桌面存放意向提供桌面副本，仓库版本为后续维护源。

*剩余问题*：用户尚未确认图示方向与原型开发上限；不自动开工原型。

## 低成本原型建议（未批准实施，非产品硬要求）

首轮建议限制为一个 **2–4 小时的开发时段**，这是检查点而非完工承诺；到点交付可见结果或具体阻塞，不自动续期。只读取一份现有建筑落位、真实 footprint/入口和 D3 快照，在一个本地二维页面上显示与比较。无登录、后台服务、编辑器框架、全世界队列、Hermes 或新的 MC 启动依赖。

这一步只能证明数据可复用、布局能快速检查，**不能证明生成算法变好**。手工参考布局与原编译结果明确区分。复用原编译器的离线重放若已有可用入口，再接一次真实输入重放；若需要先拆解运行时依赖，不在本阶段自动重构。

成本分为三档：静态示意图（本轮）低；现有数据二维查看/前后对照预计较低但需验证数据接入；改良通用布局求解器或完整 NBT 三维渲染成本未知、明显更高，必须另行估计并由用户决定。禁止把第三档伪装成第一档附带工作。

最小交付不预设必须开发完整 NBT 三维查看器。先用真实宽深高、入口和已有截图核对尺度；必要时采用简单体块，必须标明不能证明真实材质观感。之后再决定是否值得接已有渲染能力。

本轮不采集更多世界数据，不移动角色，不启动游戏，不改现有错误处理，不提交 git。成本建议保持在开发记录，需求案只保留用户已提出的行为与成本边界。
