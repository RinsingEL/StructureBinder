# D4连续外扩候选任务记录

## 目标

- 将 D4 v0.4 常规向外阵列从“指定目标 patch 后在 patch 内排布”改为“以已冻结父结构的 D2 实体 / 碰撞 bbox 为起点，按方向连续生成候选”。
- 让 D3 patch 回归地形筛选、评分和归属输出，而不是城市空间连续性的硬边界。
- 修正 D4 预览将 TerraSense 静态 footprint 画成实体内框的问题，明确 D2 body、collision 与 mask。

## 触发事实

- 真实城市会话中，庄园西北住宅簇内部 D2 实体间距约 19-32 格，但最近住宅与庄园实体边缘相距约 80 格。
- 根因不是庄园 patch 无容量，而是调用方预先指定了外侧 `坡地204`；现行 v0.4 常规外扩按该 patch 生成候选，缺少 bbox 前沿连续性约束。

## 设计口径

- 常规 outward 输入以 `focusRef + direction + bodyGapPolicy` 为主；`targetPatchRef` 变为可选兼容约束，而非必填。
- 程序从父对象 D2 真实几何的指定面 / 角生成近、中、远候选带；候选优先满足实体边缘目标间距，近带不可用时才扩大，并记录原因。
- D3 patch 按候选真实 footprint 参与 terrain/member-cell 可用性筛选和评分，可跨 patch。

## 验证

- City 自动回归通过：`./gradlew.bat test --tests com.rinsing.geomantia.systems.city.*`。
- MCP TypeScript 校验通过：`country_designer_mcp/.\node_modules\.bin\tsc.cmd --noEmit`。
- 新增专项覆盖：省略 `targetPatchRef` 的连续候选、真实 D2 `37x37` 父体与 `49x49` 子体在自动 spacing `65` 下保持 16-30 格实体间距、近圈水域拒绝并输出原因、基础 anchor 从嵌入 D2 facts 推导 body、跨 patch 归属筛选。
- 预览测试通过：D4 总览使用 D2 body，且生成簇局部图与 outward 候选局部图。
- 双仓库 `git diff --check` 通过；仅有既有文件的 LF/CRLF 提示。

## 剩余风险

- 当前客户端仍加载变更前类。需重启客户端后，以庄园 `tidewatch_manor_v2` 在不传 `targetPatchRef` 的前提下重跑南侧近邻候选，并人工确认局部图中的首户实体间距与地形结果。

## 真实验收 L1 修正

- 首次客户端验收中，庄园南侧 `坡地202` 被连续筛选器错误列为水域，未生成候选。
- D3 真值显示该 patch 为 `slope`、`gentle`、`minecraft:savanna`；仅 overlay 含 `near_water`。根因是 `waterPatch(...)` 以文本包含 `water` 判断水体，误伤临水陆地。
- 已改为只拒绝 `LandformType.WATER` 或精确水体标签；`near_water`、`nearwater`、`waterfront` 仍允许 grounded 结构。已补 near-water slope 允许、真实 water 拒绝的对照测试，并再次通过 City 包级回归。

## 真实验收 L2 修正

- 临水坡地放行后，南侧四户住宅簇仍无法在 near ring 产出三组候选；追踪显示首户 body gap 被错误计算为 `13`、`45`、`61` 等值。
- 根因是前沿起点使用了自动 spacing，而 `compoundCluster.spacingBlocks` 只在簇构图时生效。两套间距使首 guide 的内偏移补偿失真，首户不再落在由 D2 body 推导的前沿线上。
- 已让连续前沿与簇构图共用同一 `spacing(...)` 结果；先按父 / 子 D2 body 计算首户锚点，再抵消 grid 首 guide 的内偏移，候选变体只作横向移动。
- 新增“南向 `111x111` 父体 + 四户 `2x2` 簇”回归：三组候选均留在 near ring，首户真实 body gap 均为 `16-30`。已通过 City 包级回归。

## 候选不足规则

- 第二层四户住宅簇的真实近环仅有两组完整合法候选；水域、陡坡与 D2 body gap 校验共同排除了其余横向变体。
- 原实现将 `minCandidateCount` 固定钳制为至少 `3`，使这两组合法候选无法展示和人工选择。
- 已改为默认仍要求 `3` 组；调用方显式传 `minCandidateCount=2` 时才允许返回两组完整候选，不以残缺簇凑数。`candidateCount` 仍限制在 `3-5`。
- 已补“受限环境默认三选失败、显式二选成功返回两组”的回归，并通过 City 包级测试。

## 真实验收 L0 配置修正

- 开始磨坊农庄的通用装饰设计时，`query_decoration_catalog` 返回 `CITY_DECORATION_CATALOG_ROOT_INVALID`；运行时 `config/geomantia/city_decoration` 根目录从未创建，故 catalog loader 无法解析任何语义素材。
- 根因是 v0.2 已定义 config 为运行时真值，却没有正式的首次安装路径；不是农田 `cross_section_repeat`、D3 patch 或地形裁剪算法失效。
- 已加入一次性默认目录安装器：仅当根目录不存在时，把打包的 `content_index.json`、`medieval_coastal` 风格档案、四个有效 1x1 NBT tile 和安装清单写入 config；根目录存在时绝不覆盖用户内容。
- `medieval_coastal` 基础包映射 `crop_tile`、`water_channel_tile`、`field_border`、`gravel_path_tile`，可用于磨坊农庄的“田埂 - 农田 - 水渠 - 农田 - 田埂”阵列与作业小路。
- 已新增安装 / 不覆盖专项测试，并通过 `./gradlew.bat test --tests 'com.rinsing.geomantia.systems.city.*'`。运行中的客户端不会热加载 Java；重启后首次查询 catalog 才会落盘并可进入农田 Program 设计。

### 默认农田素材校正

- 首次真实查询虽然成功安装目录，但检查 catalog 后发现 `crop_tile` 与 `water_channel_tile` 继承了 `above_surface + replaceable_only` 默认值；其中 `crop_tile` NBT 仅有小麦，缺少下方耕地，无法作为可生存农田落地。
- 已将两者显式改为 `replace_surface + surface_replaceable`；农田 NBT 改为两层 `farmland + wheat`，水渠在地表位置替换为水面。田埂继续使用上方放置的栅栏，作业小路继续替换地表。
- 已确认刚生成的 config 目录仅含基础包文件后重置，不涉及用户配置；重启后由修正后的基础包重新安装。专项与 City 包级回归通过。

## 装饰连续带地形探针

- 磨坊农田的意图预览只能显示 D3 member mask 与数组构图；1x1 crop / water tile 的 worldgen 编译只检查自身 footprint，不能发现整条水渠跨坡后断流或泄水。
- 新增只读 `city_probe_decoration_terrain`：读取已经冻结的 compiled decoration plan 与 slot projection，严格只查已加载 chunk；未加载槽位只返回 unavailable，绝不生成 chunk、写世界、写 artifact 或激活 decoration registry。
- 结果 schema 为 `city_decoration_terrain_probe.v0.1`；每个 program / palette 输出 loaded coverage、height min/max/spread、四邻接高差和全部线性 pattern 的 `continuousBandProfiles[]`。`cross_section_repeat` 的连续轴取反轴，`parallel_rows` 使用声明轴，不能按世界方位猜测。
- 探针给出人工决策 `await_chunk_load`、`review_terrain_before_activation`、`ready_for_activation`，不硬阻 `city_execute_d5`；水渠只是读取连续带 profile 的一种消费者语义，不以“农田/水”业务算法实现。
- 已覆盖 cross-section 反轴、parallel rows、未加载槽位不读伪高度、handler 不写 artifact；City + HTTP 回归与 MCP build 通过。当前 `invalidTerrainAction=clip` 仍未在 chunk compiler 中实现为连续带裁剪，探针仅如实报告风险。
