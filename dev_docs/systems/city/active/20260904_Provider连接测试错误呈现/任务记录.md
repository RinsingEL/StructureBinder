# Provider 连接测试错误呈现

*需求入口*：用户在游戏内将自定义 Provider 配置为 OpenCode Go `https://opencode.ai/zen/go/v1` 与 `gpt-5.6-luna` 后，连接测试只显示“连接成功但多模态不可用”，且无法看到完整上游错误。

*修改内容*：确认 Minecraft JVM 已携带 Clash HTTPS 代理参数；用游戏保存的 Provider 配置与密钥做最小对照请求，定位连接测试请求的 `max_output_tokens=8` 低于上游最小值 16。连接探针现以具名常量固定使用 16，并增加请求体回归断言。代理配置仍留在启动器 JVM 参数中，不写入 Mod。测试器把任意视觉请求非 2xx 响应归类为 `connected_text_only` 并丢弃响应正文的问题本次未扩大处理。

*验证结果*：Go `/models` 返回 200 且包含 `gpt-5.6-luna`；经同一 Clash 代理发送纯文本与图片 Responses 请求时，8 token 均返回 `integer_below_min_value`，改为 16 后两者均返回 200、`completed`、`OK`。`ProviderConnectionTesterTest` 聚焦测试通过，覆盖探针请求必须携带 `max_output_tokens=16`。

*剩余问题*：错误呈现仍需后续按 HTTP 状态与脱敏后的上游错误区分鉴权、地区、限流、参数错误和真实多模态不支持；UI 仍需允许完整错误换行或滚动显示。修复后的游戏内按钮需在新构建重启后复验。
