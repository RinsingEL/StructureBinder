# City 模板内容包自动安装

*需求入口*：`City整合包内容配置-v0.1`；用户要求根据配置自动准备并安装外部模组模板到当前世界 `generated/geomantia/...`，不默认全量盲导入。

*修改内容*：增加 `city_template_content_pack.v0.1` manifest 与内容包组装工具，只收录当前 catalog 唯一引用；世界启动时先校验 catalog 完整覆盖、catalog/source hash 与安全路径，再原子安装缺失模板、修复漂移并保留无关 generated 文件。D4 Context 创建前从当前世界实读全部目录模板，校验运行时 hash/rawSize，缺失或漂移时在 Agent 调用前失败。开发环境和 47.4.23 实例已各生成 65 项、约 0.73 MiB 的当前内容包。

*验证结果*：`CityTemplateContentPackInstallerTest` 与 `CityTemplateAvailabilityPreflightTest` 聚焦通过；完整 `gradlew test` 通过；`tools/city_templates` 共 28 项 Python 测试通过；真实内容包 manifest 为 65 项且只包含当前 catalog 引用。47.4.23 的 `(1)` 存档已在 10:58:44 自动安装 65 份模板，`copied=65`、`repaired=0`，内容包安装路径实机通过。

*实机续跑修复*：首次重启后暴露上次模板缺失留下的 `locked=false` D6 诊断计划仍被 `skipExisting` 复用，Post-D4 因而固定失败。现 D6 只有来源锚点一致且通过完整锁定计划校验时才可跳过；未锁定旧计划会重建。继续实机观察证明更上层的所有权也有误：Post-D4/D6 失败被粗略标成 `needs_agent` 后再次交给 DeepSeek，导致只读 status、D4 重提和 30 秒无推进退避。现程序阶段失败不再属于 Provider actionable 状态，保持原地报错且不回退 D4。用户决定删除本验证世界的旧版本规划/运行产物，从干净 W 流程复验；模板包源配置与 Provider 配置保留。
