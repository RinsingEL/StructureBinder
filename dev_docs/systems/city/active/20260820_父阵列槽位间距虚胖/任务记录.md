# 父阵列槽位间距虚胖

*需求入口*：用户查看 `city_realm_salt_kingdom_0_capital` 最新 D4 产物后指出："CENTER_SYMMETRIC 父阵列……功能区之间隔很远"，并认为"出格是很正常的，因为 step 太大了，全是方格会很恶心，正确做法我觉得是真实落地的占地面积小于设计目标就得了吧"，同时提问"是不是一个城市阵列应该分主次，才能有那种明确的街区划分的感觉"。用户与 codex 讨论的"父阵列按固定 96 格排版、导致功能区间距虚胖"此前尚未登记。

*修改内容*：父阵列槽位改为按 required/fill 模板 transformed footprint、城市尺度最低结构数、子算法、密度和区内街带推导 `plannedSpanBlocks`，不再用 extent 最大跨度常量占位；CENTER_SYMMETRIC 对称成员保留同一中心和半径，但各自使用真实槽位跨度。功能区容量改用同源模板阵列需求，固定 RoadWeaver 道路预算归零；父槽位只约束建筑硬骨架，容量从槽位核心向可用地形不规则扩张，STANDARD/PERIPHERAL 目标允许小于 extent 设计目标。LINEAR 将画像 anchor/key 或 AI required 首项作为轴端主建筑，有 road entrance 时由入口定轴，后续槽位沿程序派生街带两侧排队。同步 CityBlueprint 契约与故障索引。
