# RoadWeaver 关服刷屏诊断

## 任务范围

- 类型：实现仓库故障诊断，不修改 City 方案、契约、代码导览、测试入口或业务实现。
- 现象：单人游戏退出时 RoadWeaver 日志刷屏，无法正常退出；截图同时出现大片区块未显示。
- 现场：`run/logs/latest.log` 与 `run/logs/debug.log` 各约 186MB，最后写入时间为 2026-07-09 23:02:12。

## 关键证据

1. 关服时间线：
   - 22:59:12 玩家退出并触发 `Stopping server`、`Saving worlds`。
   - 22:59:13 `RW-Idle-1` 仍在执行 `Road.generateRoad -> RoadSqliteStorage.addRoad`。
   - H2 查询 `SELECT 1 FROM roads WHERE fingerprint = ? LIMIT 1` 失败。
   - `roads.trace.db` 的底层原因为 `java.nio.channels.ClosedChannelException`。
2. RoadWeaver 2.2.2 的停止顺序：
   - `RoadGenerationService.onServerStopping()` 仅对 Future 调用 `cancel(true)`，没有等待任务结束。
   - `CacheManager.onServerStopping()` 随后执行 `RoadShardStorage.flushAll()` 和 `RoadShardStorage.shutdown()`，关闭 H2 数据库。
   - `ThreadPoolManager.onServerStopping()` 最后才关闭通用 worker。
   - 因此已有道路任务和完成回调可在数据库关闭后继续执行 SQL。
3. 异常规模：
   - `latest.log` 中约 39,704 条 `MVStoreException`、19,852 条 `Reading from file`。
   - RoadWeaver 相关日志约 934,648 行。
4. 历史征兆：
   - 2026-07-01、07-02、07-03、07-06、07-07、07-09 的多份压缩日志已有每次约 6 条 MVStore 关服异常。
   - 说明竞态早于 2026-07-09 的 Geomantia 开发版本存在；7 月 9 日只是首次放大成持续刷屏。
5. Geomantia 版本边界：
   - 2026-07-09 的 v0.1.39-v0.1.45 主要修改 D2 profile、结构 envelope 和 D4 array/layout loop。
   - `CityRoadWeaverBridge` 最近提交为 2026-07-06 的 `55b5549` 和 2026-07-01 的 `428148e`。
   - 当前证据不支持“7 月 9 日直接改坏 RoadWeaver API 调用”。可能存在的间接放大因素只是更多结构/连接使 RoadWeaver 在退出时仍有未完成任务，但根因仍是 RoadWeaver 对合法并发关服缺少生命周期屏障。
6. 数据库状态：
   - 当前存档 `roads.mv.db` 创建于 2026-07-06，大小约 502.65MB。
   - 另一个历史验收存档数据库约 1.65GB，说明文件大不是单独充分条件。
   - 本次 trace 明确指向关闭后的文件通道访问，不应先把结论定为单纯文件体积或磁盘截断。

## 结论

主根因是 RoadWeaver 2.2.2 的关服并发竞态：道路生成任务未完全停止，数据库已被 flush/close，后台任务继续执行查询、写入和后处理，触发 H2/MVStore `ClosedChannelException` 并持续刷日志，使集成服务器无法完成退出。

Geomantia 的 RoadWeaver adapter 使用公开的 endpoint/connection API，且 7 月 9 日提交没有修改 adapter。Geomantia 可能通过增加道路连接或让任务持续更久提高竞态命中概率，但没有证据表明它传入了非法坐标、直接关闭数据库或直接破坏区块。

截图中的大片缺块没有在本次日志中找到对应的渲染、区块保存或区块删除异常。它可能是服务端进入关服/道路任务阻塞后不再正常供给区块，也可能是独立的客户端渲染问题；当前证据不足以把它与数据库竞态判定为同一个 bug。

## 建议修复顺序

1. RoadWeaver 增加全局 `stopping` 状态，关服后所有 tick、idle planning、generation、DB enqueue 和完成回调立即拒绝新工作。
2. 先停止道路调度与 worker，使用 `shutdownNow()` 并有界 `awaitTermination()`；确认任务退出后再 flush/checkpoint/close H2。
3. RoadDatabaseManager 的 executor 在 shutdown 后拒绝提交，并在 `ClosedChannelException`、database closed、MVStore closed 时熔断，不把失败任务重新进入生成队列。
4. `safeGenerate` / idle 任务在中断或 epoch 失效后不得继续 `addRoad`、snap、publish 或更新连接状态。
5. 增加集成测试：生成长道路时立即触发 server stopping，断言无 DB close 后 SQL、无持续日志、进程在超时内退出。

## 临时规避与验证

- 先完整备份存档。
- 临时关闭 RoadWeaver idle generation，或退出前等待当前道路生成完成。
- 新存档/重置 RoadWeaver 数据用于 A/B：只移动备份 `data/roadweaver/minecraft_overworld/` 和相关 RoadWeaver world data，不删除 Minecraft region 文件。
- 分别测试：纯 RoadWeaver 空存档、Geomantia `roadProvider=none`、少量 City 连接、生成中立即退出。
- 成功标准：关服时无 `RW-Idle` / `RW-Gen` 在 DB close 后继续执行；无 `ClosedChannelException`；游戏能稳定退出。

## 风险

- 当前存档数据库是否已有逻辑页损坏尚未通过 H2 recovery 工具独立验证。即使修复关服顺序，已受损数据库也可能需要恢复或重建。
- RoadWeaver 本地源码目录不是 Git 仓库，无法用其提交历史确认 2.2.2 之前/之后是否已有上游修复；现场运行 jar 与日志均为 2.2.2-1.20.1。
