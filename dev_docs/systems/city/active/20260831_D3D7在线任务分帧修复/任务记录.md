# D3 D7 在线任务分帧修复

*需求入口*：用户要求修复新增需求案 `CityD3在线扫描不卡服-v0.1` 与 `CityD7区块加载不卡服-v0.1`；D3 必须保留，D7 不得一次性加载整座城市。

*修改内容*：

- D3 HTTP 与 workflow 不再把完整 D3 handler 包入服务器线程。API worker 承担采样、Patch 分析、PNG 渲染和 artifact 写入；只有维度解析及后续真实世界读写步骤短暂切回服务器线程。响应新增 `executionMode`、`serverThreadBlocked` 与 `durationMs`。
- D7 删除同步全城 `backfillMissingOwners` 路径。缺失 LandUse owner 以 exact active plan identity 进入服务器 tick 队列，使用 `getChunkFuture(..., FULL, true)` 异步请求区块；全局每 tick 最多消耗一个区块请求或一个完整 owner 事务，单 owner 仍保留预检、快照、写入、回滚与 ledger 原子边界。
- D7 进行中返回 `waiting_for_worldgen / CITY_LAND_USE_D7_BACKFILL_IN_PROGRESS`；`city_land_use_owner_completion.v0.2` 暴露 `status`、`maxOwnerActionsPerTick=1`、`synchronousChunkLoads=false` 与当前 owner。计划替换、停用、读取重置及服务器停止都会取消旧队列。
- 同步更新 City MCP、D3 review package、LandUse owner completion 契约、代码导览和测试入口。

*验证结果*：

- `compileJava compileTestJava` 通过。
- `CityPlanningEndpointHandlerTest`、`CityLandUseWorldgenRegistryTest`、`CityStructureTemplateMaterializationPlannerTest` 聚焦回归通过。
- Java 全量 `gradlew test --no-daemon --max-workers=1` 743/743 通过；MCP `npm test` 7/7 通过；`git diff --check` 通过（仅既有行尾提示）。
- D3 真实 RTF 存档 `RTF08052`：`city_plan_d3` 对独立小城测试包耗时 `1602.9417 ms`，wall time `1872 ms`，固定 `step=16`，生成 279 个 Patch；`rtf_heightmap_preview_inferred_climate`、`fastPath=true`、`executionMode=api_worker`、`serverThreadBlocked=false`。期间状态接口 16/16 次成功，最大延迟 75 ms。
- D3 Minecraft fallback 存档 `RTF0810`：一次 22.813 秒 fallback 扫描期间状态接口 111/111 次成功，最大延迟 70 ms，证明慢路径同样不再阻塞在线 tick。该存档虽然安装 RTF，但当前地形路由没有 RTF GeneratorContext；按真实世界数据回退是正确行为，不能套用无关 RTF 预设。

*剩余问题*：D7 代码与自动回归已完成，但真实存档验收需要一个当前契约、已激活且不与用户大型城市冲突的独立城市计划。按用户决定暂不强行激活旧测试城市，记录为“已开发完成、未验收”。
