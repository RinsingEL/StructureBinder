# City 首次生成性能优化

*需求入口*：用户要求以普通玩家设备标准优化首次进入城市时的严重卡顿，保持既有规划与已生成城市幂等，并在开发运行环境真实游玩验证。

*根因*：JFR 的 30 秒关键区间共采到 1844 个 CPU 样本，其中 1264 个经过 `resolveStructureFoundationDatum`，约 1300 个落在 `generatorTerrainSample`。首次触发相邻建筑时，每座建筑会为周围 owner 重新构建微整地模型，并对大量坐标分别调用 `getBaseHeight` 与 `getBaseColumn`，反复执行 RTF/原版密度函数；模板解析、NBT 哈希和 JSON 写盘在采样中只占个位数，不是主因。

*修改内容*：

- 为规划结构建立按区块索引，为结构放置账本建立精确身份索引，移除区块生成热路径上的全量线性扫描。
- 缓存运行期 `StructureTemplate` 内容哈希；结构碎片与 feature 抑制观察改为一秒批量落盘，启动/激活和服务器关闭仍强制同步落盘，结构写入前的授权与 datum 冻结继续保持同步持久化。
- 复用相邻建筑的 prepared owner fragment、微整地平台模型和地形采样；采样缓存设 131072 点 LRU 上限，并在激活、卸载、重载时清空。
- RTF 世界优先使用既有的生成器原生二维 Heightmap 做无区块地形采样。每个 512×512 区域首次使用前，以建筑中心与四角共 5 个 `getBaseHeight` 控制点校准中位偏移；最大残差超过 2 格或接口/采样异常时，整个区域回退到原精确采样。水面使用 RTF preset 的缩放水位参与同一校准。
- 增加仅开发环境使用的存档自动加载后延迟 TP 参数，用于固定坐标复现实测；生产注册逻辑不变。

*验证结果*：

- `gradlew test` 全量通过，`git diff --check` 无空白错误。
- 同一份未加载目标区块的存档副本、同一坐标 `(-1584, 200, -3264)`、视距 16、同样触发 6 座建筑：原基线主线程停顿 28575 ms；只加共享缓存后为 19756 ms；启用 RTF 快速路径后为 2711 ms，较基线降低约 90.5%。
- 实测两个校准区域的中位偏移均为 0，最大残差分别为 0 与 1 格；六个 StructureStart 从首次注入到全部注入约 1.17 秒。
- 测试副本账本仍显示既有 35 个已完成结构，新增触发过程 `failures=0`；源验收存档未被修改。

*剩余问题*：目前只在本次 RTF preset 与目标城市附近两个校准区实测。非 RTF 世界以及校准不通过的 RTF 区域仍使用旧精确路径，正确性优先但不会获得同等加速；实际关服重进后的区块级幂等本轮未在游戏副本中完整走完，强制落盘与重载幂等由自动测试覆盖。
