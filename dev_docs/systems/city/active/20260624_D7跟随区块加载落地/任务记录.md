# 20260624 D7 跟随区块加载落地

## 背景

City D6-D7 最小闭环在 vanilla 存档中验证 `minecraft:village_plains` 时，直接 `/place structure` 曾失败并显示“该位置尚未被加载”。查 MC 1.20.1 源码后确认：`PlaceCommand.placeStructure` 会先生成 `StructureStart`，再用生成后的 bounding box 检查覆盖 chunk 是否已加载；只要任一 chunk 未 loaded 就失败。原版自然生成通过 `StructureStart` / `STRUCTURE_REFERENCES` / 每 chunk `placeInChunk` 分阶段推进，不要求玩家当前一次性加载整座结构。

用户确认 D7 长期设计应跟随玩家或预加载 mod 的 chunk 加载推进，而不是 D7 主动大范围预加载。

## 本轮改动

- `CityStructureD7Executor`
  - 新增可重入执行入口，可读取上一轮 `PlacedStructureMap` 作为真实 ledger。
  - 只有 `worldMutationApplied=true` 的记录可复用；dry-run 产物不会跳过真实执行。
  - fixed 结构缺 chunk 时写 `status=waiting` / `STRUCTURE_CHUNK_NOT_LOADED`，不触发 `failurePolicy`，不继续 variable。
  - variable 候选新增 `requiredPlacementBounds` / `requiredChunkRange`，由起点 footprint 和 `expectedAreaRange.maxAreaBlocks` 推导，并额外留 1 chunk 余量。
  - trace 新增 `waitingSummary`，区分 waiting 与 failure。
- `MinecraftStructurePlacementBackend`
  - 真实执行前只检查 `requiredLoadBounds` 覆盖 chunk 是否已 loaded。
  - 不再通过 `level.getChunk(...)` 主动预加载 footprint 周边。
  - 中文“尚未被加载 / 未被加载”也归类为 `STRUCTURE_CHUNK_NOT_LOADED`。
- `CityPlanningEndpointHandler`
  - 真实执行 D7 时读取既有 `placed_structure_map.json` 作为 ledger。
  - dry-run 不读取 ledger，避免预览产物污染真实执行。
- 测试
  - 新增 chunk 未加载等待测试。
  - 新增 dry-run 不污染真实 ledger、真实 ledger 可重入复用测试。
  - 将临时 `village_plains` fixture 的 `expectedAreaRange.maxAreaBlocks` 调大到大 jigsaw 级别。
- 文档仓库
  - D7 方案、起点候选案、数据契约、测试入口、临时真实结构配置同步 chunk-driven scheduler 口径。

## 风险与后续

- 首版仍通过 `/place structure` 等价入口真实放置 configured structure；它不是完整接入原版 `ChunkStatus` pipeline。
- variable 的 `requiredPlacementBounds` 是保守估算，依赖 TerraSense / debug catalog 的 `expectedAreaRange.maxAreaBlocks` 质量。后续正式 TerraSense `structure_assembly` 应提供更可靠的影响范围。
- 若未来要让 variable jigsaw 随 chunk 真正逐块增长，应单独实现持久化 `StructureStart` / piece 计划 / per-chunk ledger。
