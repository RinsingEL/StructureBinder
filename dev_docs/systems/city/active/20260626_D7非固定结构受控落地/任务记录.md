# D7 非固定结构受控落地任务记录

## 背景

用户验收要求 D7 的 `variable_area` 非固定结构不能只验证起点，后续 jigsaw 展开的 child piece 也必须遵循功能区、地形、占用和预算规则；真实落地前还要处理植被等软障碍，避免结构漂移或悬空到植物上。

## 本轮实现

- 硬化 `CityStructureD7Executor.ZoneInfo.covers`：候选 footprint 必须完整位于功能区 bounds 内，且覆盖到的规划 cell 都必须属于 buildable cells，不再通过 clamp 把越界坐标折回网格。
- 扩展 `CityConstraintField`：`validatePiece` 保留原 reasonCode，同时输出 `ruleResults[]`，可解释 allowed area、预算、buildable / reserved cell、runtime occupied 等规则。
- 扩展 `BoundedJigsawSolver`：加入可插拔 `PieceRuleEvaluator`；start / child piece 在 accept / reject 前都会写入 `ruleDecision` 和 `ruleResults[]`，runtime evaluator 失败时 piece 不进入 accepted plan。
- 新增 `CityTerrainProbe`：以 height / fluid / support 样本判定 piece 级地形合法性，稳定输出 `JIGSAW_RULE_TERRAIN_TOO_UNEVEN`、`JIGSAW_RULE_FLUID_OVERLAP`、`JIGSAW_RULE_TERRAIN_SUPPORT_TOO_LOW`、`JIGSAW_RULE_CHUNK_WAITING`。
- 扩展 `MinecraftStructurePlacementBackend` bounded jigsaw 后端：solver 运行时对每个 piece footprint 做 MC heightmap / fluid / support 探针；chunk 不足时 job waiting；true-run paste accepted piece 前清理 footprint 上方软植被 / 可替换方块，并写 `clearedVegetationBlocks`。
- 同步文档仓库契约、代码导览和测试入口，明确 `ruleDecision`、`ruleResults[]`、`terrainProbeSummary` 和植被清理验收口径。

## 风险与后续

- 当前地形策略是硬拒绝高差 / 水体 / 支撑不足，并在 paste 前清软障碍；台基、地形过渡、嵌入地面仍未实现，只在文档中保留为后续增强项。
- D7 start candidate 评分尚未直接纳入 terrain probe；真实验收中可以看到 terrain 失败候选会被后置拦截，后续可把 terrain 预评估加入起点排序，减少无效重试。
- `/place structure` fallback 仍只能证明起点受控；用户要求的“子结构也受控”必须使用 `materializationMode=bounded_jigsaw` 验收。
