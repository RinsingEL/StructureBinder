# 建筑驱动土地使用区域任务记录

## 任务边界

- 在 D4 建筑、阵列和组合关系确定后，为 group 或未分组单建筑生成 block 级 LandUseArea。
- 补齐 D3 LandUse 粗格地形事实和 D4 结构化 group / provenance 真值。
- 以配置规则派生用途、面积、成本和执行策略，允许 AI / 人工只覆写 group 与规则引用，不接受裸算法参数。
- 在 D6 锁定实际 footprint 后定稿 LandUse，随后接入 DecorationProgram、D5 精确植被策略和 owner-chunk worldgen。
- 已到 FEATURES 的旧 chunk 不回填；道路可后写覆盖 LandUse，LandUse 不猜测 RoadWeaver 最终路线。

## 开发前设计检查单

- 本阶段真正要解的问题：建筑或显式组合取得可解释、可复现的 block 级土地使用范围，并让适合的范围驱动 block 级地表、边界、植被与装饰执行。
- 输入：D3 LandUse terrain field、D4 v0.2 anchor/group provenance、D5 预案、D6 locked actual footprint、LandUse 规则 profile 和可选 intent override。
- 输出：seed group plan、LandUseAreaPlan、执行计划、claim trace、preview、quality、active registry 与 worldgen ledger。
- 不做：不恢复旧 FunctionZone 主线；不主动加载或回填旧 chunk；不猜 RoadWeaver 最终路线；不把全部区域直接复制为 noVegetationMask；不实现鱼塘体积挖掘。
- 成功标准：group / 单建筑扩张、同类融合、异类竞争、自然空地、跨 chunk 幂等落地、Decoration target、道路后写优先和固定输入确定性均有自动测试与可视产物。
- 失败回退：配置默认关闭；`confirmWorldMutation=false` 不激活；激活前可删除或重算 artifact；激活后可停止未来 chunk，但已生成世界不自动回滚，真实验收使用备份的新存档。
- 代码路径：独立 `domain/landuse`、`algorithm/landuse`、`application/landuse` 与 infrastructure worldgen 边界；HTTP/MCP 仅编排。
- 需要用户评估：LandUse preview 的区域形态、真实地表与边界效果、道路穿越后的视觉合理性。

## 多智能体分工

- 核心规划 agent：D3/D4 真值、LandUse domain/algorithm/application 与纯 JVM 测试。
- worldgen agent：owner-chunk compiler/executor/registry/ledger 与纯边界测试，不改中央 mixin/handler。
- 接口文档 agent：MCP schema/handler 与文档仓库产品、契约、导览、测试入口。
- 主 agent：中央 HTTP/controller/server、workflow、Decoration/D5/D6、mixin/Mod 生命周期、冲突归并、全量验证与提交。

## 实际完成

- D3 新增 `city_land_use_terrain_field.v0.1`，保存每个规划粗格的高度、坡度、局部高差、粗糙度、水体、群系、patch 与采样状态；D3 重算会撤销旧 LandUse / Decoration completion。
- D4 anchor plan / map 升级到 v0.2，普通结构、模板、key candidate、array、composite、staged merge 均保留 `placementGroupId` 与结构化 provenance；D6 通过 deep-copy 保留这些字段，并以 locked actual footprint 为 LandUse 权威。
- 新增严格 LandUse intent、内置规则 profile、确定性语义匹配、多源行动力竞争、同类连通融合、D5 gate corridor / 模板入口 / array gateway 排除、scanline / boundary / gate 编译、plan hash、quality 与 preview。
- `unclaimedSpans` 使用逐行补集，不为整个城市范围创建 block 对象；未达最小面积写 quality warning，不伪装为成功范围。
- 新增 `POST /realm/city/plan_land_use`、MCP `city_plan_land_use` 和 workflow `enableLandUseLayer`；settings 默认关闭，显式独立调用不受该开关阻止。
- DecorationProgram 新增 `targetArea.sourceType=land_use_area`，只消费同时具有合法 completion 的 area plan，并避让结构、入口 corridor 与 gate。
- `city_execute_d5` 校验 LandUse plan / completion / rule profile / D6 hash，激活前只读证明所有 owner 尚未到 FEATURES；显式关闭时注销旧 active plan。LandUse 几何不复制进中央全域植被 mask。
- worldgen owner 顺序为 planned structure 注入 -> LandUse surface / boundary -> Decoration -> vanilla / RoadWeaver 后写；LandUse 只替换自然表面，只对 vegetation-like configured feature 执行 CLEAR 抑制。
- active registry 按 dimension + city 持久化 plan / material palette hash，ledger 按 plan + palette + owner chunk 幂等；已到 FEATURES 或状态未知的旧 chunk 整体拒绝，不加载、不生成、不回填。
- bundled `config/geomantia/city_land_use/settings.json` 仅在目录缺失时安装，不覆盖已有目录。

- 本轮没有启动 Minecraft 新存档做跨 chunk 视觉验收，尚未观察真实群系地表、边界高度、结构先后、Decoration 密度和 RoadWeaver 后写覆盖的最终画面。

- active plan 停用只影响未来首次 FEATURES owner；已经生成的 LandUse block 不自动回滚，实机验收必须使用可恢复的新存档备份。
