# City 通用装饰阵列系统 v0.2 任务记录

## 任务定位

- 类型：City 双仓库联动、契约与实现重构。
- 目标：将写死的七类装饰算法替换为通用 `DecorationProgram`，并支持从 `config/geomantia/city_decoration/` 加载索引化 NBT 装饰素材。
- 真值：文档仓库 `docs/systems/city/10_product/案子/City通用装饰阵列系统-v0.2/README.md` 及本轮同步的数据 / MCP 契约。

## 已确认设计

- 核心模型：`TargetArea + CoordinateFrame + Shape + Pattern + ContentPalette + TerrainPolicy + ConflictPolicy + Seed`。
- AI 只提交目标、形状、排列、内容引用和策略，不提交具体 block 坐标。
- 规划阶段固定全局程序；worldgen 按真实 block 地形分 chunk 编译。
- 所有 chunk 共用全局原点、方向和稳定种子；禁止按 chunk 独立随机。
- `config/geomantia/city_decoration/content_index.json` 与 `templates/*.nbt` 是装饰 prefab 素材源。
- `styles/<styleProfileId>.json` 是语义键到已有 prefab 变体的映射；AI 填 `market_stall` 等语义键，规划后 compiled plan 才写 concrete content ref。
- 规划 / 激活时冻结 `catalogHash` 与 `styleProfileHash`；worldgen 不逐 chunk 重读配置，任一 hash 漂移都必须重新规划。
- 多方块 prefab 使用统一地面基准；首期禁止携带实体的 NBT。
- v0.1 七类业务 schema 破坏性退场，不做隐式兼容或默认 fallback。

## Multi-agent 分工

- 契约 agent：更新文档仓库方案、数据契约、MCP 契约、代码导览与测试入口。
- 核心 agent：实现纯 Java `DecorationProgram`、Shape / Pattern 原语和确定性测试。
- 内容索引 agent：实现 config NBT catalog、hash、路径 / NBT 校验和测试。
- 主 agent：设计主管、过程记录、HTTP/MCP/worldgen 集成、冲突审查与最终回归。

## 剩余风险

- worldgen 当前由 `ConfiguredFeature.place` 触发；完全没有 configured feature 的 chunk 可能不执行装饰，需后续增加稳定 chunk-stage hook。
- 多方块 prefab 跨 chunk 时首期明确跳过，不会拆件放置。
- 注销或替换 active plan 只影响后续 worldgen，不自动清理已经放入世界的旧装饰方块。
- D5 已在 RoadWeaver 注册前完成全部本地方案 / catalog / completion / build plan 预检；但第三方 RoadWeaver API 不提供跨调用事务或撤销，中途外部调用失败时无法自动回滚已注册端点。
- 已在默认世界的未加载目标区块完成真实 config NBT 的 worldgen 回归；人工观感验收仍由游玩测试继续覆盖。

## 验证记录

### 2026-07-13 阵列相位与跨 chunk owner 修复

- 超平坦实测复盘确认两项独立缺陷：`cross_section_repeat` 从 compiled coordinateFrame 原点起相，局部 `u=120` 的农田带被前移；worldgen registry 逐 chunk 即时写入，第四个 owner chunk 未就绪时前三块已落地并写入 ledger。
- `DecorationPatternSupport` 增加 Shape 局部 phase 起点；`cross_section_repeat`、`parallel_rows`、`grid_repeat` 的 offset 都从 Shape 对应轴的起始边界计相位。
- 默认世界的未加载区块实测否决了“整组写入”方案：单个 `WorldGenRegion` 回调写其他 owner 时持续记录 `Detected setBlock in a far chunk`；退出时服务端主线程仍在 `ForceLoadCommand.changeForceLoad -> ServerChunkCache.getChunk` 等待该批生成，worker 持续执行装饰投影。
- `CityDecorationWorldgenRegistry` 最终改为当前 owner-local 编译 / 预检 / 落地：禁止跨 `WorldGenRegion` 写入；READY fragment 在当前 feature 继续前即登记 vegetation suppression；不可写 fragment 不写 ledger、只延后自身，其他 owner 在各自回调按相同 program / seed / frame 独立补齐。
- 新增 `crossSectionRepeatStartsAtShapeMinimumInsteadOfCoordinateFrameOrigin` 与 `writesOnlyTriggeredOwnerChunkAndDefersItsUnavailableFragment`；定向 decoration Java 测试通过。实机须使用新 client 和未生成目标区块复测，旧进程已于本次故障后强制结束。
- 第二次默认世界实测确认 owner-local 不再写远区块，但暴露 ledger 独立故障：一个 owner 的大量 tile fragment 每成功一次都重写完整 JSON，Windows 对固定临时文件替换报 `AccessDeniedException`，`CITY_DECORATION_LEDGER_WRITE_FAILED` 被冒泡为 worldgen `Feature placement`。
- ledger 改为 owner 回调末尾一次批量 flush；成功方块先登记内存幂等账本，唯一同目录临时文件替换失败时标记 pending、限频日志并在后续 callback / snapshot 重试，绝不炸掉 worldgen。并发 ledger 读写统一受 registry 锁保护。
- 新增批量一次写、写失败后内存幂等且恢复后落盘、双 owner 并发完整落盘的回归用例；`CityDecorationWorldgenRegistryTest` 强制重跑 11 项通过。残余边界：进程在 pending ledger 写盘成功前崩溃时，下次启动可能重放已放入世界的 fragment；未来需用 chunk 级持久化标记消除该跨资源事务窗口。
