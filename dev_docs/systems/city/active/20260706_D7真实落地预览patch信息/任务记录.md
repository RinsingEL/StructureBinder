# D7 真实落地预览叠加 patch 信息任务记录

## 背景

用户希望结构真实落地后的 `placed_structure_preview.png` 能带上 D3 patch 信息，方便判断真实落地结构和地貌 patch 的关系。

用户同时询问 Plan 阶段 patch 是否缺少温度、群系信息，并明确要求该问题只查不改。

## 读取入口

- 文档仓库导航：`docs/README.md`、`docs/00_nav/repo_map.md`、`docs/00_nav/function_map.md`、`docs/00_nav/AI语义检索规则.md`
- City 真值：`docs/systems/city/README.md`
- City 契约：`docs/systems/city/20_contracts/数据契约/结构落地交接契约.md`
- City 代码导览：`docs/systems/city/30_code_guide/代码导览.md`
- City 测试入口：`docs/systems/city/40_tests/测试入口.md`
- Bug 定位流程：`docs/00_nav/Bug修复流程.md`

## 实施内容

- `CityStructureLandingPreviewRenderer.renderD7(...)` 增加带 `CityLandformReviewPackage` 的重载，在 D7 `placed_structure_preview.png` 中叠加 D3 patch backdrop。
- `CityPlanningEndpointHandler.handleExecuteD7(...)` 在存在 D3 package 时读取并传给 renderer，同时在 artifacts 中输出 `sourceD3Package`。
- `CityPlanningEndpointHandlerTest.handlePlanD6AndExecuteD7_writeStructureArtifactsAndPreviews` 增加 PNG 像素检查，确认 D7 preview 含 patch 背景色。
- 文档仓库同步更新结构落地契约、代码导览和测试入口中的 D7 preview 验收口径。

## Plan patch 温度 / 群系调查

- GIS cell 层有 `biomeId`：`AtlasCell` / `AtlasRegionSnapshotIo.cellToJson` 会记录 cell biome。
- City D3 的 `LandformPatch` 当前字段不含 biome 或 temperature，仅有 `landformType`、范围、海拔、坡度、水距、touchesWater、confidence、flags 等。
- City D3 的 `LandformPatchSummary` / `city_landform_review_package.json.landformPatches[]` 当前也不含 biome 或 temperature，仅保留地貌类型、bbox/memberCells、metricsSummary、tags、facts、邻接 patch。
- Realm planning 侧另有 `biomeHist` / `dominantBiome` 聚合逻辑，但没有进入 City D3 patch 契约。
- 本轮按用户要求只查，不改该数据契约。

## 风险与边界

- D7 preview 读取 D3 package 是可选行为；缺 D3 package 的手工调试 artifact 仍可生成旧式预览，不因预览增强硬失败。
- 本轮没有修改 Plan 阶段 patch 的 biome / temperature 数据结构，也没有把 GIS cell biome 聚合到 City D3 patch。
- 当前两个仓库本来已有未提交改动，本轮只在相关实现、测试、文档上做增量修改，未回滚 RoadWeaver / 城墙 / D4 阵列等既有脏区。
