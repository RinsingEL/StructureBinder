# City D4 功能区实体化任务记录

## 目标与边界

- 实现 D4：`PatchGroupPlan` -> 引用 / 功能类型校验 -> `FunctionZonePatch[]`、`FunctionZoneMap`、`FunctionZoneTerrainStats`。
- `PatchGroupPlan` 由 MCP 调用方侧 AI / Codex 看 `landform_review_map.png` 后生成并提交；Java 运行时不内置 LLM。
- 本轮不实现 D5 道路 / 边界，不实现 D6 结构池，不放置真实方块或 jigsaw。

## 关键决策

- D3 增补落盘 `city_landform_review_package.json`，D4 读取该包，不重新跑 GIS。
- D3 从 `AtlasRegion.cells()` 收集 GIS patch 成员 cell，`landform_review_map.png` 和 D4 preview 优先渲染真实成员格子；只有缺少 `memberCells` 时才显式降级到 envelope。
- `splitRequested` 只记录 warning，不实际裁剪 patch。
- 未知 `functionType`、不存在 patch 引用 hard block；D4 不要求 AI 回填 GIS tag / metric evidence。

## 重要修改

- 新增 D4 domain model：`PatchGroupPlan`、`FunctionZonePatch`、`FunctionZoneMap`、`FunctionZoneTerrainStats`、`CityQualityReport`、`CityFunctionType`。
- 新增 `PatchMemberCell`，并扩展 `LandformPatchSummary` / D3 JSON 输出 `blockBounds`、`geometryMode`、`memberCells`。
- 新增 `CityFunctionZoneBuilder` 负责草案校验、实体化和 stats 聚合。
- 新增 `FunctionZonePreviewRenderer` 输出 `function_zone_preview.png`。
- 新增 HTTP `/realm/city/plan_d4` 和 MCP `city_plan_d4`。
- 同步 City 契约、代码导览、测试入口和 v0.1 开发计划。

## 风险

- 单元测试中的纯 `LandformPatch` 构造仍会走 envelope fallback；真实运行路径应从 `AtlasRegion` 提供 `memberCells`。
- `新的世界` 存档真实启动需要加载 ReTerraForged；本轮已把 `geomantiaDevUseReTerraForged=true` 写入 `gradle.properties`，后续默认 `runClient` 会带上本地 RTF 运行依赖。
- D4 首版不校验结构 catalog，`mainBuildingRole` 只作为下游输入记录。
