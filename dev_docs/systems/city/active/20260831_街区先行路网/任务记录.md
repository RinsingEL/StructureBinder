# 街区先行路网

*需求入口*：用户要求保持现有台地实现不变，开发《City城市基面与路网形态-v0.1》中尚未实现的街区先行路网，并完成真实游玩测试。

*修改内容*：保持既有台地实现不变。D4 改为 required/core 建筑先落位，随后预留共享主路与按阵列语法生成的区内街道骨架，fill/connectivity/percentage 建筑避让该骨架落位；全部建筑提交后按真实入口和路口使用裁撤无用段，并以短巷或同功能区确定性绕障共享支路补接，冻结唯一 `streetBands[]`。主路对显式交通 `CONNECTION` 优先复用已有共享路段，空间关系不自动造路。新增 `streetFirstNetworkTrace`、主路复用 trace 与 `compilationAcceptance.allStreetEntrancesConnected`。修复真实 D4 暴露的短巷横断面压楼及固定 COMPACT 骨架无法覆盖远端入口问题；更新自动测试、产品案、数据契约、代码导览、测试入口和故障索引。

*验证结果*：街区聚焦回归通过；全量 `gradlew test --max-workers=1` 736 项通过。真实 `runClient` 对 `realm_w_mte38ltl_f1964c5a / city_realm_stone_march_1_capital` 最终 D4 复编为 8 anchors、3 段预留骨架、2 段共享绕障扩展、7 段短巷，8/8 入口接入，road/body overlap 0，视觉与 compilation acceptance 均通过且 warnings 为空；局部预览确认 T 形共享骨架组织建筑、各入口支路接入。继续 workflow 时 D5 规划成功，D6 因该城市 owner chunks 已在旧游玩中生成而返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，未执行 activation、传送或 D7，符合新区块保护规则。补测 `city_realm_green_court_2_capital` 大型三功能区城市时，先补齐已验收旧 schema 产物的只读兼容（原始哈希仍严格核对，归一化仅作用于内存副本；测试清单正常写回时升级 schema），回归通过；真实 D4 最终明确失败：34 anchors 中农业 29、市场 5、行政 0，农业 29 个入口均未接入，主路起点与风车主体重叠，`compilationAcceptance.passed=false`，因此未进入 D5/D6。

*剩余问题*：绿廷大城市暴露了规模化失败：行政功能区为空、农业 GRID 被判定为 `LANDSCAPE_GAPS` 后缺少区内道路、显式农业→市场主路的 source transition 与风车重叠；这三项必须修复后重测。MCP 返回还包含非标准 JSON 数值 `Infinity`，当前调用侧只能临时转为 `null` 后读取指标。当前 run 的三座首都均已生成或完成激活，没有可用于本次新 D4 的干净 CitySeed；新区块 worldgen/D7 现场验收需另建测试城市或新存档后继续。台地成立条件与可达性按用户要求不在本任务修改。
