# 多城市模板 Registry 共存

*需求入口*：用户 2026-09-03 要求修复九城自动推进后旧城 Stubbs 建筑计划被后续城市 D5 覆盖的问题；故障 `CITY-TW-20260903-01`。

*修改内容*：

- `CityReservationMaskRegistry` 的单个 active mask / template registry 改为按 `cityId` 保存的多城市集合；D5 同城新 revision 只替换本城，不同城市共存，server-root 文件使用集合外壳原子写入。
- 旧的单城市 mask / template registry 文件在 load 时提升为单项集合；每城 D5 artifact 仍输出原单城 registry，不把 server-root 聚合格式泄漏成 Stubbs、Trek 或其他模板来源的特殊契约。
- worldgen 结构与 mask 查询遍历全部城市；模板 piece 在既有 `anchorId + templateRef + templateHash` 外增加冻结 `anchorBlock` 匹配，避免多城复用同名 anchor 时取错计划；失败 ledger 补齐 run / city identity。
- workflow 的 D5 skip 除 artifact provenance 外，新增 runtime 多城市 registry 存在性校验；旧 artifact 尚在但当前城市已被覆盖时会重新执行激活。
- 同步模板 active registry 数据契约与代码导览，明确 server-root 集合、同城替换、多城共存和旧单城迁移口径；不存在 Stubbs 或 Trek profile 特判。

*验证结果*：`CityReservationMaskRegistryTemplateFragmentTest` 10 项与 `CityPlanningEndpointHandlerTest` 48 项全部通过，覆盖两城共存、同城 revision 替换、重启恢复、旧单城文件迁移、同名模板按锚点区分及 workflow runtime 激活检查。全量 689 项中 688 项通过；唯一失败为未修改的 `CityLandscapeCapacityReservationPlannerTest.reusesInvariantCandidatesDuringMultiLandscapeJointSearch` 在游戏进程并行运行时超过 8 秒门槛（8.828 秒），单独复跑仍为计时超限，未改测试或 Landscape 实现。

*剩余问题*：当前游戏进程仍加载旧代码，且 Green Court 目标区块已在建筑计划缺失时生成；修复不会对已生成区块执行 late paste。重启后需对未生成城市重新执行/续跑 D5，使旧单城存档逐城恢复为集合，再用未生成 owner 实机复验多城模板 ledger。
