# 玩家多模态 Provider 服务

*需求入口*：`docs/systems/city/10_product/案子/跨模块/玩家多模态Provider服务-v0.1/README.md`。

*本轮范围*：完成发布版 Provider 配置、能力验收，并把同一 Provider Runner 接入既有 W/T/City 决策位。普通玩家默认 DeepSeek；开发者保留自定义 OpenAI-compatible Base URL、模型和超时。接入层不修改既有阶段顺序、T4 完成条件、City 队列建立条件或排序配置。

*修改内容*：

- 冒险者地图新增 `Provider 设置` 入口；GUI 提供 DeepSeek/自定义切换、隐藏 API Key 输入、启停、保存、清除和“保存并测试多模态”。
- DeepSeek 预设固定官方 Base URL，并自动选择 `deepseek-v4-flash-vision-exp`，普通用户不填写模型 ID。
- 公共配置写入 `config/geomantia/provider.json`；Key 单独写入 `provider-secret.txt`，不进入世界、规划 artifact、公共配置、客户端回包或日志。若无已保存 Key，可读取 `GEOMANTIA_PROVIDER_API_KEY` / `DEEPSEEK_API_KEY` 环境变量。
- 独立服务器只有权限等级 2 的管理员可修改或测试，配置快照只返回 `hasApiKey` 和来源，不返回 Key。
- 连接测试先调用 `/models` 检查模型可用，再向 `/responses` 发送一张 16×16 内置 PNG 做真实图像输入探针；明确区分多模态可用、仅文本可达、缺 Key、模型不存在和 HTTP 错误。
- `MultimodalProviderClient` 与 `PlayerProviderService.analyzeImage` 提供后台图片 + 提示词调用入口，限制图片/提示词大小并只返回正文或稳定错误码；具体阶段适配仍负责提示词与严格结果 schema。
- 自定义远程地址强制 HTTPS；仅 `localhost` / loopback 允许 HTTP，便于本地开发网关。
- 新增 `PlayerProviderAgentRunner`：服务启动后只消费持久队列的 `waiting_for_agent`、`waiting_for_patch_review`、`needs_agent`，通过 DeepSeek Responses API 的函数调用直接调用与 MCP 相同的 City 工具；MCP Node 入口不变，可继续人工接管。
- Provider 工具网关锁定当前 run / 当前城市，自动注入托管 TerraSense、template catalog 与 Blueprint reference catalog；模型不能选择本地路径。HTTP 层原有队列顺序、旧状态、Patch Review 和失败预算继续作为最终门禁。
- Patch / D3 工具响应中的 PNG 会以 `function_call_output` 图像内容回传视觉模型；无新状态时同一语义任务不会反复付费调用，接口错误按退避重试。
- Runner 按当前服务端世界 seed 只选择该世界最新规划 run；最新 run 已完成时不回退消费同世界更早的遗留未完成队列，避免切档后误推进历史测试包。
- DeepSeek 首轮工具选择显式关闭 thinking 以支持 `tool_choice=required`，进入有工具结果的设计轮后恢复 high reasoning；Provider GUI 增加自动接管状态和当前工具。
- `ProviderPlanningDiscovery` 只读取当前世界最新 run 的正式 checkpoint，恢复到既有的 W、T1、逐国 T2、统一 T3、逐国 T4 或 City 队列决策位；没有当前世界 run 时使用稳定 runId 启动既有 W 入口。
- W/T 接入直接调用与 MCP 相同的 HTTP 工具：W refresh、T1 prepare、T2 Patch Explorer/select、统一 T3、T4 Patch Explorer/planning/finalize 和 City queue refresh；run、realm、city 与 Patch/T4 session 均由宿主锁定，模型不能跨 scope。
- T1 恢复时只把精简世界概览与正式世界预览图交给多模态模型；其他阶段继续以工具响应及其 PNG 为证据，不向模型开放任意本地文件路径。
- Provider 恢复调度明确要求全部 RealmProfile 完成 T2 后才允许统一 T3，全部国度完成既有 T4 后才允许消费 City 队列；即使存在遗留的部分 City 队列也不得抢跑。

- `ProviderConnectionTesterTest`：模型列表、真实 `input_image` 请求、仅文本接口区分、缺 Key 拒绝和可调用客户端正文解析。
- `DeepSeekToolLoopClientTest`、`ProviderPlanningToolGatewayTest`、`ProviderRunDiscoveryTest`、`ProviderPlanningDiscoveryTest`：覆盖无状态函数回环、当前 run/realm/city 防串线、托管目录注入、PNG 回传、当前世界恢复、统一 T3 门禁、全部 T4 前禁止 City 抢跑和完成队列忽略。

*真实连通验证*：2026-09-02 使用本机 `DEEPSEEK_API_KEY`，官方 `GET https://api.deepseek.com/models` 返回 200，包含 `deepseek-v4-flash-vision-exp`；随后 `POST /responses` 的 16×16 PNG 图像探针返回 200。函数调用探针取得 `function_call`、合法 JSON arguments，并在回传 `function_call_output` 后取得完成消息；同时确认视觉模型默认 thinking 下不接受 `tool_choice=required`，实现已按官方协议分轮设置 reasoning。2026-09-03 再以新增 `realm_t3_expand` schema 做真实函数调用探针，返回 completed/function_call 与合法 `runId,qualityMode` 参数；实际运行仍由宿主覆盖并锁定正式 runId。验证过程没有输出或写入 Key。

*剩余问题*：完整 CityBlueprint 仍以服务端正式校验和最多 5 次编译失败预算收敛，后续应把 MCP 的完整 Blueprint 参数 schema 生成进发布资源，减少首版模型依赖校验反馈修正的成本。还需真实客户端验收 GUI、配置重启恢复，以及在一个全新世界上实跑 W/T/City 全链和至少一座城市到 `waiting_for_generation`。
