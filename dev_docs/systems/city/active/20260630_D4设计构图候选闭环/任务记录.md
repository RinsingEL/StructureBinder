# City D4 设计构图候选闭环任务记录

## 本轮目标

- 在现有 D3-D7 结构落地主链前增加 D4 候选闭环。
- AI / 人提交 `DesignSlotPlan` 后，程序基于 D3 patch、TerraSense profile、envelope facts 生成少量候选点。
- 人 / AI 选择候选后转成标准 `StructureAnchorPlan`，继续复用现有 D4-D7 worldgen-time 落地、D6 锁形态、D7 actual footprint 道路。

## 主要实现

- 新增 `CityStructureAnchorCandidatePlanner`：
  - 支持 `city_d4_design_slot_plan.v0.1`、`city_d4_anchor_candidate_set.v0.1`、`city_d4_anchor_selection_plan.v0.1`。
  - 候选来自引用 patch 的代表点、关系目标方向点、compact / practical / dramatic 点。
  - 候选先做城市范围、patch 引用、profile / envelope facts、估算 envelope 防撞过滤。
  - `slotId` / `displayRole` 只作为本轮设计槽位，不作为 City 全局枚举。
  - 支持单结构 `structureId` 和多备选 `structureIds[]`。
  - `candidateId` 按 `slotId + candidateKind + 序号` 生成，保证同一 slot 内稳定唯一。
- 新增 HTTP / MCP：
  - `POST /realm/city/plan_d4_candidates`
  - `POST /realm/city/select_d4_candidates`
  - MCP tool 同步新增 `city_plan_d4_candidates`、`city_select_d4_candidates`。
- 新增预览：
  - `anchor_candidate_preview.png` 展示 D3 patch、已选/候选 envelope、候选 label 和评分摘要。
- 单测覆盖：
  - 候选生成、单 `structureId` slot、旧 function payload hard fail。
  - 候选选择转标准 D4。
  - endpoint 产物写出和 selection 进入现有 D4。

## 风险与后续

- 当前候选 planner 仍是轻量启发式，不做全局最优布局。
- `targetSlotId` 只作软提示，真正按已选 anchor 的关系评分仍依赖 placement order。
- D7 道路是现有 WorldEdit 后处理，虽然已基于 actual footprint 避障，但路线审美和复杂绕行仍是后续 Road Weaver / 道路系统议题。
- 对于高差 / 地形融合，本轮未处理，仍留给后续结构地形兼容阶段。
