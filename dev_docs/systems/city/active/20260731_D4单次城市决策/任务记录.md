# D4 单次城市决策与程序化编译联动任务记录

## 目标与边界

- 实现案子 01 的 `CityBlueprintContext`、`CityBlueprint v0.3`、服务端校验、HTTP/MCP 入口与 artifact。
- 程序准备上下文不计入 AI 城市设计调用；同一冻结 context 只消费一次完整 Blueprint 提交。
- 串行完成案子 01 -> 02：Blueprint 被接受后由程序自动生成标准 D4 anchor，并继续交给现有 D5/D6。
- 旧 D4 candidate/session/manual anchor 路由只作为显式 legacy/debug 保留，不再是 workflow 默认。

## 关键决策

- `CityBlueprint` 不允许任何 block 坐标、旋转、候选 ID、直接 template ID 或自由算法名。
- Blueprint 只引用程序冻结的 D3 artifact 和 catalog snapshot；两者都使用 `path + schemaVersion + sha256` 身份。
- `requiredStructureRefs`、fill pool、algorithm、composition、style、road、surface 全部来自版本化 reference catalog。
- v0.3 只支持 `STRUCTURE`；`LANDSCAPE` 与非空 `attachedFeatures` 明确失败。
- Group 的产品语义是连通功能区：AI 提交 `preferredPatchRefs[] + preferredPatchZone + extentClass + densityClass`，不提交建筑数量；多个 Group 可共享 patch。
- `compositionProfileRef` 只控制模板组成顺序，不得携带数量上限。实际建筑数由空间预算、密度和模板 collision footprint 推导。
- 校验失败只更新报告与 trace，不覆盖最后一次有效 `city_blueprint.json`。
- 当前 D3 v0.1/v0.2 可作为开发输入；partial D3、未完成/过期的首都选址审查会在 prepare 阶段阻断。D3 v2 正式生产验收仍由案子 00 阻塞。

## 当前修改

- 新增 Blueprint 强类型领域对象、严格 codec、reference catalog 和 validator。
- 新增 `CityBlueprintService`，负责冻结上下文、目录快照、单次提交预算、原子 artifact 写入和 stale 校验。
- 主审补充每个 `contextId` 的原子 submission claim，阻止并发 HTTP 请求同时消费并接受同一提交预算；非消费型拒绝不覆盖既有校验报告与 trace。
- 主审补充 Relation 的 `distancePreference=NONE|NEAR|FAR`，使案子 02 能区分远近关系，不必重新解释自由文本。
- 新增 HTTP/MCP `prepare_d4_blueprint_context` / `submit_d4_blueprint`。
- 新增 valid/invalid golden fixture 与 codec/service 测试。
- 同步文档仓库的数据契约、接口、代码导览、测试入口和影响面。

## 案子 02 当前修改

- 新增 `CityBlueprintCompilerService`，编译入口重新验证 context identity、accepted validation/submission trace、Blueprint hash、D3/catalog ArtifactRef 与 schema。
- 全部 Group 先按 HIERARCHY `from -> to` 稳定拓扑排序、同层按 priority/groupId 排序；层级循环 hard fail。随后先完成所有 `requiredStructureRefs`，再按 fill pool、composition profile 与 algorithm profile 扩张。
- 复用 `CityStructureArrayCandidatePlanner` 的固定模板 geometry、D3 member-cell legal region、collision/occupied 和评分；每次只提交一个结构，支持模板 variant 回退和容量软缩。
- fill 失败的 structure ref 会进入本 Group 的 blocked 集合并从后续轮次排除；全部 pool 无连通合法空间时以 `CONNECTED_SPACE_EXHAUSTED` 软停，不会重复尝试形成死循环。
- 候选自动记录过滤原因、基础分、关系分、连通分、connection gap、稳定 seed tie key 和提交 envelope；HARD 关系参与过滤并在必要结构阶段后复验。
- `extentClass` 冻结 4096/16384/36864 blocks² 空间预算与 96/160/240 blocks 最大跨度；`densityClass` 冻结 0.22/0.38/0.55 覆盖率与 48/32/20 blocks 组内 gap。
- 每个 Group 先按 `preferredPatchZone` 在偏好 patch 精确成员格内独立扎根；required 不朝其他 Group 偏移。随后关系图 connectivity growth 从最近的本组实际结构中心推进，不设固定组间距离上限。输出 `city_generation_compile_trace.v0.5`、`group_extent_map.v0.5`、标准 anchor 和现有预览。
- 真实联调发现 D3 patch 的 `memberCells[]` 会包含 `review.grid` 外的扫描 padding；编译器现已把前沿种子和 legal region 都裁到正式规划网格，避免选中 padding 后被下游以 `POINT_OUTSIDE_PATCH` 拒绝。
- 真实联调发现复用的阵列候选器会从 patch center 重新排序，丢失编译器已选的连续前沿；现由编译器注入程序内部 `candidateOrigin`，候选器从该精确 member cell 起步。该坐标不进入 Blueprint 或 AI 输入。
- 新增 HTTP/MCP `city_compile_d4_blueprint`；`city_run_workflow` 默认 `blueprint`，缺输入返回 `awaiting_city_blueprint + nextAction`。旧 mode 只有显式传入才执行。
- 正式 Blueprint workflow 只有在 D5/D6 artifact 的 `sourceStructureAnchorMap` 与当前 D4 map 完全一致时才允许 `skipExisting`；显式 legacy/debug mode 保持原跳过语义。
- v0.3 仍只支持 STRUCTURE，不实现 LANDSCAPE、道路、城墙、Foundation、地表细节或装饰退役；v0.1/v0.2 Blueprint 不静默迁移。

## 案子 02 持续阵列修正（2026-08-01）

- 现场预览确认旧编译器虽然保留 `algorithmProfileRef/arrayPattern`，却把每栋结构都包装为 `arrayCount=1`；阵列形态实际退化为单栋最近点排序，COMPACT 形成单轴方格队列。
- 新增 `CityBlueprintGroupLayoutPlanner`：每个 Group 建立一次持续 frame，按连续 `slotIndex` 生成 COMPACT、GRID、LINEAR、COURTYARD、ORGANIC_COMPACT 二维布局。required/fill 都消费同一状态，outward 只对原阵列槽位施加方向 bias。
- `densityClass` 不再通过统一 `collisionArea/coverage` 决定空间消耗。DENSE/BALANCED/SPARSE 基础 target gap 为 4/8/16、max gap 为 12/20/32、LandUse handoff gap 为 16/24/40；各算法再叠加 gap、jitter 与 claim multiplier。
- `CityStructureArrayCandidatePlanner` 支持程序内部 `candidateOrigins[]`；这些精确 block guides 保持原坐标，D3 member-cell 只作为合法 mask，不再把 guides 二次吸附回 16 格 cell center。无该字段的旧阵列路径保持原行为。
- compile trace 与 group extent 升级为 v0.3；每个选择/anchor 冻结 `blueprintLayout` provenance。`group_extent_map.v0.3` 使用 `ARRAY_OUTWARD_THEN_LAND_USE`，删除含糊的旧 `connected`，区分 `structureGraphConnected` 与固定 `landUseConnected=false/PENDING_LAND_USE_COMPILE`；64 格只保留为发现/可行性窗口。
- 连接端点和 gap 在全部 fill 完成后按最终 collision envelopes 重算，避免继续 outward 后仍输出首栋结构时期的旧 gap。

## v0.4 Group 连接生长修正（2026-08-01）

- 用户冻结新口径：同一城市的全部 Group 必须连接；D3 preview/grid 已限定城市最大范围，D4 不再使用固定 64 格作为后续 Group 首栋可行性门槛。
- 编译流程改为“全部 Group 在各自 preferred patch 完成 required 播种 -> 关系图 connectivity growth -> 普通 fill”。required 核心仍只在偏好 patch 内落地，初始距离只增加连接阶段需要消费的结构与空间。
- 连接图优先使用 `CONNECTION / ADJACENCY / HIERARCHY`；显式关系不足时按初始结构前沿距离与稳定 seed 生成 `FALLBACK / DETERMINISTIC_SHORTEST_COMPONENT_EDGE`，不删除 Group、不替换 AI 的偏好 patch 或功能关系。
- 每条边由双方交替消费各自持续阵列的连续 slot；outward 从当前结构前沿向对端推进并保留算法横向节奏，仍经过 template、D3 member-cell legal region、terrain policy、collision、occupied 与组内最大 gap，不存在直线桥或最近格旁路。
- connectivity growth 可认领 D3 `review.grid` 内 terrain-compatible patch；`extentClass` 的目标面积与 96/160/240 最大跨度在连接阶段视为软目标，D3 grid、collision、terrain、组内连续 gap 和每 Group 256 anchor 安全护栏仍为硬约束。
- compile trace / group extent 升级 v0.4，删除 `maxInterGroupGapBlocks`，增加 `connectivityPlan`、拓扑来源、初始/最终 gap、严格双方最小 handoff、连接结构数、连接空间需求、扩张距离、`extentExpandedForConnectivity`、`claimedPatchRefs` 与 D3 grid 边界策略。`landUseConnected=false/PENDING_LAND_USE_COMPILE` 保持不变。
- 无合法地形连续槽位时返回 `CITY_BLUEPRINT_CONNECTIVITY_NO_LEGAL_PATH`；当前按连接边稳定顺序贪心施工，没有复杂窄通道的全局回溯。
