# Trek 模板语义与旋转目录修复

*需求入口*：用户要求修正 Trek 可用模板的旋转授权、逐模板 style / 建筑语义，以及 AI Reference Catalog 中的 Style Profile 和候选池。

*修改内容*：新增 `tools/city_templates/curate_trek_v3_catalog.py` 及自动测试，以已审核 `StructureProfile.jsonl` 为语义真值，给 46 个 `trek_v3_sanitized_v1` 陆上独栋模板统一授权 Minecraft 四向旋转，并把折叠的 `trek_v3_building / trek_v3` 改成逐栋建筑语义与 5 类具体 Trek 风格。同步托管 `template_catalog.json`、`blueprint_reference_catalog.json`：现有 65 个模板均有四向旋转，7 个实际模板 style 均存在对应 Style Profile；Reference Catalog 从 3 个 Style Profile 扩为 9 个兼容/具体 profile，从 11 个池整理为 42 个非空的通用、功能、风格及风格×功能池，所有派生池只纳入 `planning_role.fill`。删除错误地把矿业 workshop 当 civic fill 的 `pool:civic`。托管重建脚本现保留新增的 4 个 fixed Trek profile，并在重建后自动运行目录整理器，防止回退。

*验证结果*：整理器首次写入报告 41 个旋转、46 个 style、46 个 building semantic 发生修正；第二次 dry-run 三项均为 0，证明幂等。65/65 模板均有四向旋转，65 个 structureRef 均命中 StructureProfile 与模板候选，全部实际 style 均命中 Style Profile，42 个 fill pool 均非空且无未知引用，派生池无 anchor 混入。`tools/city_templates` 26 项 Python 测试全过；`CityTemplateCatalogTest`、`CityBlueprintServiceTest`、`CityTemplateOrientationSolverTest` 聚焦 Gradle 回归通过；托管 PowerShell 重建脚本语法检查和 `git diff --check` 通过。

*剩余问题*：尚未以新 Reference Catalog 发起一次真实 AI D4 设计，因此本轮证明配置可读、可复现与几何能力正确，不宣告风格选择质量的真实 Agent Loop 验收。船只、水岸、地下和多-piece 模板不在本轮开放范围。
