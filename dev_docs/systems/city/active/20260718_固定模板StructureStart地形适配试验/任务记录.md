# 固定模板 StructureStart 地形适配试验

## 目标

让 Stubbs 风车、谷仓和肉铺在固定模板 identity 不变的前提下，于噪声生成前进入原版 `Beardifier`，验证坡地与水岸的地形兼容性。

## 实现范围

- 仅 `windmill_01`、`barn_windmill_01`、`small_butcher_shop_01` 命中 `CityTemplateTerrainStartPolicy`。
- 注册 `geomantia:city_template_terrain` 和持久化 `city_template_terrain_piece`；每个建筑 start 只包含一个固定模板 piece。
- anchor `createStructures` 通过 generator `MOTION_BLOCKING_NO_LEAVES` base height 冻结 datum，向所有 footprint owner 持久化 pending proof 后才写 start。
- piece 校验 template hash、raw size、rotation / mirror footprint 与 D6 locked footprint；原版分 chunk 调用 piece 后，继续使用既有 template fragment ledger。
- 命中试验的模板跳过 FEATURES direct-template 写入和延迟 direct retry，避免双重落地。
- Decoration content、冻结 terrain run、FEATURES 落地与 fill-only foundation 未修改。

## 验证

- `./gradlew.bat compileJava` 成功。
- 显式 Java 17 JShell 检查：风车 templateRef 命中策略，普通农舍不命中。
- `compileTestJava` 未再报告本轮新增测试错误；但被装饰 v0.4 正在进行的改造阻断，现存 13 个错误均为 legacy 常量或已移除 upgrade endpoint 的测试引用。

## 未完成与风险

- 尚未在未生成真实坡地完成风车、谷仓、肉铺三种模板的游玩验收；需检查 start 是否被结构引用流程带入所有 owner chunk、ledger 是否完整以及 `terrainAdaptation=beard_thin`。
- 当前 Decoration foundation 密度仍加到原版 Beardifier 结果上；建筑 beard 区与 decoration foundation 相交时可能过填，必须实机观察后再决定是否收缩或屏蔽重叠 segment。
- 若出现 datum 偏移、片段缺失、过填或持久化失败，只需从 `CityTemplateTerrainStartPolicy` 删除对应 templateRef，即可回退该模板到既有 direct-template 路径。

## 实机验收结果

- 2026-07-18 在未生成的 720000 区域完成三模板验收：barn、windmill、butcher 均写入 `TEMPLATE_TERRAIN_START_PIECE_PLACED`，分别完成 4/4、4/4、2/2 owner fragment。
- runtime ledger 的三项 datum policy 均为 `generator_base_height_motion_blocking_no_leaves`，D7 terrain adaptation 标记为 `beard_thin`；实际 XZ footprint 与 D6 locked footprint 一致，建筑外围 datum 与自然地表差为 0..1 block，无悬浮。
- Beardifier 观测诊断仍为 `CITY_TERRAIN_ADAPTATION_HOOK_UNAVAILABLE`，因此本轮只确认 StructureStart 与 beard_thin 策略路径，未宣称已观察到密度 hook 的实际贡献。
