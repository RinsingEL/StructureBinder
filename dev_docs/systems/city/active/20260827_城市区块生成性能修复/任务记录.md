# 城市区块生成性能修复

*需求入口*：用户现场复现：RTF0810 世界在 32 视距生成/加载城市后 JVM 高频年轻代 GC、服务端落后且整机卡顿；要求定位并修复，不做需求案检查。

*修改内容*：Decoration / LandUse worldgen 的成功幂等查询改为内存 O(1) 索引，Decoration outcome 查询同步索引化；区块生成线程不再序列化 ledger，改由服务端 tick 最多每秒持久化一次，停服和显式快照强制落盘，文件写入在 registry 锁外完成。Decoration 每个 active plan / owner chunk 只编译一次完整计划，再按 program 分组执行，删除原先逐 program 重复编译和全域 slot 重投影。

*验证结果*：`compileJava compileTestJava` 通过；Decoration registry、LandUse registry、Decoration compiler 聚焦测试通过；`gradlew test --no-daemon` 全量 747 项通过，0 failure / error / skipped；`git diff --check` 通过（仅既有 Windows 换行提示）。代码检查确认仓库没有 Region Ticket / forceChunk 创建路径，RoadWeaver 注册使用 `generateImmediately=false`，本次不改视距或第三方模组语义。

*剩余问题*：需在 RTF0810 新区块以原 32 视距现场复验 GC 频率、server tick 落后、ledger 写入频率与区块卸载；65×65 客户端渲染网格本身仍会占用大量 `LevelChunkSection` / `VertexBuffer`，本修复只消除 StructureBinder 的额外放大。
