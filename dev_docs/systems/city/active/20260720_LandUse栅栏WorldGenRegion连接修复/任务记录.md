# LandUse 栅栏 WorldGenRegion 连接修复

## 问题与证据

- 实机截图中 LandUse 农业边界连续栅栏只显示半边连接。
- 当前存档 `city_fresh_river_full_20260719` 的连续坐标 `(649959,78,652107)` 与 `(649959,78,652108)` 都是橡木栅栏，但前者保存为 `south=false`，后者为 `north=true`；服务端 BlockState 已经单向，不是客户端渲染问题。
- `CityLandUseChunkCompiler` 产出的 boundary points 连续且材质正确；问题位于 L3 执行层。
- 第一次修复在写当前格前调用 `Block.updateFromNeighbourShapes`，随后使用 `Block.UPDATE_ALL`。Minecraft 1.20.1 的 `WorldGenRegion#setBlock` 直接写 `ChunkAccess`，不消费 flags，也不通知既有邻居；按 z/x 稳定顺序落地时，后写栅栏能看见先写栅栏，先写栅栏永远看不见未来邻居。
- 原 Forge GameTest 传入 `helper.getLevel()`，实际是 `ServerLevel`；它会处理邻居通知，因此双向通过不能证明生产 `WorldGenRegion` 正确。

## 修复范围

- 不改 LandUse schema、边界几何、材质 palette、owner ledger 或旧区块不回填规则。
- `WorldGenExecutionWorld` 写块后显式重算四个水平邻居中的 `CrossCollisionBlock`，覆盖 fence / wall；后写连接块会主动回刷先写连接块。
- FEATURES 的 `WorldGenRegion` write radius 为 1，中心 owner 边界外一格仍可受控写入；configured-feature 兼容入口若提前处理相邻 owner，外侧连接邻居可能不可写，此时恢复本次状态并保持 owner 未落账，等待该 owner 成为中心 chunk 后重试，不扩展到更远 chunk。
- 单次写入先保存当前格与四个水平邻居状态；连接刷新或最终校验失败时恢复这五个快照，再由 owner transaction 处理此前 mutation 的逆序回滚。

## 测试边界

- `CityLandUseChunkExecutorTest` 使用完全忽略 flags 的轻量状态访问器，覆盖同一调用序列和 `x=15/16` chunk 边界双向连接。
- 同一测试覆盖邻居刷新失败，断言新格恢复为空气、先写栅栏恢复为未连接状态。
- 同一测试覆盖连接邻居超出 write radius，断言不远写且本次主格恢复。
- `CityLandUseGameTests` 只保留为真实 Minecraft BlockState / ServerLevel 适配器冒烟，不再声称直接覆盖 `WorldGenRegion`。

## 剩余验收

- 代码修复只影响修复后首次生成的 owner；现有 ledger 已完成的旧区块不会回填，截图现场不会自动改变。
- 最终需在全新未生成边界实机确认连续栅栏两侧 BlockState 均连接，再把状态从“待新区块实机复验”改为完全完成。
