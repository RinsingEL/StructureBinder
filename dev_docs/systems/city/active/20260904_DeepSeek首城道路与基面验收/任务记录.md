# DeepSeek 首城道路与基面验收

*需求入口*：用户要求检查当前存档中 DeepSeek 设计的第一个城市，重点核实铺装基面覆盖率极低和看不到主路的问题。

*排查对象*：

- 存档：`D:\\PCL2-2.8.12\\.minecraft\\versions\\1.20.1-Forge_47.4.23\\saves\\RTF_beta_validation_01 (1)`；
- Realm 调试目录：`D:\\PCL2-2.8.12\\.minecraft\\versions\\1.20.1-Forge_47.4.23\\realm_debug\\provider_4c88d8fb9d1cfd78_r8192`；
- 首城 run：`city_realm_a_capital`，城市名 Stormwall Capital；
- 现场玩家坐标约 `(-1586, 73, -2826)`。

*诊断结果*：

1. Blueprint 的五条关系全部是 `ADJACENCY` 或 `DISTANCE`，`CONNECTION` 数量为零。主路规划 trace 因而返回 `CITY_MAIN_ROAD_EXPLICIT_TRAFFIC_CONNECTIONS_EMPTY`、`status=not_required`；不是 worldgen 漏写了一条已规划主路。
2. 唯一的内部街网属于 `defense_ring`：17 条 street band、4,557 个道路 surface feature，范围约为 X `[-1614,-1363]`、Z `[-3440,-3194]`，与玩家位置相距数百格，所以中心区现场看不到路符合规划产物。
3. 55 个结构锚点散布在 X `[-2003,-1382]`、Z `[-3477,-2482]` 的 `622×996` 包围框内。Foundation 的自动铺装保持启用，材料为 `minecraft:stone_bricks`，但 `autoConnect=false`；它只铺结构足迹经 margin/close 得到的 Foundation 掩膜，不覆盖整座城市包围框。该掩膜仅 73,494 格，占包围框 619,512 格的 11.86%，并被分为 16 个组件；预览显示为多个断开的铺装岛。其正式最低/期望面积均为 84,130 格，本次少了 10,636 格仍被 `admitted`，进一步放大了裸地问题。
4. D4 质量报告虽记录 `requiredRelationsSatisfied=false`、`structureGraphConnected=false`、`allRequiredStructuresCommitted=false`、`arrayVisualGeometryPassed=false`、`allStreetEntrancesConnected=false`，仍因顶层 hard block 为空而返回 `passed=true / score=100`。这是明显不合格方案能继续进入 D5/D6/D7 的直接验收缺口。
5. 最新存档日志仅发现区块 `(-119,-184)` 一次 `CITY_LAND_USE_MICRO_FILL_TARGET_OCCUPIED`，且 `rollbackComplete=true`。它只能造成局部缺口，无法解释零主路和全城 11.86% 的规划覆盖率。
6. 本城使用的 `foundation:urban` 参数为 margin `8`、close radius `24`、max join `64`，实际求解半径为 `41`。当前分层 Foundation 路径固定跳过 LandUse auto-connect 与 `CityUrbanResidualResolver`，生成的 `city_urban_space_plan` 为 `enabled=false`，所以近距离建筑间未被形态学闭合纳入的余隙不会再被二次吸收。SurfacePrint 还按 55 个矩形结构 footprint 排除了 15,680 格；若模板矩形范围内存在露天空地，也会保留原群系地表。该现场同时构成既有 `CITY-DL-20260811-02`（应改为 Group-aware polygon）的新实机证据。

*代码定位*：

- `DeepSeekToolLoopClient` 与 `ProviderPlanningToolCatalog` 未向模型解释 relation 类型的生成语义；
- `CityBlueprintCompilerService` 将未满足连接、非 CORE required 缺失、入口未接路和视觉质量问题降为 warning，并只按顶层 hard block 决定是否通过；
- `CityStructureAnchorPlanner` 在记录 `arrayVisualGapRecorded` 后继续把阵列视觉 hard block 并入 warning；
- `CityFoundationPlanner` 允许按距离形成多个 Foundation 组件，放大了无主路、跨大范围布局的稀疏结果。

*修改内容*：

- 在 DeepSeek Provider 系统提示中写明 `CONNECTION` 是唯一主路触发关系、普通结构组团需进入同一可达网络、孤立外围前哨才可用 `allowRelationConnection=false` 退出；
- 同步补强 `city_submit_d4_blueprint` 工具描述、`relationKind` 与 `allowRelationConnection` schema 描述，避免模型只看到枚举名而不知道执行语义；
- D4 acceptance 新增交通组团数与显式交通连接数审计：多个交通组团零 `CONNECTION` 或最终关系图不连通均 hard fail；
- HARD 关系无法完成、任意优先级 required 结构缺失、入口未接路、阵列视觉失败全部由 warning 提升为 hard block；SOFT 关系失败仍只警告；
- 保留 Foundation 修复边界：不扩大整城 bbox，不恢复道路式 LandUse auto-connect；近邻组团多边形和内部余隙另沿既有 `CITY-DL-20260811-02` 处理。本轮未修改存档。

*验证结果*：Provider/Compiler 专项共 45 项通过；`gradlew test --no-daemon` 全量 705 项通过，0 failure/error。回归覆盖系统提示、工具/schema 主路语义、零主路交通组拒绝、孤立组退出、硬连接受阻、入口未接路与阵列视觉 hard block。用户观察属实：原主路从未被规划，低覆盖率主要由 D4 放行跨大范围且不连通的结构布局导致；D7 仅忠实落地已有计划。

*实机部署*：游戏进程退出后已执行 `gradlew jar --no-daemon`，将新 jar 安装到当前 `1.20.1-Forge_47.4.23/mods/geomantia-0.1.0.jar` 并核对 SHA-256 与构建产物一致。旧 jar 保存在同目录 `geomantia-0.1.0.pre-20260904-road-gate.jar.bak`；存档未修改。新规则需重启游戏并由新的 DeepSeek D4 提交复验。

*后续建议*：修复时应同时补充 Blueprint relation 的显式语义与最低交通骨架要求，并让 D4 对关键连通性、required、阵列视觉、入口接路、Foundation 组件数/有效覆盖率执行真正的拒绝或受控重提。Foundation 不应简单扩大为全城 bbox，而应落实既有 `CITY-DL-20260811-02` 的 Group-aware polygon：主要组团生成局部封闭面，吸收近邻小簇和内部余隙，远端组团保持独立；结构 footprint 应改用精确占用/安全底面，避免整块矩形排除留下模板内裸地。
