# 20260625 D7 任务账本显式化

## 背景

City v0.3 计划要求先补 `CityMaterializationJob` / ledger，让 D7 从“一次调用里直接尝试所有结构”逐步变成计划驱动、可重入、可解释的 materialization scheduler。实现仓库在上一轮已经具备隐式 ledger：`PlacedStructureMap.placedStructures[].worldMutationApplied=true` 的记录会被后续 D7 调用复用；但 D7 产物中还没有独立的 job 视图，也没有显式 `ChunkMaterializationLedger` 对象。

本轮按 v0.3 P1 做最小兼容切片：不重写执行调度，不改变固定 / variable 真实放置路径，只在现有 attempt 和 placed structure 基础上显式输出 job / ledger 产物。

## 本轮改动

- `CityStructureD7Executor`
  - 从 `fixedPlacements` 和 `variableAttempts` 聚合 `materializationJobs[]`。
  - 每个 job 记录 `jobId`、`sourcePlanRef`、`placementMode`、`materializationMode`、`retryBudget`、`attemptCount`、`requiredPlacementBounds`、`requiredChunkRange` 和轻量 attempts 摘要。
  - dry-run 成功的 job 标记为 `planned`，不进入真实 ledger。
  - waiting attempt 映射为 `waiting_chunks`，失败 attempt 映射为 `failed`。
  - previous real ledger 复用的 attempt 映射为 `applied`。
  - 从 `placedStructures[]` 中筛选 `worldMutationApplied=true` 生成 `chunkMaterializationLedger.appliedJobs[]`。
  - `PlacedStructureMap` 和 `StructureGenerationTrace` 都内嵌同一份 `chunkMaterializationLedger`。
- 测试
  - 扩展 `d7ReusesOnlyRealPlacementLedgerEntriesAcrossCalls`：
    - dry-run ledger 为空，job 状态为 `planned`。
    - true-run 写入 `appliedJobs[]`。
    - `PlacedStructureMap.chunkMaterializationLedger` 与 `StructureGenerationTrace.chunkMaterializationLedger` 保持一致。
    - replay 后 job 状态为 `applied`，且不再调用 backend。
- 文档仓库
  - `城市规划数据契约.md` 新增 `PlacedStructureMap`、`CityMaterializationJob`、`ChunkMaterializationLedger` 字段口径。
  - `代码导览.md` 更新 D7 输出说明。
  - `测试入口.md` 登记 materialization job / ledger 自动测试。

## 验证

- `.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.CityStructureD6D7Test"`：通过。
- `.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.*" --tests "com.rinsing.geomantia.platform.http.CityPlanningEndpointHandlerTest"`：通过。

## 风险与后续

- 本轮只做产物显式化，不引入持久化独立 job queue，也不改变 HTTP 端点文件名；job / ledger 目前内嵌在既有 D7 JSON 中。
- `appliedPieces[]` 目前为空，等待后续 bounded jigsaw 多 piece solver / template paste 接入真实 piece ledger。
- 后续 P5 / P6 需要让 `BoundedJigsawPlan.pieces[]` 的 accepted piece 写入 `appliedPieces[]`，并将 job 状态从 start-piece 口径扩展到多 piece。
