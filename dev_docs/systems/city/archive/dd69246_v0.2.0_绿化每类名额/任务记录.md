# 绿化每类名额与挤压告警

*需求入口*：学院用户试玩 G02“花坛吃光名额、灌木绿篱花丛一个没种”；路线图 0.3.0 用户试玩修复第 3 项。

*修改内容*：`CityPublicRealmPlanner.plant` 原先只按 `maxPlacements` 共享一个额度，`slotLimits` 缺省等于 `maxPlacements`，所以花坛先种就拿走全部 320 个名额，后面的灌木、绿篱、花丛 limit 变成 0 且无任何记录。现改为：

- 每类有缺省上限：trees 80、planters 40、hedges 64、shrubs 96、flowers 220，合计 500，与默认 `maxPlacements` 对齐；作者显式 `slotLimits` 仍优先。
- 名额被前方类别压缩时写 `PUBLIC_REALM_SLOT_LIMITED:<area>:<slot>:requested=?:allowed=?`；额度耗尽被跳过时写 `PUBLIC_REALM_SLOT_STARVED:<area>:<slot>`。
- 作者显式把某类设为 0 仍视为主动关闭，不产生告警。
- `CityPublicRealmAssets.describe()` 的契约串补全 `slotLimits` 五类，避免 AI 继续照缺省示例写。

*验证结果*：新增 `CityPublicRealmPlannerTest.everyGreenerySlotHasItsOwnBudgetAndStarvedSlotsWarn`，断言五类都实际种下、花坛不超过 40、总量不超 `maxPlacements`、额度耗尽时出现 `SLOT_STARVED`；该测试类原有 7 项全部通过；`compileJava`/`compileTestJava` 通过。
