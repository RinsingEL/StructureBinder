# 城市高度组合与第二轮修复方案

**2026-10-18用户确认实施：“可以的，这套就自然很多，我们改改呗”。** 分支：`codex/campus-playtest-fixes-round2`；起点 `1d4fe4a6`。

本轮先明确城市空间关系，再替换相互覆盖的高度计算。修复目标是完整城市地面的协调、衔接和可行走性。

## 现有确认与本轮建议

已确认的[主建筑与分层台地](https://github.com/RinsingEL/designer_territoryMod/blob/main/docs/systems/city/10_product/%E6%A1%88%E5%AD%90/%E5%85%B7%E4%BD%93%E6%B5%81%E7%A8%8B%E7%9A%84%E6%A1%88%E5%AD%90/60_LandUse%E4%B8%8E%E5%9F%8E%E5%B8%82%E5%9F%BA%E9%9D%A2/%E4%B8%BB%E5%BB%BA%E7%AD%91%E4%B8%8E%E5%88%86%E5%B1%82%E5%8F%B0%E5%9C%B0/README.md)规定：一区一个核心，核心脚下一片地形决定本区落地基准，本区共享台地沿用；不同区分别取高，允许形成层次。

已确认的[城区地表与公共绿化](https://github.com/RinsingEL/designer_territoryMod/blob/main/docs/systems/city/10_product/%E6%A1%88%E5%AD%90/%E5%85%B7%E4%BD%93%E6%B5%81%E7%A8%8B%E7%9A%84%E6%A1%88%E5%AD%90/00_%E8%B7%A8%E9%98%B6%E6%AE%B5%E4%B8%BB%E7%BA%BF/%E8%81%9A%E8%90%BD%E7%A9%BA%E9%97%B4%E4%B8%8E%E5%9C%B0%E8%A1%A8%E5%8D%87%E7%BA%A7/03_%E5%9F%8E%E5%8C%BA%E5%9C%B0%E8%A1%A8%E4%B8%8E%E5%85%AC%E5%85%B1%E7%BB%BF%E5%8C%96.md)规定：庭院/广场整平，绿地顺应大坡向、消除小起伏，外缘/林缘保留地形；不为补植额外封洞或造台地。

本轮建议保留以上组织方式，明确区内“共享台地的实际范围”与区外“顺坡绿地”的分界。功能区是设计归属，不能仅凭功能区标签或一个庭院矩形，决定每个地表列是否突然改高。

## 统一比较什么高度

比较对象是**人物实际脚底站立面**。完整方块、半砖、楼梯、模板原点和地表方块Y不是同一种数值。概念规则先以站立面定义，实现时再分别转换成方块坐标和状态。

核心建筑的落地基准也不等于屋内任意一层地板。模板可能自带基座、门前楼梯和架高门厅：需要保留内部几何，以实际对外连接点接入公共路网，不能为了让屋内地板和街道同高而移动一整片城区。

## 各元素的高度关系

| 元素关系 | 建议约束 | 原因及例外 |
|---|---|---|
| 同一共享台地内的建筑承载基面、公共铺地、内院步道、嵌入式草坪 | 使用同一局部基面 | 草坪与石砖是地表材料和用途的区别，不能各取一份天然高度。建筑室内及自带台阶仍保留模板内相对高度。 |
| 建筑对外入口与紧接的门外落脚平台 | 接口站立面必须吻合 | 模板自带楼梯时，以楼梯真正对外的端点衔接；未自带时，需要明确编译连接，不凭空留门槛断差。 |
| 同一条道路的横断面、同一交叉口的落脚面 | 横向等高，交叉口有共同落脚面 | 纵向可以通过楼梯/半格台阶升降；路缘装饰高出是有意构件，不算车行/步行面横坡。 |
| 同一庭院/广场里的铺地、步道和普通草坪 | 默认共享平面 | 局部抬高花坛、下沉庭园应作为明确设计，有自己的边界和出入口；不能由独立采样偶然形成。 |
| 绿带紧贴道路/广场的边缘 | 接平或采用明确、低矮的路缘关系 | 绿带内部可以逐步顺坡，紧接处不出现无解释的3～5格直坎。不能由两侧各算高度后临时补墙。 |
| 两个功能区的共享台地 | 可以不同高 | 必须给两端留落脚平台，连接道路全宽统一坡段；其他边缘明确用坡地或挡土收边。 |
| 台地外公共绿带、林缘与自然地形 | 顺应地形，小起伏有限整理 | 与城市接边处统筹过渡；避免以8×8或chunk边界制造突变。 |
| 树、灌木、花草、花坛 | 根点/素材落地面读取最终地面 | 植物与素材高度只能相对最终地面增加。花坛土层可以高于道路，但其局部偏移不能变成城市台地高度。 |
| 护栏、挡土墙、柱头 | 从最终真实高差派生 | 它们不决定地面高度；同一台面内部不生成假挡墙，显式素材边界保留其设计语义。 |
| 水体、桥与两岸 | 水体保留；桥面有独立设计标高并接好两岸 | 普通草坪不借用桥面/建筑薄板策略在深坑上自动架空。 |

## 高度怎样确定

1. **先明确空间归属。** 标出每个核心共享台地的实际范围、同台的公共活动面、外围绿地、显式道路与桥，以及自然保留地。公共庭院帮助描述用途和构图，不应成为唯一强制改高的矩形开关。
2. **确定本区合理基准。** 依据核心完整落地面、核心脚下一片地形、水面和实际对外入口取高。取消把任意高度自动规整为4的倍数所带来的无需求跳变；若确有有意台阶层级，应由明确设计关系产生。此项属于本轮建议，需结合现有模板落地实现验证。
3. **同时考虑台地内部和外围。** 内部建筑、道路、铺地、草坪共用基面；外围接到自然地形或其他台地。若相邻固定端点有冲突，应规划过渡，或报告空间不足，不用中位数覆盖其中一端。
4. **把连接当作完整构件。** 入口楼梯、区间坡道、桥接岸均须检查起点、末端、全宽、净空及中途连续性。楼梯修好门口而末端出现3格断口，仍属失败。
5. **地面确定后再布置植物。** 素材使用最终承载面。支持不足时按完整素材拒绝，不重写地形来证明“种植成功”；允许的微小整地在地面规划阶段解决。

## 代码调整方向

现状是 Foundation、SharedTerrace、PublicGround 和执行期 MicroGrader 会先后修改同一列的高度；它们处理的范围与优先级不一致。第二轮应建立一个明确冻结的最终地面结果，后续地表材料、绿化和边界都读取它。

- 保留核心、台地与道路的已有能力，重做它们之间的归属与约束交接。先补每一列最终高度的来源：核心台地、道路过渡、自然地面微整或显式桥面；避免无来源的最后写入覆盖。
- `CityPublicGroundPlanner` 应依据“在共享台地内还是在外围绿地”选择策略，不仅对 publicSpaces 矩形写共享高度、矩形外恢复天然高程。
- `CitySharedTerracePlanner` 与道路定坡一起确定共享地面及其边缘，植物不再修改基面；`CityPublicRealmPlanner` 只在适合的最终承载面上放完整素材。
- `CityLandUseChunkExecutor` 对普通草地、建筑基础与显式桥面采用不同土方/承载限制。遇到实际地形偏差时保留明确诊断，不以无上限填高/架空让普通绿地通过。
- `CityLandUseMicroGrader` 在执行阶段只负责已批准的局部实现和实际地形核验；不能重新独立改变已经验证的公共地面关系。若必须做现场微调，需要更新完整连接关系及邻区上下文，不能只修某个owner的一列。
- 统一地面高度、楼梯高低端、模板groundPlane和素材surfaceOffset的转换约定；当前ROAD_SLAB实际使用double slab，不能套用过时的“所有slab都半格高”文档假设。

具体类拆分、字段和schema在开始实现前对照真实调用链确定，此草稿不提前宣称已经完成接口设计。

## 用什么证明修好了

- 平坦自然地面上，连续共享台地内换成草地或花坛，不产生额外高台/深坑；内外接边必须有完整设计。
- 不同区高度可以不同，但所有实际出入口、道路与桥接岸全宽可连续行走；非通行边缘有明确的坡地/挡边关系。
- 检查全部公共地面相邻边，不只检查入口附近或owner数。保留自然高差与显式挡土边的分类，避免将“所有边都必须同高”写成新的错误约束。
- 素材落地后不改变道路/草坪基准，不出现石柱、漂浮花坛或地下埋花；不适合的位置整实例拒绝。
- 覆盖庭院矩形边缘、8×8采样边界与chunk边界，验证结果不受切片或执行顺序影响。
- 使用本次教学庭院4格坎、书馆5格坎及深坑草皮作为真实回归样本，在独立副本比较整体与近景，并检查NPC实际行走。
