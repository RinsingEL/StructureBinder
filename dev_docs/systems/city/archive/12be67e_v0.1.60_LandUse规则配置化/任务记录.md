# LandUse 规则配置化

## 目标

将 City LandUse 的功能语义规则从运行时硬编码默认表迁移到用户可编辑的 profile 配置，使录制结构可通过配置新增 `military`、`industrial` 等用途，而不修改 Java 规则列表。

## 实现范围

- 配置根目录：`config/geomantia/city_land_use/`。
- `settings.json.profileId` 选择 `profiles/<profileId>.json`。
- 新增严格 `city_land_use_rules.v0.1` loader，校验 profile identity、完整 rule 字段、数值和 policy enum；未知字段 hard fail。
- bundled `default_v0_1` 保留原八类规则与既有参数；bootstrap 对既有配置目录只补缺失文件，不覆盖用户 settings / profile。
- City HTTP 规划、D5 激活校验和 Decoration 引用 LandUse 时均读取当前 profile hash；profile 变更要求重新规划。

## 验证

- `LandUseSettingsLoaderTest`、`LandUseRuleCatalogLoaderTest`、`LandUseRuleCatalogTest`、`LandUsePlanningServiceTest`、`CityPlanningEndpointHandlerTest` 共 57 项通过。
- `LandUseRuleCatalogLoaderTest` 校验 bundled default profile 与旧硬编码默认表的 `ruleProfileHash` 完全一致，证明默认行为未漂移。
- `git diff --check` 已检查实现与文档仓库，无空白错误。

## 风险

- 只迁移运行时 HTTP 主路径；纯 application overload 仍保留内置默认 catalog，供无文件 IO 的 JVM 单元测试使用。
- 用户修改 profile 后，已生成但未激活的 LandUse plan 会因 hash 漂移被拒绝，必须按设计重新规划。
