# 阶段一：理解场地并构思全城

## 目标

将 citySeed 的服务地位、定位、功能与玩家活动转成完整城市的空间组织，并为本次地形选择充分的规模。

## 设计工作

结合 cityDesignHandoff.savedCityDesign、D3 地形与群系图、siteReviewDecision 和 environmentStyleGuidance，确认城市要求。继承已保存的职责与名称，具体空间组织由这次场地决定。

先定骨架，再定功能区：在 D3 图上确定入口、制高点和主轴方向，选出全城唯一的一级地标及其位置，确定中心广场或主庭院在主轴上的位置，再决定哪些二级地标围绕它。然后考虑主要活动如何沿骨架分区：生活、研究、生产区域分别贴在主轴或广场的哪一侧，外围低地与岸边留给什么。指出应保留的自然分隔及其构图作用。

结合 scaleDesignTask 的规模背景、功能需求和场地容量估计体量。体量服从骨架：宁可紧凑成整体，也不要为占满场地而分散。将主轴、中心、一级地标、各区相对位置和体量理由写入现有城市意图字段，说明缺失资料或条件限制。

在 designIntent.boundary 用 form 和 reason 说明边界选择：NONE、GATEWAYS、LOW_BOUNDARY、LAND_ONLY 或 FULL_WALL。学院、宗教与无防御职责的小聚落通常采用开放边界；结合边境压力决定是否需要城防。天然水面保留，内街不构成城门；城门只服务真实对外道路或 externalAccess。

按人定区（见手册“按人定区”）：在每个功能区 role 开头写明【工作】【居住】或【公共】；先估各工作区的岗位与服务对象，算出全城人口，再估居住区床位与公共区容量。把岗位合计、全城人口、所需床位与公共容量写入城市意图，并让公共区落在居住区与工作区之间的通勤路上。

## 本阶段操作与规则

用 city_d4_overview 提交全城设置和按主次排列的 districts，填写实际 schema 要求的 designAnswers。此阶段定义功能区与城市组织，具体建筑、阵列和景观在分区阶段提交；素材可按需查询。

普通区共同组成城市主体；只有职责确实适合外围独立的区域才标独立，并说明用途。地形上的间隔需要设计关系，不能只靠功能名称宣称已经形成整体。

## 阶段完成依据

功能区清单覆盖本城主要职责；城市意图能说清主轴、中心、一级地标和各区挂在骨架上的位置；空间组织利用真实场地。程序接受总览后进入逐区初版，完整性最终以实际全城预览复核。
