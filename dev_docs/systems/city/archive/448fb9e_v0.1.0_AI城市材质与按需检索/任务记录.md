# AI 城市材质与按需检索

*需求入口*：文档仓 `CityAI材质选择与景观参数-v0.1/README.md`；用户要求开发选材与按需搜索两项。这两项在当前已确认的同一份七节需求案内。

*修改内容*：
- 可选 cityBlueprint.surfaceMaterials：城市默认、group 局部、道路类型、景观实例；严格解析可替换部位，原省略字段的蓝图序列化不变。
- 景观只暴露现有启用配方非空部位；内容覆盖进入原 surfaceSettings，生长参数和容量几何不变。
- SurfacePrintPlan 冻结 materialField 与实际道路用材并参与哈希；ChunkFragment 传递，执行器覆盖地面、路基、底板、填充、支柱、挡土墙、边缘与接入通路。
- blockMaterials 独立分页查询（12 项）、默认候选（每部位至多 4 项）、单方块客户端材质样片。名称/命名空间/现有标签搜索；适用性与未知形状如实标注；同名配套只是候选。
- Java Provider 和 TypeScript MCP 两套声明已同步；查询不变更工作流、不入编译队列、不扣格式重试预算。
- 材料预检/写入失败提供 sourceId、部位阶段、方块、坐标、原因；保持事务回滚。连接收尾这种批量失败不虚构单块归因。
- 默认候选作为资源数据提供，可由游戏 config/geomantia/city_material_candidates.json 替换。

*验证结果*：
- 195 项 Java 聚焦测试通过，0 失败/跳过。覆盖 BlueprintService、OutdoorCompiler、材料解析/查询、打印计划 codec、ChunkCompiler/Executor、WorldgenRegistry、HTTP handler、Provider schema。
- MCP npm test 12 项通过，包括新的材质参数声明；既有真实 stdio 桥接和图片传递测试通过。
- jar/reobfJar 成功，产物 build/libs/geomantia-0.1.0.jar。
- 新增回归验证：局部用材不串区；道路类型覆盖优先；更换道路用材保留坐标/高程/朝向；冻结计划往返及哈希；景观换作物/围栏保留容量域、生长参数和建筑 footprint；台地真实写入所选材料；道路覆盖已有台地时保留路基的道路类型来源；连续 12 次查询错误不创建格式预算文件；写入失败报告材料并回滚。
- 两仓 git diff --check 通过。按当前七节需求逐条核对，未引入布局、阵列、数量或面积需求。
- 测试过程修复：optional 根字段初版误设为必填、离线配置路径为空、路基被基础面合并后遗漏来源。景观对比测试改用各自蓝图的正确容量哈希，不绕过缓存校验。
