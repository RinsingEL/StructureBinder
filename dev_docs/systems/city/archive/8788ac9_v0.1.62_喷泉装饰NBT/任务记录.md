# 喷泉装饰 NBT

## 目标

- 为 City Decoration v0.4 增加可显式选择的 `fountain` 装饰。
- 生成当前 `run/config` 可读取的 `templates/fountain_01.nbt`，同时让全新默认 catalog 可由 bootstrap 生成同一结构。

## 实现

- 新增 `geomantia:decoration/fountain_01`：`5x5x5`、53 个方块记录、无实体，材质为石砖、磨制安山岩、水和錾制石砖。
- 使用 `above_surface + replaceable_only`，`comfortMarginBlocks=1`，标签为 `civic/public_facility/plaza/fountain/water_feature`。
- `medieval_coastal` 新增显式 `fountain` 语义映射；不加入 `civic_plaza` 随机池，避免一个广场程序重复生成多个大型中心装饰。
- 默认 bootstrap 生成 `fountain_01.nbt`；现场文件位于 `run/config/geomantia/city_decoration/templates/fountain_01.nbt`。
- 未修改 `落地测试` 的 active plan 和 ledger。catalog hash 改变后，必须重启并重新规划、激活显式包含 `fountain` 的 DecorationProgram，旧 active plan 不应继续使用旧 hash。

## 验证

- 默认 bootstrap、完整 content catalog loader、style resolver 三组 JUnit：通过。
- 源与现场 content/style JSON：PowerShell `ConvertFrom-Json` 解析通过。
- 现场 NBT：gzip 解析通过，尺寸 `5x5x5`，53 个唯一坐标，0 实体，palette 四种材质。
- 实现仓库与文档仓库 `git diff --check`：通过，仅保留现有 LF/CRLF 提示。
- 运行时只读 `GET /realm/city/query_decoration_catalog` 未执行成功：检查时 `127.0.0.1:5000` 无监听；需在客户端服务重新可用并重启加载 catalog 后复查查询结果。

## 风险与后续

- 当前 NBT 已生成但不会热注入既有 active plan；用户需要重启客户端并重新规划包含 `fountain` 的新区域。
- 顶部水源会在 Minecraft 方块更新后向下流入石盆，最终水流形态仍需实机观察。
