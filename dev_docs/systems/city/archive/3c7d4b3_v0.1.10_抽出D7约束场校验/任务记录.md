# 20260625 D7 约束场校验

## 背景

City D7+ 受控 jigsaw 首个切片已经能读取 start pool / start piece，并在写世界前做最小校验。但校验逻辑原先内联在 `MinecraftStructurePlacementBackend` 中，只能检查 `allowedArea`、`buildableCells`、`occupiedFootprints` 和面积预算；D5 已经产出的 `reservedCells` 没有进入 bounded jigsaw 约束场，导致道路、边界、缓冲区和小模板 hard reserved 的拒绝规则不够集中。

本轮按文档仓库 v0.2 / v0.3 路线推进 P4：先抽出可复用 `CityConstraintField` validator，不进入完整多 piece solver。

## 本轮改动

- `CityConstraintField`
  - 新增 D7+ 运行时约束场解析和 `validatePiece`。
  - 支持 `allowedArea`、`buildableCells`、`reservedCells`、`occupiedFootprints` 和 `targetAreaBlocks`。
  - 结构化返回 `CITY_CONSTRAINT_FIELD_MISSING`、`JIGSAW_BRANCH_OUT_OF_ALLOWED_AREA`、`JIGSAW_AREA_BUDGET_REACHED`、`JIGSAW_PIECE_RESERVED_CONFLICT`。
- `CityStructureD7Executor`
  - `ZoneInfo.asConstraintJson()` 继续输出 D5 `buildableCells`。
  - 新增输出 D5 `reservedCells`，保留 `reservedRefs` 和 `reservationTypes`，供 piece 级拒绝和后续 trace 解释。
- `MinecraftStructurePlacementBackend`
  - bounded jigsaw start piece 不再维护一份内联 covers / overlap 规则。
  - 改为调用 `CityConstraintField.fromJson(...).validatePiece(...)`。
- 测试
  - 新增 `CityConstraintFieldTest`，覆盖 buildable 接受、reserved 拒绝、功能区外拒绝、runtime occupied 拒绝、预算超限和缺约束场。
  - D7 bounded 后端测试新增 `reservedCells` 透传断言。
- 文档仓库
  - 新增 v0.3 D7 计划驱动 Jigsaw 拓展开发计划。
  - City README 和 function_map 挂入 v0.3 入口。
  - `城市规划数据契约.md` 为 `CityConstraintField` 补充 `reservedCells[]`。
  - `代码导览.md` 登记 `CityConstraintField.java`。
  - `测试入口.md` 登记 D7+ CityConstraintField validator 测试。

## 验证

- `.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.*" --tests "com.rinsing.geomantia.platform.http.CityPlanningEndpointHandlerTest"`：通过。

## 风险与后续

- 本轮只完成 piece 级 hard rule 抽取和 D5 reserved 透传，不实现 connector 多 piece 展开、terminal / endcap 收尾或 template paste 增强。
- `CityConstraintField` 首版仍是 2D footprint / cell 级校验；水体、坡度、道路接入和 3D clearance 后续按 v0.3 计划继续补。
- bounded jigsaw 真实世界验收仍沿用当前 start-piece 切片能力；完整城市级多 piece 可控落地需要后续 P5 / P6。
