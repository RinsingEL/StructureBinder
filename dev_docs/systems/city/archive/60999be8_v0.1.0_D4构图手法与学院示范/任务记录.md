# D4 构图手法与学院示范

*需求入口*：用户 2026-10-12 反馈独立 Agent 的 D4 学院“整体性一般，功能分得小却没层次”，要求审查 D4 阶段、阵列与装饰算法及提示词，在工作台做漂亮的魔法学院示例并尽量同步 Java。

*修改内容*：
- 诊断：D4 蓝图 6 个根锚点分散（东西相距 600 格以上），10 个组全部 gap 8 / BALANCED / faceInward=false，publicRealm.spaces 为空；提示词反复强调“规模充分”，缺少主轴、地标分级、围合朝向、疏密梯度等可执行手法。
- 提示词：handbook 新增“空间构图手法”与学院骨架示范；overview/district/integration/finalize/agent 改为先定骨架、整体性优先、体量与职责相称；README 记录本轮修订。
- Java：CityRectangleLayoutPlanner 的 GRID 支持 crossAlign=CENTER 格内居中（缺省 START 不变），工具 schema 补充说明。
- 工作台：新增 academy-starvault.json 示范与结果；修复 designed_landscape 对无入口地块的 KeyError。

*验证结果*：
- GRID 居中独立断言：START 坐标与原实现一致，CENTER 与 90° 方向正确。
- 工作台 Python 测试：city_fringe、connection_terraces、dem、gap_landscape、landscape_borders、space_composer、template_greenery、workbench 通过；array_tools、intentional_layout 依赖 gradle 或 Windows JDK 路径，修改前后同样失败。
- 云端无法访问 Forge/Mojang 仓库，gradle 测试未执行；使用离线 javac 编译生产 city 源码与工作台实验源码，重建 R31 结果与本机记录一致（23 栋、4 台地、76 段道路），新示范生成 33 栋、5 台地、107 段道路，浏览器 0 错误。

*剩余问题*：
- 需在本机运行 `prepareCityWorkbench` 与聚焦 City 测试复核。
- 正式 D4 缺少单栋朝向字段，非庭院成员无法朝向广场。
- 模板绿化的底色撒点仍为随机均匀分布（Python 与 Java 两端），“边缘密植、中心留空”的结构化改动待用户决定。
- 提示词实例目录已有文件不会被资源自动覆盖，需手动同步开发实例。
