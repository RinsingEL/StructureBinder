# 20260625 D7 多 Piece 求解核心

## 背景

City v0.3 P5 要求 bounded jigsaw 从 start pool 开始，按 connector 展开 accepted piece plan，并在越界、预算超限或候选不可用时写入 rejected / stopped trace。上一轮已经让 bounded start-piece accepted piece 写入 `ChunkMaterializationLedger.appliedPieces[]`，但还没有独立 solver 核心来表达多 piece plan。

本轮按最小可验证切片推进：新增纯 Java `BoundedJigsawSolver`，输入为已经解析好的 start piece 与 candidate pool JSON，不直接读取 MC registry / `StructureTemplatePool`。这样先把 connector、seed、validator、预算、branch stop 和 trace 口径稳定下来，后续再把 MC pool adapter 接入。

## 本轮改动

- `BoundedJigsawSolver`
  - 从 `startPieces[]` 和 `candidatePools` 生成 `BoundedJigsawTrace` / `BoundedJigsawPlan`。
  - 按 connector `pool` / `target` 匹配下一批候选 piece。
  - 使用 seeded shuffle 保证同一输入稳定输出。
  - 每个候选 piece 加入 plan 前调用 `CityConstraintField.validatePiece(...)`。
  - 维护 accepted footprint、visibleAreaCost、open branch、piece budget 和 depth。
  - 越界、预算超限、pool 为空或 piece budget 达到时写入 `rejectedPieces[]` / `stoppedBranches[]` / `failureSummary`。
- 测试
  - 新增 `BoundedJigsawSolverTest`：
    - connector 可展开为稳定两 piece plan。
    - 越界子 piece 进入 rejected / stopped，且不进入 accepted plan。
    - 面积预算不足时停止分支，不伪装成功扩展。
- 文档仓库
  - `城市规划数据契约.md` 说明 solver 核心已支持多 piece JSON 输入，MC registry / pool adapter 仍是后续接入。
  - `代码导览.md` 登记 `BoundedJigsawSolver.java`。
  - `测试入口.md` 登记 D7+ BoundedJigsawSolver 多 piece 核心测试。

## 验证

- `.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.BoundedJigsawSolverTest" --tests "com.rinsing.geomantia.systems.city.*" --tests "com.rinsing.geomantia.platform.http.CityPlanningEndpointHandlerTest"`：通过。

## 风险与后续

- 本轮 solver 输入仍是已解析 JSON candidate pool，不代表 `MinecraftStructurePlacementBackend` 已能从真实 `StructureTemplatePool` 递归读取子 pool。
- 当前真实 MC bounded backend 仍是 start-piece adapter；后续需要把 `BoundedJigsawTemplateInspector` 解析出的 connector 接到 registry pool 读取，再调用 solver。
- Template paste 后端仍需确保只写 solver accepted pieces，并把多 piece 结果完整写入 `appliedPieces[]`。
