# D4 职责与面积语义核对

*需求入口*：用户六条批注，询问分区是否固定、功能素材选择与重复、关系是否道路、整份提交失败风险，明确面积四阶段：初始阵列→近距离功能区双向连接扩张→冻结核心实际面积并按核心占比推导总量→仅其他区补足占比。最新用户澄清为本轮判断依据。

*修改内容*：仅诊断留档，没有改实现、配置、存档。纠正此前把连接扩张本身归为多余设计的判断。

*验证结果*：Group.role 是字符串，不是行政/农业/商业固定枚举；CORE 等优先级、布局算法及规模密度为结构化选择。Validator 检查结构与池引用存在，不会凭 role 自然语言自动确保功能匹配；池内循环取用本身不提供次数/多样性限制。角色选错应区分模型明确选择、池内容配置、程序执行来源，不能笼统归责。

当前编译主顺序符合初始→连接→冻结→占比补足。freezeDynamicAreaTargets 按 CORE.ownedAreaBlocks / CORE.targetAreaShare 推导总量（另受预览区面积上限约束），非开局固定最终城市面积。差异：连接关系来自显式 CONNECTION / ADJACENCY / HIERARCHY，未自动枚举所有近邻；growConnectivity 按接合间距终止，不等同于用户提到的连接启动距离阈值。补足条件 internalSpatialDemandBlocks 扣去 connectionSpatialDemandBlocks，冻结用 ownedAreaBlocks 包含连接面积及景观；补足遍历全部 groups，无 CORE 排除。stopWhenTargetReached=false 会覆盖目标为 previewArea。这些路径可能造成超出用户期望的追加，未声称已复现旧大农田城的唯一根因。

提交与编译是整城级，必需内容/硬关系/安全失败可阻断整城，填充不够及部分景观目标缺口有记录缺口继续路径，不能说任意单栋失败都作废。保留 Blueprint 不等于保留各成功组的编译检查点；目前不存在可证明的失败组局部修订隔离保障。

*剩余问题*：尚未实施修复。若后续授权，应保留用户要求的连接扩张与核心占比流程，核对统一面积口径、核心冻结、近邻启动阈值，以及分组修订的依赖失效范围；不得自行替换成纯道路连接或固定最终面积。
