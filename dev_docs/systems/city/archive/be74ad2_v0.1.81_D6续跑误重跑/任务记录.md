# D6 续跑误重跑任务记录

## 目标与边界

- 修复 Blueprint workflow 在 `skipExisting=true` 的续跑中重新执行 D4，继而误重跑 D5/D6 的问题。
- 保持 D5/D6 对完整 anchor map 的严格来源绑定，以及 D6 对已生成 owner chunk 的拒绝规则。
- 补齐 D6 质量失败原因向 workflow manifest 的透传。

## 现场证据

- run：`rtf0810_medium_city_20260810_01`。
- city：`city_rtf0810_greenfield_01`。
- attempt 4 已完成 D4、D5、D6、LandUse 激活与 D7，状态为 `waiting_for_worldgen`；attempt 5 再次执行 D4 和 D6。
- attempt 5 的 D6 `quality_report.json` 为 41 项 `STRUCTURE_CHUNK_ALREADY_GENERATED`。
- attempt 4 的 D5 内嵌 source anchor map 与 attempt 5 覆盖后的当前 D4 存在真实 anchor 坐标和模板差异，不只是 `timingMs` 差异。

## 根因与决策

- `workflowRunD4Blueprint` 没有提供 skip artifact，导致 Blueprint D4 无条件重编译。
- D4 被覆盖后，D5/D6 的精确来源校验按设计判旧产物过期；不能通过忽略 anchor 差异来修复。
- 修复采用稳定 accepted Blueprint provenance 判断 D4 是否仍为当前产物；旧产物缺 provenance 时保守重编译一次。
- D6 若只有一种失败原因，将 `qualityReport.failureSummary` 的该原因提升为响应顶层 `reasonCode`。

## 实现修改

- `CityBlueprintCompilerService` 在 `cityBlueprintCompileProvenance` 中新增 `contextId` 与 `sourceBlueprintHash`。
- `CityPlanningEndpointHandler` 仅在 context、validation、accepted submission、Blueprint 文件与 D4 provenance 一致时把 anchor map 作为 Blueprint D4 skip artifact。
- D5/D6 的 `sourceStructureAnchorMap` 精确比较保持不变。
- `CityStructureMaterializationPlanner.Result.asJson()` 将单一 failure summary 原因提升为顶层 `reasonCode`；多原因统一为 `D6_PREFLIGHT_FAILED`。

## 验证结果

- `CityPlanningEndpointHandlerTest` 与 `CityStructureTemplateMaterializationPlannerTest` 两个聚焦测试类通过。
- provenance、D4 skip、D5/D6 精确身份和 D6 reasonCode 四条定向回归通过。
- `CityBlueprintCompilerServiceTest` 全类 21 项中 20 项通过；既有 Landscape capacity 场景因 `CITY_BLUEPRINT_GROUP_MINIMUM_UNREACHABLE` 失败（实际 2 栋、规则 minimum 3 栋），与本案修改无关。
- 双仓库本案文件 `git diff --check` 通过，仅有既有 LF/CRLF 提示；待使用修复后新 D4 产物做实机续跑复验。

## 剩余风险

- 旧 run `city_rtf0810_greenfield_01` 的当前 D4 已被第 5 次失败续跑覆盖，不能自动猜测恢复 attempt 4 的 anchor map；本修复防止新产物再次被覆盖。
- 首次使用修复后的代码处理旧 D4 时，由于缺少新增 provenance 会保守重编译一次；应在未生成 owner chunks 的新城市上完成首次编译和续跑复验。
