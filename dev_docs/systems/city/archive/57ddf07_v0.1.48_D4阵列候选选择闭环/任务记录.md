# D4 阵列候选选择闭环 v0.4 任务记录

## 范围

- 实现仓库实施 D4 v0.4：基于已 Plan collision occupied 的附近空间查询、方向外扩候选生成、整组选定后提交。
- 文档仓库 `docs/systems/city/10_product/案子/D4阵列候选选择闭环-v0.4/README.md` 为本轮产品真值；保留既有未提交改动，并在验收修复阶段同步写入导航、契约、测试入口和案子状态。

## 实现结果

- 新增 `array_candidate_selection_loop_v0_4` 显式 loop mode，不改变 v0.2/v0.3 的直接执行语义。
- 外扩查询返回 focus collision、附近 patch、可用方向、距离、容量和外扩入口；全局 patch 搜索仅在 `newFunctionalArea=true` 时启用。
- 候选生成默认 3-5 组完整方案，不改 loop state、occupied、array zones 或剩余空间；不足时返回 hard failure。
- 选择一组候选时才在一个 state snapshot 中写入 anchors、occupied、zones、remainingExpansionSpace 与 decision trace；默认必须指定 candidateId，显式 `autoSelectHighestScore=true` 才可快测自动选择。
- 保留 `composite_array` parent/subZones/child arrays，并为 `plaza_ring` 增加向外半圆候选点生成。

## 验收修复

- `newFunctionalArea=true` 不再要求 `focusRef`、`direction` 或 `targetPatchRef`。query 返回按可用性、剩余容量排序的 `globalPatchCandidates[]` 与入口；后续 plan 必须显式传 `selectedGlobalPatchRef`，未选择、patch 不存在或无容量分别返回 `D4_ARRAY_LAYOUT_GLOBAL_PATCH_SELECTION_REQUIRED`、`D4_ARRAY_LAYOUT_GLOBAL_PATCH_UNAVAILABLE`、`D4_ARRAY_LAYOUT_GLOBAL_PATCH_NO_CAPACITY`。
- 常规外扩仍保持 `focusRef + direction + targetPatchRef` 的兼容语义，不能回填 focus collision 一侧。v0.4 仍不进入默认 workflow。
- 修正 `guide_line_dual_side` 在外扩候选中的变体起点：双侧带状点位围绕各 candidate origin 生成，不再全部钉在可用区边缘，因此能稳定返回 3-5 组完整候选，同时仍受外侧 available bounds 限制。
- 增补 planner 自动测试：compound cluster、沿线两侧、外向半环 / `composite_array` 分别验证 collision 无重叠；验证候选生成不改 state、整组选定才更新、默认禁用自动选 / 显式 auto trace、容量 hard fail，以及显式新功能区全局搜索、选 patch 和无容量失败。
- 同步 Node MCP 工具描述及文档仓库的导航、City README、案子状态、接口契约和测试入口；文档真值明确 v0.4 的五段接口、artifact、失败码、兼容边界和真实游玩验收要求。
