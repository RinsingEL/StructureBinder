| 本案要求 | 实现核对 | 验证与边界 |
| --- | --- | --- |
| 五档提前告知、初始底层阵列计数、主体嵌套 | CityScaleDesignTask 在 prepare 内联上下文；submit/compiler 使用同一任务；LARGE_CITY 不再折叠成 CITY | 规模测试、服务全量测试通过。建议数量非硬门槛；CORE 参与组合及大城市多个组合只是最低结构检查，主体美观仍需预览验收，不声称算法能判断审美。首都默认未擅改。 |
| 阵列组织其他阵列、各自保留算法和道路空间 | 复用 centerGroupId/memberGroupIds；成员可继续当中心；拒绝循环和多父归属；内外分层规划 | 递归四组编译及既有算法、槽分配测试通过。不新增功能区类型、逐侧道路字段或专用商业区算法。 |
| 沿实际岸线布置建筑/子阵列 | ALONG_PATCH_BOUNDARY 的共同采样边生成实际候选；COMPACT/ORGANIC_COMPACT 建筑和非对称父组合可用 | 折线岸线和不相邻 patch 测试通过。不相邻明确报错；CENTER_SYMMETRIC 保持对称含义，不能承诺它同时弯曲沿岸；地形、工程限制不变。 |
| 从中心与已有阵列周围扩张、补厚度 | expansionFrontiers 枚举全部 committed arrays 和方向，优先靠近主体、减少不必要长条；随后仍经原候选/地形检查 | 既有扩张编译测试通过。只改变百分比扩张前沿排序，不替 AI 换素材或强行把自然狭长地形改方形；最终全占地和道路仍受原预览边界检查。 |

| 局部修正、保留 AI 设计权 | 保留 existing draft/patch/checkpoint 恢复链；新增几何失败为结构化返回，明确更改位置/关系；没有新增自动删除成员 | 全量现有失败、恢复和验收测试通过。不用减少初始组数来满足新规模要求，不维护独立网页。 |
