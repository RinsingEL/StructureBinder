# 冒险附属集成故障

## AD-001：主仓 Harness 输入换行导致构建校验失败

*现象*：合入后的完整构建停在 processHarnessResources，报 Stale Harness runtime (build.mjs)。

*首次偏离*：Gradle 按原始文件字节核对已提交运行包的输入指纹。

*根因*：本机 build.mjs、src/runtime.mjs 为 CRLF，manifest 对应 LF；逐一归一化后完全匹配，源码逻辑和已提交运行包没有变化。

*修复*：恢复与 manifest 一致的 LF 字节，在 .gitattributes 中固定 Harness 输入文本为 LF；没有关闭指纹检查或复制旧工作树的运行包。

*验证*：八项源输入均匹配现有 manifest；修复后冒险测试、主 MCP 独立测试、四包隔离及冒险单包检查通过。主仓全量测试的其他失败另做合入前基线对照，不以此项修复宣称全部通过。

*记录*：[冒险附属合入主仓](archive/e8879f07_v0.1.0_冒险分布附属合入/任务记录.md)。

## AD-002：主仓全量测试有 16 项既有失败

*现象*：合入后的 test 共 1364 项，16 失败，13 跳过；失败涉及 ProviderRevisionLoop、CityPlanningEndpointHandler、CityD4Versions、CityDesignExamples、CityLandUseCapturedAccess 和 PlanningBoundary。

*首次偏离*：全量单元测试执行阶段；冒险独立测试、MCP 隔离与分包验证通过。

*根因*：各失败的产品/测试根因待专项定位。合入前 4b32d0b1 独立基线复现完全相同的 16 项失败，未发现本次合入新增失败。基线因未装本地样本多跳过一项入口目录测试，该项在主工作区通过。

*修复*：本次保留原测试与失败，不修改无关主功能来使结果变绿。对照证据完整保存，后续独立排查。

*验证*：两边均运行 1364 项；失败名称集合完全一致；主包单独运行和冒险启用后的 3 项 Forge GameTest 通过。

*记录*：[合入与基线对照](archive/e8879f07_v0.1.0_冒险分布附属合入/任务记录.md)，详见同目录 verification.json。
