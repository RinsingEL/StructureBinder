# GIS MCP 调试接口任务记录

## 背景

- 目标：为 GIS v1 基线补本地 MCP 调试入口，减少客户端窗口焦点和截图判断的不确定性。
- 范围：Java 本地 HTTP 接口、Node MCP 工具、文档仓库接口契约/代码导览/测试入口同步。
- 非范围：G8 消费者查询接入、生产级远程 API、SavedData/二进制长期持久层。

## 实现摘要

- Java 侧新增 `com.rinsing.geomantia.platform.http`：
  - `GeomantiaHttpServer`：MC server 启停时在 `127.0.0.1:5000` 注册本地接口。
  - `GisHttpController`：提供 `/gis/status`、`/gis/refresh`、`/gis/test_run`。
  - `GisHttpUtil`：JSON 读写与 `run/geomantia_mcp_log.jsonl` 诊断日志。
- Node 侧补回 `country_designer_mcp` 源码：
  - `gis_status`
  - `gis_refresh`
  - `gis_test_run`
- 文档仓库新增接口契约：
  - `docs/systems/gis/20_contracts/接口契约/GIS调试MCP接口.md`

## 验证记录

- `./gradlew.bat compileJava`：通过。
- `npm run build`（`country_designer_mcp`）：通过。
- `./gradlew.bat test`：通过。
- 真实客户端游玩态：
  - 启动 `runClient` 并自动进入存档 `新的世界 (1)`。
  - integrated server 启动后接口监听 `127.0.0.1:5000`。
  - `GET /gis/status` 返回 `ok=true`，在线玩家 `Dev` 位于 `minecraft:overworld`，中心附近 `5537,3439`。
  - `POST /gis/test_run {"caseId":"mixed"}` 返回 `ok=true`、`passed=true`，runId：`gis_mq6q9go8_f2ed2cb3`。
  - `POST /gis/refresh {"radiusChunks":8,"sampleMode":"prior"}` 返回 `ok=true`、`status=completed`，runId：`gis_mq6q9nuv_502149d9`。
  - MCP stdio 工具烟测：`tools/list` 返回 `gis_status`、`gis_refresh`、`gis_test_run`，`tools/call gis_status` 成功返回 HTTP 状态。

## 风险与后续

- 当前接口是本机调试/验收入口，默认无鉴权，仅绑定 `127.0.0.1`。
- `gis_refresh` 当前同步阻塞等待刷新完成，半径过大时调用方需使用足够长 timeout。
- 无在线玩家时，`gis_refresh` 必须显式传 `centerBlockX` 与 `centerBlockZ`。
- Node MCP 包此前仅保留 `dist/` 产物，本轮补回最小源码；旧 `dist/src` 中历史工具产物未作为当前 GIS 真值。
