# GIS v1.1 Step 参数化任务记录

## 任务范围

- 本轮属于双仓库联动。
- GIS 实现仓库只实现 `cellStepBlocks` 参数化最小闭环。
- 文档仓库同步收窄 GIS v1.1 计划，明确 W / T 调度、WorldPatchMap 编排、AI 选点和国度规划不属于本轮 GIS 内核实现。

## 实现摘要

- `GisSampleConfig` 新增 `withCellStepBlocks`，保留默认 step=4，允许调试入口传入 `1..256` 且能整除 Region 方块尺寸的 step。
- `RegionKey` / `AtlasRegion` / `AtlasRegionStore` 将 `cellStepBlocks` 纳入 Region ID，避免不同 step 的同维度同 region 坐标互相污染。
- Forge 命令支持 `/geomantia gis refresh <radiusChunks> [sampleMode] [cellStepBlocks]`。
- HTTP `POST /gis/refresh` 和 MCP `gis_refresh` 新增可选 `cellStepBlocks` 参数。
- `progress_manifest.json`、`preview_manifest.json`、`region_snapshot.json`、`test_report.json` 均记录实际 step；preview manifest 额外记录 `metricRadiiCells` 和 `metricRadiiBlocks`。
- 新增测试覆盖 step-aware Region ID、默认 step 兼容和非默认 step 产物字段。

## 文档同步

- 收窄 `docs/systems/gis/10_product/开发计划-v1.1-多分辨率Atlas与W粗Patch.md` 为 Step 参数化最小闭环。
- 更新 GIS 采样配置、AtlasCell、AtlasRegion、RefreshJob、PreviewManifest、GIS 调试 MCP 接口契约。
- 更新半径刷新实现指南、测试入口、自动测试方案、半径刷新功能设计和预览图功能设计。

## 风险与后续

- 本轮没有为粗 step 校准独立分类阈值；非默认 step 只保证链路运行、隔离和产物可追溯。
- W / T 后续可以选择传入粗 step 消费 GIS 产物，但调度、选点和 WorldPatchMap 编排应在对应消费层任务中实现。
- Atlas 数据格式版本未提升；本轮通过 step-aware Region ID 和 manifest 字段避免调试/内存层混用。
