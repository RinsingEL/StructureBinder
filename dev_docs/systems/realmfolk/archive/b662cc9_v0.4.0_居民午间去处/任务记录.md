# 居民午间去处

*需求入口*：学院用户试玩 L03“日常活动与路线不够丰富”；路线图 0.3.0 用户试玩修复第 5 项。

*修改内容*：

- `Design.PublicActivity.maxDistance` 默认 128 → 384；`Design.resolve` 把旧默认 128 迁移为 384，显式更大的半径保持不变。
- `DailySchedule.phase`：有 `trade` 能力的职业在午间（5000–7000）继续工作，其他居民照常用餐。
- 食堂只有入口一个公共点属于素材缺口（餐饮建筑只有 3 个 work 设施，没有 seat/meeting），留给第 13 项模板床位与工位检查，本分支不改素材。

*验证结果*（真实游玩，客户端 `Realmfolk_Behavior_Config`）：

- 自动测试：`DailyScheduleTest` 3 项、`DesignActivityMigrationTest` 2 项通过；realmfolk 编译通过。
- 实机：`time set 6000` 后，餐食商“塞拉·ac4c”显示“工作”，旅人显示“去吃午饭”，学生在 438 格外显示“去吃午饭”；迁移前旧半径下同批居民只会选 128 格内的公共点。
- 截图：`午间食堂与居民.png`；报告快照：`life-snapshot-01.json`。
- 调用记录：`/command {time set 6000}` → ok；`/command {tp -2994 66 5486}` → ok；`/life` 两次、`/state` 三次、`/screenshot` 两次。

*剩余问题*：食堂没有座位/会面设施，公共点仍只有入口；洗衣、串门等次要去处按 11 号案排期；“岗位动作不可用”的用品商属于工作设施动作缺口（另项）。旧存档的活动半径经解析迁移生效，但重新发布配置后才会写入新值。
