## 2026-10-10 固定窄范围步行检查误报全局不通

*现象*：园艺疗养实验 services:1 至 guest:1 在原 ±2 格道路裁剪内不可达，其余 6 条通过。

*首次偏离*：check-campus-walk.py 按二维道路路线截取附近方块，裁剪范围不足以容纳可通行的绕行。

*根因*：检查范围限制；扩大裁剪为 ±6 格后，同一份实际方块全部 7 条通过，没有补地板。窄路线内具体阻挡尚未定位。

*修复*：未改原检查器；本批保留窄范围失败及宽范围成功两份证据，仅确认存在可达路线。

*验证*：runtime/city-subjects-20261010/woodland/revisions/r0001 的 campus-walk-check.json 与 campus-walk-wide-check.json。

*记录*：[城市主体快速对照](active/20261010_城市主体快速对照/任务记录.md)。

## 相邻核心台地高差的道路只通过二维连接审查（已修复，2026-10-09）

*现象*：通用设施试验 R9 教学礼堂入口 (-2955,73,5185) 与研究书楼入口 (-2955,77,5176) 的 streetReview 为连接状态，但实际导出方块的单入口离线步行检查无法到达研究书楼。

*首次偏离*：给同一展示分区引入两个独立核心台地及四格高程差后，既有道路高程处理没有形成可行走的连接。

*定位证据*：runtime/campus-workbench/revisions/r0009/terrace-walk-check.json；仅礼堂入口作为种子，未把两个目标入口同时作为可达起点，窗口内 881 个步行节点，未截断。

*根因*：入口接驳分成多个短 band 后，每段端点和重叠范围单独固定高度；同一分区的入口还产生重复 streetBandId，冻结高程索引会发生覆盖。预览 VirtualWorld 将 Java 的 double 路面写成 bottom slab。台地挡土预备构件也可能在道路降坡后重建到道路面以上。

*修复*：实验适配为重复 band 分配唯一实例编号；新增主题无关的完整道路图高程规划，保留实际入口接驳高度，冻结楼梯后再交给原区块执行。空间不足明确拒绝。VirtualWorld 道路/桥面半砖状态与 Java 一致；区块执行器跳过高于冻结道路面的挡土墙写入，邻接立面保留。

*验证*：68 项聚焦 Java 测试和 7 项工作台回归通过。最终 R18 的实际方块碰撞检查仅从礼堂入口出发，可到达高四格的研究书楼入口，1147 个节点、未截断；二维连接审查不替代此检查。浏览器两套主题及设施开关检查通过。证据 runtime/campus-workbench/revisions/r0018/terrace-walk-check.json 与 terrace-features/validation-summary.json。

*记录*：[任务记录](archive/db7fbb04_v0.1.0_魔法学院轻量建筑工作台/任务记录.md)，未提交。

## 台地角部构件按扫描顺序聚集在同一侧（已修复，2026-10-08）

*现象*：通用设施试验首版的礼堂台地角塔集中在西侧和南侧，未能覆盖同一台地的不同转折。

*首次偏离*：CityTerraceFeaturePlanner 将符合承载、净空条件的角点按 z/x 排序后直接截取限额。

*根因*：扫描顺序参与了构件的空间分布，没有在有效候选之间进行距离选择。

*修复*：先选择离台地中心最远的有效候选，之后逐个选择离已选构件最远的候选；保留最小间距、数量限额及确定性排序。无法完整承载或侵入道路、建筑的候选仍排除，不扩大台地。

*验证*：Java 几何测试与 7 项工作台回归通过；学院和普通城镇真实浏览器预览已核对，角部构件分散在不同转折，建筑与道路净空、完整承载均通过。证据 runtime/campus-workbench/terrace-features/final/。

*记录*：[任务记录](archive/db7fbb04_v0.1.0_魔法学院轻量建筑工作台/任务记录.md)，未提交。

## 教学区高层连接口未接廊，试摆缺少跨楼连通验收（待设计修复，2026-10-08）

*现象*：用户指出两侧翼楼像“飞楼”，仍是单一模板。R8 两栋 MG-34 的二层预留连接口没有对应连廊实例，实际教学区尚未形成跨楼连通的建筑组团。

*首次偏离*：素材作者 connections 仅保存端口语义，工作台目录没有向阵列传递这些端口，教学试摆只排布独立模板并连接地面道路。

*根因*：当前嵌套阵列处理子组合包围盒和坐标平移，没有必需连接关系、端口匹配、连接件选取或未用接口收口步骤。验收覆盖楼内通路和地面入口，未覆盖本方案实例之间的建筑连通性。

*核对*：两侧翼楼底板下有支撑，本轮不将“整栋楼悬空”作为已确认根因；确认缺失的是高层端口消费与组团连通验收。之前手工旋转接廊检查证明素材可以对接，不证明 R8 已经实例化这些连接。

*修复状态*：本轮仅核对与讨论；建议在整体占地预算内规划连接件，将完整组合几何与连接关系在落地前冻结，并为未用可选接口收口。该方案尚未实现，也未修改正式 City 数据契约或 R8。

## Windows MCP stdio 编码随控制台变化（已修复，2026-10-08）

*现象*：Windows 上 UTF-8 工具响应被按 GBK 解码，中文响应出现断行，JSON-RPC 解析失败。

*首次偏离*：array_tools.py stdio 输入输出沿用控制台编码；测试子进程也沿用平台默认编码。

*根因*：MCP 的 UTF-8 传输约定没有显式落实，中文响应会受宿主控制台及测试读取方式影响。

*修复*：stdio 模式将 stdin/stdout 配为 UTF-8，测试 subprocess 显式 UTF-8 读取；文件读写统一 UTF-8，Windows 选择 gradlew.bat 与本机中文字体。

*验证*：test_stdio_transport 修复后通过，initialize、tools/list、工具 JSON 和两张 PNG 均正常返回。

*记录*：[任务记录](archive/db7fbb04_v0.1.0_魔法学院轻量建筑工作台/任务记录.md)，未提交。

## 2026-10-10 D3 换行差异拒绝同源 DEM

*验证*：3 项 DEM 回归通过，包含 CRLF 同源接收与内容变化拒绝；完整 step=1 DEM 实际导入 R29，134532 个施工地形列逐一核对通过。
