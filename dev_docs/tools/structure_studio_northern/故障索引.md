# 寒海航民建模故障索引

## 寝间门正对桌凳或个人柜

*现象*：NS-05-v02～v05 局部寝间标记净空正常但无法从入口抵达。

*首次偏离*：隔门两侧分别紧邻餐凳端板、床沿或床尾柜，阻断了门口的实际碰撞通路。

*根因*：家具占地与门位置分别设计，没有预留双方连接的一格通路。

*修复*：隔门移至相邻完整通道，不移除必要的床柜、公共桌凳与分区。

*验证*：四项重导出后全部导航可达、零警告，最终逐图复查通路。

*记录*：[填充任务记录](active/20260922_寒海航民填充建模/任务记录.md)。

## 后墙储物架默认站位落墙

*现象*：住宅代表 NS-05-v01、NS-06-v01 的被服柜数据净空及导航检查失败。

*首次偏离*：后墙前一格柜架沿用朝 +Z 的默认站位，站位落在后墙。

*根因*：紧凑寝间未将柜面使用方向与墙位一起核对。

*修复*：住宅模块柜架在 +Z 被挡时改用前侧 -Z 站位，核心模块保持冻结。

*验证*：两住宅代表重建数据与导航均零警告；逐项检查最终全视图。

*记录*：[填充任务记录](active/20260922_寒海航民填充建模/任务记录.md)。

## 高台护边穿入物资库

*现象*：NS-02 首轮导航无法抵达高台物资点，登记站位占用云杉原木。

*首次偏离*：高台横护边误放在 Z=22，穿过后库内部。

*根因*：防坠护边坐标沿用内部横线，未与库体边界核对。

*修复*：护边移至台地 Z=18/31、X=18/33 外沿，并留三格梯口。

*验证*：修复后数据与导航零警告，最终 26 张截图实际查看后归档，梯口及高台储备站位可达，双哈希匹配。

*记录*：[任务记录](archive/431b5cef_v0.13.0_寒海核心完成/任务记录.md)，Git 主审集中处理。

## 填充家具与入口平台连接

*现象*：盐坊抬高入口、仓库隔门、客栈侧寝间和桶器铺入口在首轮验证中出现站位或通路警告。

*首次偏离*：NS-03-v04 入口 Z=6 缺抬高支承；NS-08-v01 T 形隔门 X=12 正对墙；NS-09-v02 寝室门口被床尾柜/长凳阻挡；NS-F01-v07 前架 Z=4 遮住店门。

*根因*：平台、隔断与家具坐标分别落位，未给交接处预留完整通道。

*修复*：盐坊补 Y=4/Z=6～7 平台；仓门改 X=10；客栈侧门后移一格；桶器铺前架改 Z=5。温床 NS-F02-v04 门外站位同步移至 X-2，避免碰撞边界。

*验证*：最终重建数据与导航零警告，各项全视图实际复核后发布。

*记录*：[填充任务](active/20260922_寒海航民填充建模/任务记录.md)。

## 同材质顶视造成护栏漏渲染误判

*现象*：NS-05-v06、NS-06-v05、NS-08-v03、NS-09-v03 的顶视图中梯井木护栏不易辨识。

*首次偏离*：仅依据正俯视中木材颜色融合推断实体缺失。

*根因*：顶视压缩高度线索；主审检查当前 NBT 的16个栅栏、原版26面网格与隔离栅栏图，确认几何完整。

*修复*：保留 U 形栅栏，不改共享渲染或替换实体墙。四项各补真实浏览器 floor-2-oblique.png 并实际查看，护栏高度及连接清晰。NS-05-v06 作者文字残留临时“实体木护边”已恢复 U 形护栏描述并重建复拍。

*验证*：四项最终斜视已归档；44项最终共825图、NBT/作者双哈希匹配，数据/nav零警告。

*记录*：[填充任务](active/20260922_寒海航民填充建模/任务记录.md)。
