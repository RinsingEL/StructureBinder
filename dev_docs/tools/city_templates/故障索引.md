# 城市素材工具故障索引

## 多风格包静默交付缺少核心的哥特风格

*现象*：476项首包宣称10风格，但哥特47项不含核心，不能用于完整哥特城市测试。

*首次偏离*：导出器按缺失入口朝向逐项排除后，没有检查每个风格是否仍有核心建筑。

*根因*：memorial_lanterns.py 的 entry 与旧路高台入口漏写 facing；书库和议事庭的庭院侧翼门也被当成对外道路入口，补朝向后会直投穿过庭院设施。打包器缺少风格核心覆盖检查。

*修复*：依据实际NBT门状态及旧路台阶几何补 north；庭院侧翼门改 circulation，保留其步行目标。同步builder元数据，源NBT与validation文件不变。打包器拒绝含无核心风格的素材包。

*验证*：6项真实NBT入口投影与更新元数据后的导航复验全部通过，详细证据 build/gothic-core-metadata-evidence.json；修正版482模型含哥特53项/4核心，全部通过Minecraft编解码、目录覆盖、哈希、ZIP CRC及正式解析/安装器验证。旧476项包被新增核心覆盖检查拒绝，未生成输出。

*记录*：archive/0d261066_v0.1.0_多风格测试素材包导出/任务记录.md。

## Studio 正面导出测试依赖已变动的模型入口

*现象*：test_studio_frontage_export 保存 side 主入口时失败，提示入口不存在。

*首次偏离*：测试复制当前 DS-F04-v03 作者文件后，仍假定存在历史 front/side 双入口。

*根因*：该模型目前只有 entry 入口，测试夹具直接依赖可变素材数据。

*修复*：仅在测试临时副本中明确构造 front/side 两个入口；几何投影仍由该测试原有 stub 提供，不修改源模型。

*验证*：本轮 Studio 导出相关10项回归全部通过。

*记录*：archive/0d261066_v0.1.0_多风格测试素材包导出/任务记录.md。

## 建筑候选编号包含大写导致正式规划加载拒绝

*现象*：173建筑合入后PLANNING_AUTHOR_ANNOTATION_REQUIRED。

*首次偏离*：生成器将B编号直接拼入templateRef。

*根因*：Minecraft资源ID仅允许小写，语义目录跳过无效ID。

*修复*：生成器小写化资源路径；合并工具写出前验证资源ID；当前标注原件保留，运行输入使用独立规范化副本。

*验证*：完整471件正式规划源解析和内容包安装通过。

*记录*：active/20260919_建筑173配置合入/任务记录.md。
