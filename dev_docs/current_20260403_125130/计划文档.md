# 剩余工作区清理提交计划

## 本次任务标题

整理并提交当前仓库中剩余的归档重命名与工作流文档删除变更。

## 最终计划摘要

核对当前工作区里未提交的 `dev_docs` 归档重命名、`docs/workFlow` 删除以及其他残留项，明确哪些属于历史任务归档和文档清理，哪些属于运行产物不应入仓；随后只提交与仓库文档整理相关的内容，并为本轮清理补齐 AI 工作流文档。

## 实施步骤

1. 检查剩余工作区变更，区分可提交文档清理与不应提交的运行产物。
2. 将已有 `current_...` 文档目录按对应提交号归档纳入版本控制。
3. 提交 `docs/workFlow` 删除与 `dev_docs` 归档整理。
4. 记录本轮清理范围与残留项。

## 验收标准

- 工作区中剩余的文档归档/删除变更被正确提交。
- 不把 `logs/` 等运行产物误提交。
- 能说明哪些历史目录被归档，哪些文档被清理删除。
- 提交信息与提交正文符合项目中文规范。

## 关键假设

- 用户要求“把剩余修改一起处理并提交”，主要是指当前剩余的文档删除与归档整理。
- `logs/` 与其他运行产物仍不应提交，即使它们是未跟踪文件。
