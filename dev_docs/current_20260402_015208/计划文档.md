# C8/C9 工头计划化重构实施

## 本次任务标题
C8/C9 工头计划化重构实施

## 最终计划摘要
本轮将 `C7 -> C8 -> C9` 从旧的“一次性排列求解 + 直接建造队列”流程，重构为“工头计划 -> 单节点施工编排 -> 程序校验 -> 已批准节点落地”的新流程。保留原有 `C7/C8/C9` 主文件名与 `CityController` 阶段接口，但升级数据结构、控制器语义和队列逻辑；阶段字段采用 `phase_key + phase_name` 双字段，其中 `phase_name`、错误说明、计划说明等自然语言值统一使用中文。

## 实施步骤
1. 新建并落地 `C7` 工头计划主结构，加入唯一 `start_node`、`phase_list`、`global_constraints`、模板池边界与中文说明字段。
2. 重构 `C8` 产物为施工会话模型，引入活跃节点、待施工队列、已校验节点、失败尝试记录和中文错误说明。
3. 将 `CityC8ArrangementEngine` 从整组扩张器改为校验与节点派生工具，移除旧的一次性扩完整树主流程。
4. 重构 `C9` 队列与执行器，仅消费已通过 `C8` 校验的节点，不再自动 terminalize 祖先。
5. 扩展 `CityController` 的 `C7/C8/C9` 阶段接口，补充 `C8` 节点提交、节点重试、活跃节点读取能力。
6. 更新测试，覆盖工头计划输出、节点状态流转、`C9` 新队列行为和控制器接口返回。

## 验收标准
- `C7` 能输出唯一 `start_node` 与包含中文阶段名的 `phase_list`。
- `C8` 能输出 `active_node`、`node_queue`、`validated_nodes`、`failed_attempts` 等会话字段。
- `C9` 只执行已校验节点，运行时失败回写错误而不是自动收尾祖先。
- `CityController` 现有 `C7/C8/C9` 路由仍可调用，且新增 `C8` 节点提交/重试接口可用。
- 新增或重构的字段定义处有中文注释，自然语言型值统一使用中文。

## 关键假设
- 本轮优先保留现有文件名和分阶段入口，减少上层调用断裂。
- 阶段只支持单 `start`、串行施工、单活跃节点，不实现并发施工。
- 枚举值、错误码、模板 ID、节点 ID、方向等稳定机器值继续使用英文；说明性文字统一使用中文。
