具体建筑在所属风格中一起确定功能、形体、空间与材料。不同风格可以有不同的建筑内容，不要求填同一张功能表，也不按固定“类型×布局×风格”组合生产。各目录的核心与填充内容已合并到 **建筑清单.md**，原两份文件只保留跳转入口；核心、填充与明确选用继续作为条目的规划角色。

风格采用能够联想到具体建筑传统的常见类别，例如矮人、精灵、北欧、沙漠与蒸汽朋克；不编造国名代替风格定义，也不机械禁止地域词。各类的形体、材料与装饰基准见[建筑风格分类](文明命名.md)。目录与结构 ID 保持稳定，具体落地仍以模型条件为准。

## 用户确认的方向

- 面向异世界整合包：玩家穿越后探索不同文明，每局世界具有不同体验。
- 发挥 AI 在多风格、多功能建筑与组合设计上的能力，包含车站、码头等基础设施。
- 可进入的建筑具有与用途一致的完整内饰，建模过程中同步标记。
- **这是国度 Mod；“因地制宜”是原则。**
- **一个风格一份建筑清单；核心与填充在文档内区分，日常建筑与配套重点关注多样性。**

## 核心与填充的分工

| 类别 | 制作重点 | 选用方式 |
| --- | --- | --- |
| 核心结构 | 承担组团主要功能；完整空间、鲜明身份、配套关系 | 按规划明确选择，并组织配套或子阵列 |
| 填充结构 | 可重复的生活、商业、生产与农业结构；一个结构族包含多个有实际区别的模型 | 按文明、用途、尺寸、地形条件组成候选池，组织有差异的重复 |
| 专项条目 | 遗址、信号楼等需要明确选材的对象 | 放在核心文档的专项小节，保留明确选用身份 |

**核心和填充按用途与重复适用性区分，尺寸独立记录。** 大型住宅可以是填充，小型功能主体也可以是核心。小型商铺与主市场大厅、独立田块与农业管理中心分别判断。

代码对照：`planning_role.key/anchor` 表示核心，`planning_role.fill` 表示可重复候选，`planning_role.structure` 表示明确选用；`planning_role.self_contained` 需要实际完整组合证据。文档分组不会自动写入运行时标记。

依据：[角色整理工具](../../tools/city_templates/curate_planning_roles.py)、[蓝图编译器](../../src/main/java/com/rinsing/geomantia/systems/city/application/CityBlueprintCompilerService.java)。现有代码将核心、明确选用和完整组合排除出普通填充选择；本次只调整制作清单。

## 因地制宜

**地理条件与资源 → 文明如何利用环境 → 聚落承担什么功能 → 选择建筑 → 组合落地。**

- 聚落的产业、生活与交通应有所在地条件支撑；码头联系实际可用水岸，矿运设施服务矿业，关卡联系真实通道。
- 地形约束可行性，文明决定应对方式。同一峡谷可以由不同文明采用桥梁、渡口、绕行驿站或特殊交通；具体技术需要相应玩法支持。
- 建筑考虑坡向、入口高程、岸线、支撑与空间净空，提供有用途差异的适配版本。
- 文明与生物群系不固定一一对应；依据环境、资源、文化和世界关系选择合理组合。
- “山地铁路接入运河港口”是条件合适时的组合示例，不是每局必须施工的场景。
- 保留所在地的地貌特色；填充同样受地理、资源与作物条件约束。

## 材料换皮与设计差异

- 材料换皮方案在 AI 设计前填写，限定墙、柱梁、屋面、基础与装饰的材料映射；执行替换不再触发多模态审美判断或结构重设计。
- 换皮仅替换材料，不改变方块位置、平面、屋顶形状、门窗位置和通路。映射需保留对应构件形状与所需方块状态；无法兼容的替换不能作为纯材料方案。
- 中式小住宅与欧洲中世纪小住宅即使用途、体量相近，其屋顶和构架差异仍属于风格设计，分别制作模型，不能以换材料代替。
- 同一种风格内，布局、体量组合与用途差异形成不同建筑样式；单纯换色换材不计为新增样式或风格。
- 以上为制作清单约定，本次未实现材料替换功能，也未新增运行时字段。

## 填充多样性

| 结构族 | 需要变化的内容 | 建议起步范围 |
| --- | --- | --- |
| 小房屋、住宅、公寓 | 单户／多户、独栋／联排／街角／院落、长宽比例、楼层、屋顶、入口与家庭平面 | 每族 6～10 个 |
| 商铺与摊位 | 食品、杂货、衣物、工具等行业；单铺／双开间／街角／商住，以及各自内饰 | 日常商铺族 8～12 个 |
| 工坊、旅店与仓储 | 工位、客房、货物、后勤、装卸面与院落；避免不同名称复用同一室内 | 每族 4～8 个 |
| 农田、菜畦与药圃 | 作物、面积、狭长／L形／边角形、灌溉、田埂、入口与地形高差 | 每族 4～10 个 |
| 葡萄棚与藤架 | 单列／多列、直形／L形／靠墙、棚架高度、行距、采收与出入口 | 每族 4～6 个 |
| 工具棚、货棚与小配套 | 开敞／半围合／贴墙、功能物品、开口、形体与使用空间 | 每族 4～8 个 |

以上数量是制作建议，不是硬门槛。优先覆盖有意义的用途、平面与地形差异；不枚举全部组合，也不把旋转、镜像或单纯换色计成新的形体与平面变体。已有变体中缺少合适占地、入口或内饰时，再有针对性地补充。

- 每个可进入版本具有完整内饰；开放田块、棚架和货场完成对应生产与作业细节。
- 同套材料语言保持协调，同时让房屋轮廓、室内组织和街道界面有辨识度。
- 实际填充按用途、体量、高度和环境条件选用；出现频率与单模板复用限制依用途确定。
- 农田清单覆盖固定模板田块、棚架与农业配套；自然地形生长的大田仍按既有 Landscape 路径设计。不能把两种落地方式混作同一资产能力。
- 田块和棚架记录独立／连片／封边用途；涉及拼接的版本先核对接口，不默认运行时自动补齐。
- 葡萄等作物按整合包确认外观与生产机制；棚架成品不自动代表作物功能已接入。

## 文件与进度维护

- 总清单维护共同方向与导航；各风格 README 只作入口；**逐项进度只在该风格的建筑清单.md 维护**。
- 每个结构或结构族保留唯一主归属；跨风格组合归原跨文明文件夹，交通类别用索引检索。
- 原编号保持稳定。新增填充族使用文明前缀＋`Fxx`，制作具体模型时再追加 `-v01` 等变体编号。
- 一个填充族完成首个模型不等于该族已完成；在所属文档记录已做变体、仍缺的差异和验收状态。
- 条目状态为“待建模”“建模中”“待验收”“完成”；实际模型须核对外观、内饰、入口、标记与适用环境后计为成品。
- 开始制作具体条目时再建立成品目录，收纳结构、预览和作者标记，不预建空目录。

## 内饰与随建随标记

内饰按用途组织：住宅有生活空间，车站有候车与站务，码头有理货与仓储，工坊有原料、加工和成品。门、楼梯、床位和工作区实际可达。

| 内容 | 记录要点 |
| --- | --- |
| 身份与语义 | 稳定编号、结构族与变体编号、文明、视觉风格、主功能与实际兼用功能 |
| 规划角色 | 核心、填充或明确选用；用途与重复资格分别核对，完整组合另附证据 |
| 多样性 | 与同族已有模型相比的形体、平面、内饰、行业与环境差异 |
| 环境条件 | 资源与服务对象、适用地形、坡向、水面关系、支撑与接地位置 |
| 入口与连接 | 步行入口、正面、朝向与高程；特殊交通接驳位置和净空分别记录 |
| 室内用途 | 房间、床位、工作点、储物点、上下楼与后勤路线 |
| 几何 | 实际尺寸、屋檐台阶外延、允许旋转与镜像 |
| 组合关系 | 自带配套、可搭配结构、需要保留的空间、独立或连片适用条件 |
| 历史与探索 | 使用状态、改造痕迹、线索与隐藏空间 |
| 交付证据 | 外观与内部预览、结构文件、核对记录、已完成模型数量 |

现有字段按当前契约接入；新增房间、变体差异和特殊连接信息先保存于作者附属记录，不直接加入未支持的运行时字段。模板本体与交通运行、跨城线路、传送、浮空、水下和地下适配分别核对。

## 每局变化的制作方向

聚落身份、交通关系、地方产业、历史状态与文明接触共同决定选材。填充变体让街巷、农田和生活空间有可辨认的变化；历史版本改变实际房间用途、通路和陈设。优先确保生活逻辑与地理适配，再扩展探索线索和更多版本。
